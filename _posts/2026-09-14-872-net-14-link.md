## 2. 知识框架

```
数据链路层功能：成帧、差错控制（检错/纠错）、流量控制（相邻节点）
  ├─ 封装成帧：帧定界（SO/EOT、字节填充、比特填充）
  │    └─ 透明传输：数据比特流恰含帧定界符 → 填充转义，使接收方不误判帧边界
  ├─ 差错检测：奇偶校验 → CRC 循环冗余校验（本章计算核心，只检错不纠错）
  └─ 可靠传输（相邻节点）：停止等待 / 后退 N 帧 GBN / 选择重传 SR
       ※ 872 把这三个协议放在**数据链路层**考；408 多在传输层 TCP 讲

点对点协议 PPP（872 高频）：
  ├─ 帧标志/定界符 0x7E；只用 CRC 检错，**出错丢弃不重传 → 不提供可靠传输**
  ├─ LCP（链路控制协议）：建立/拆除链路、协商 MRU、认证、链路检测
  └─ NCP（网络控制协议，IP 对应 IPCP）：配置网络层参数、**分配 IP 地址**
      异步链路 透明传输 → 字节填充（转义字符 0x7D）
      同步链路 透明传输 → 零比特填充（5 个连续 1 后插 0）

介质访问控制（广播信道）：
  ├─ 静态划分：FDM/TDM/WDM/CDM
  └─ 动态分配：轮询/令牌（受控） vs CSMA/CD（随机）
       CSMA/CD —— 有线以太网：先听后发、边听边发、碰撞停发、随机重发
       退避等待时间 = r × 争用期（争用期 = 2τ = 最小帧长 / 速率）
       CSMA/CA —— 无线 802.11：检测不到碰撞 → 事先避免（IFS + 退避 + 确认重传）

```

## 3. 简答与名词解释

### 必背

- **透明传输**：不论数据是怎样的比特组合，都能原样通过链路而不被误判——对上层（网络层）而言，链路层所做的填充/转义**仿佛不存在**，故称"透明"。**核心要解决的问题**：数据中恰好出现与**帧定界符相同的比特流**，接收方会把它误当帧边界，导致帧定界错误。**两种实现**：异步/字符链路用**字节填充**（PPP 用转义字符 0x7D，把 0x7E、0x7D 及控制字符转义后发送）；同步/比特链路用**零比特填充**（发送方每遇到 5 个连续 1 就在其后插入一个 0，接收方每收到 5 个连续 1 就把紧随的 0 删除）。
- **PPP（点对点协议）**：面向**点对点链路**的数据链路层协议，用于主机到 ISP、路由器直连等场景。帧以 **0x7E** 标志字段定界，地址字段 0xFF、控制字段 0x03，协议字段用于区分载荷是 IP、LCP 还是 IPCP。**只用 CRC 检错，检测到差错直接丢弃、不重传——PPP 不提供可靠传输**，可靠性交由上层负责。

![PPP 协议组成、帧格式与透明传输](/assets/img/csreview/Snipaste_2026-09-19_10-45-22.png)
_PPP 帧：F(0x7E) 定界｜A/C 固定无意义｜协议字段区分 IP/LCP/NCP｜信息 ≤1500B｜FCS 做 CRC 检错_

- **LCP 与 NCP 的分工（高频）**：**LCP（链路控制协议）**负责**建立、配置、测试、拆除数据链路**，包括协商 **MRU（最大接收单元）**、认证方式（PAP/CHAP）、链路质量检测等，**不负责 IP 地址分配**；**NCP（网络控制协议）**负责配置**网络层**参数，IP 对应 **IPCP**，**IP 地址分配由 IPCP 完成**。陷阱选项常把"分配 IP"塞进 LCP。

![PPP 协议工作过程](/assets/img/csreview/Snipaste_2026-09-19_10-48-38.png)
_拨号建链顺序：物理链路 → LCP 配置协商 → LCP 鉴别 → NCP 协商（分配 IP）→ 携 IP 分组上网_
- **停止等待 / 后退 N 帧 / 选择重传（链路层 ARQ，本篇主战场）**：可靠传输的原理主场在**数据链路层**（相邻节点），872 在本层考，TCP 只是同一套机制在端到端的复用（07 篇从 TCP 视角讲）。三者都是滑动窗口式 ARQ，四个基本机制：**校验**（检错）、**序号**（区分新帧/重传旧帧、检测丢失失序重复）、**确认**（ACK 告知已正确收到）、**重传**（超时未确认就重发）。
  - **停止等待**：发送窗口 = 1，发一帧 → 等确认 → 再发；超时重传。需 0/1 交替序号区分新帧与超时重传的旧帧。优点简单，缺点信道利用率最低，U = T_D / (T_D + RTT + T_A)。
  - **GBN（后退 N 帧）**：发送窗口 > 1、**接收窗口 = 1**；接收方**只按序接收，失序帧一律丢弃不缓存**，重发对最后按序帧的确认；**累积确认**（确认号 n 表示 n 及之前全部收到）；某帧超时则**从该帧起重传其后所有已发帧**（"后退 N 帧"），序号约束 W_T ≤ 2ⁿ − 1。
  - **SR（选择重传）**：发送窗口与接收窗口均 > 1（通常相等，W_T + W_R ≤ 2ⁿ，即 W_T = W_R ≤ 2ⁿ⁻¹）；接收方**缓存落在接收窗口内的失序帧**，等缺失帧补齐后一并上交；**逐个确认**；发送方**只重传真正出错/超时的帧**，代价是缓存与逻辑更复杂。
- **CRC（循环冗余校验）**：约定**生成多项式 P(X)**（r 次多项式对应 r+1 位除数）。发送方在 k 位数据后拼接 r 位校验码：把数据**左移 r 位**（末尾补 r 个 0），对除数做**模 2 除法**（异或不借位），所得 r 位余数即 FCS。接收方将收到的 k+r 位**再除同一除数，余数为 0 判定无错**。CRC 只检错不纠错（考纲范围内）。
- **CSMA/CD（载波监听多路访问/碰撞检测）**：用于总线式有线以太网。要点十六字：**先听后发、边听边发、碰撞停发、随机重发**。发送中持续检测信道，一旦检测到碰撞立即停发并发出**强化碰撞信号**，然后按**截断二进制指数退避算法**推迟重发。半双工总线网必备；全双工交换式以太网不需要 CSMA/CD。

![CSMA/CD 发送方工作流程](/assets/img/csreview/csma-cd.1.png)
_发送前监听到信道忙就坚持等待（1-坚持），空闲立即发送；边发边听，冲突即停发并记次数，k≤15 随机等待后重发，k=16 放弃并报告网络层_

- **CSMA/CA（载波监听多路访问/碰撞避免，IEEE 802.11 无线局域网）**：为什么不用 CD——无线网卡接收信号强度远小于发送强度（自身发射信号淹没接收端），**硬件上无法边发边检测碰撞**；且存在**隐蔽站问题**（A、C 都在 B 范围内但互相听不到，同时发给 B 仍会碰撞，监听再久也避免不了）。所以 802.11 改"事后检测"为"**事先避免**"：①监听到信道空闲还要再等**帧间间隔（IFS）**才发送，忙则退避（收到 ACK 说明无碰撞，未收到 ACK 视为碰撞/丢失，超时重传）；②**帧间间隔区分优先级**：**SIFS（短 IFS，最短）**——ACK、CTS 等最紧急帧使用；**PIFS（点协调 IFS，中等）**——PCF 轮询用；**DIFS（分布协调 IFS，最长）**——数据帧和管理帧使用；**SIFS < PIFS < DIFS**，间隔短者先发、优先级高；③**随机退避**：信道由忙转闲后冻结/继续计时，从 {0,…,2ᵏ−1} 选一个时隙数，计满才发；④**确认 + 重传**：接收方正确收到数据帧后隔 **SIFS** 回 ACK，发送方超时未收到 ACK 就重传（802.11 链路层确认重传，区别于以太网的"不确认、差错丢给上层"）。可选 **RTS/CTS 机制**缓解隐蔽站：发送前先广播 RTS 申请信道，接入点回 CTS 占用通知，邻站听到 CTS 保持静默。

CSMA 按"信道忙时怎么办"分三种策略，以太网采用的是 **1-坚持 CSMA**：监听发现信道忙就**坚持继续监听**，一旦变空闲**立即（概率 1）发送**；另有非坚持 CSMA（忙就不监听了，随机等一段时间再来问）和 p-坚持 CSMA（空闲时以概率 p 发送、以 1−p 推迟到下个时隙），考试要求能据策略名称判断忙时行为。完整流程串起来是：帧准备好后先做发送前载波监听，忙就等，空闲立即发；发送期间持续"边发边听"，若一个争用期内没听到冲突，就可以断定本次发送不会再发生冲突，放心把整帧发完；一旦听到冲突，立即停止发送（已发出的是不完整的碎片），并发出 **32 bit（4 字节）的人为干扰信号（jam signal，强化碰撞）**，让总线上所有站都知道发生了冲突，然后进入退避流程：这是本帧第 k 次冲突，k ≤ 15 时按截断二进制指数退避随机等待后重新从"监听信道"走一遍，k = 16 时放弃本帧并向网络层报告传输失败。
- **最小帧长（争用期）**：设总线端到端往返传播时延为 2τ（**争用期/碰撞窗口**）。发送方最迟要经过 2τ 才能检测出碰撞，为在发送期间就能发现碰撞，帧的发送时延必须 ≥ 2τ，故**最小帧长 = 2τ × 数据传输速率**（以太网取 64 B，64 B × 10 Mb/s 恰对应 51.2 μs 争用期）。凡长度小于最小帧长的帧都视为无效帧（碰撞碎片）。
- **截断二进制指数退避**：第 i 次碰撞后，从 {0,1,…,2^k −1} 中**随机**取一个数 r，退避 r × 争用期时间再重发，其中 k = min(i, 10)（**指数部分截断到 10**）；重发达 **16 次**仍失败则放弃并报错。"截断"即指指数上限、以及重传次数上限。
- **以太网帧结构（IEEE 802.3 / Ethernet II）**：目的 MAC（6 B）+ 源 MAC（6 B）+ **类型**（2 B，标识上层协议：0x0800=IPv4、0x0806=ARP）+ 数据（**46~1500 B**）+ FCS（4 B，CRC 校验）。数据不足 46 B 时**填充**（保证最小帧长 64 B）；硬件在帧前加 8 B 前同步码（不计入帧长与 FCS）。MAC 帧**没有帧结束定界符**，靠帧间间隙与物理层编码定界。
- **集线器 vs 交换机**：集线器工作在**物理层**，对比特信号再生放大后广播式转发，所有端口共享带宽、同处一个冲突域（半双工）；交换机工作在**链路层**，按 MAC 地址表转发，每端口独立冲突域、可全双工。两设备都不隔离广播域。

### 辨析

- **奇偶校验 vs CRC vs 海明码**：奇偶校验只能检奇数位错、不能纠错；CRC 检错能力强（突发错误）、检错不纠错；海明码可定位并纠正 1 位错（考纲以了解为主）。计算大题集中在 CRC。
- **CRC vs 检验和（为什么链路层用 CRC 不用检验和）**：CRC 基于模 2 除法，硬件上用移位寄存器加异或门即可逐位实现，检错能力强（能覆盖突发错误、多位错），适合链路层对**每一帧做硬件检错**；检验和是普通加法求和取反码，实现简单、贴合软件逐层校验，但检错能力弱（字节交换、进位叠加等差错会漏检）。所以链路层（以太网 FCS、PPP 的 FCS）选 CRC，而 TCP/UDP/IP 等上层协议用检验和。
- **透明传输 vs 可靠传输**：透明传输解决的是**帧定界不被误判**（填充分帧问题），**与是否出错无关**；可靠传输解决的是**丢帧/错帧的恢复**（确认与重传）。"透明"不等于"可靠"——PPP 既透明又不可靠。
- **GBN vs SR vs 停等（872 在链路层就考）**：接收窗口——GBN 为 1、SR > 1；失序帧——GBN 丢弃、SR 缓存；确认——GBN 累积确认、SR 逐个确认；重传——GBN 退后重传一批、SR 只重传一帧。做题先问"接收方缓存不缓存失序帧"即可秒判。
- **链路层 ARQ vs TCP 可靠传输**：同一套滑动窗口思想（校验/序号/确认/重传），应用位置不同——链路层 ARQ 管**相邻节点间一跳**，TCP 管**端到端进程间**；链路层窗口小（序号常按帧编），TCP 序号按**字节**编、窗口由 rwnd/cwnd 共同决定；链路层是否可靠随协议（PPP/以太网不可靠，出错丢弃交上层），TCP 永远可靠。872 把停等/GBN/SR 放链路层考，408 多借传输层 TCP 考——细节 TCP 视角见 07 篇。
- **Ethernet II 帧 vs IEEE 802.3 帧**：两者目的/源 MAC 与 FCS 相同，区别在 MAC 地址后的那个 2 字节字段——**Ethernet II 是类型字段**，直接标识上层协议（0x0800=IPv4、0x0806=ARP）；**IEEE 802.3 是长度字段**，表示数据字段的字节数。**判别规则**：值 **< 0x0600（1536）判作长度**，**≥ 0x0600 判作类型**（数据字段最多 1500 B，故 0x05DD~0x05FF 为保留区）。
- **碰撞检测 vs Jam 信号（因与果）**：碰撞检测是**本地网卡物理层瞬间完成**的——边发边听，检测到电压摆动异常（叠加增大超门限）即判定碰撞，不需要等待任何特殊信号包；Jam 信号（人为干扰/强化碰撞）是**检测到碰撞之后**才主动发的 32 bit（谢希仁口径）干扰序列，目的是**拉长冲突、拉高电平，让全网（尤其远端因衰减感知弱的主机）都感知到碰撞**并使其他接收方 CRC 校验失败丢弃残帧，不用于自我检测——检测是因，Jam 是果。
- **曼彻斯特编码的层归属**：它属于**物理层**编码（把比特变成带时钟信息的波形），不是数据链路层功能；802.3 只是规定以太网物理层采用曼彻斯特编码，"编码"这件事本身不属链路层——考"该功能属于哪一层"时是高频设错点。
- **CSMA/CD vs CSMA/CA**：CD 用于**有线**（802.3），检测碰撞靠"边发边听"——有线信号全程不衰减到检测不出，能边发边测；CA 用于**无线**（802.11），无线信号衰减大、无法边发边检测，且隐蔽站存在使监听失效，只能"事先避免"（IFS 等待 + 退避 + 确认重传 + RTS/CTS）。**有线以太网无确认重传（出错交上层），802.11 有链路层确认重传**——这是两者最常考的行为差异。CD 的代价概念是**争用期 2τ**，CA 的代价概念是**帧间间隔 SIFS/PIFS/DIFS**。
- **为什么 ACK 隔 SIFS 发而不是等 DIFS**：SIFS 最短，若 ACK 等 DIFS 再发，别的站可能先抢到信道，ACK 就被挤掉了；规定 ACK、CTS 用 SIFS，普通数据帧用 DIFS，保证 ACK 恒优先于其他数据帧——**间隔越短优先级越高**是排序题与流程题的统一底层逻辑。

### 了解

- 同步/异步链路的成帧区别：异步链路以字符为单位、用字节填充；同步链路以比特流为单位、用零比特填充（PPP 与 HDLC 都如此）
- PPP 的 0x7E 标志字段兼作帧首尾定界，PPP 帧中没有序号与确认字段
- TDM 统计复用：时隙按需分配，避免传统 TDM 空闲浪费（物理层篇展开）
- 载波延伸（千兆以太网 512 B）与帧突发，为拓展阅读

## 5. 计算与方法

### ① CRC 计算（本章压轴）

**触发条件**：给出数据位串与生成多项式，求发送序列或校验码。

**步骤**：
1. 多项式次数 r → 除数为 r+1 位、数据后**补 r 个 0**
2. **模 2 除法**：把除数与当前最高位的 1 对齐，对齐后的 r+1 位做一次异或（不借位、商只取 0/1）
3. 异或后最高位变 0，再往低位找下一个 1 继续对齐异或；剩的位数短于除数时停止，余数不足 r 位**高位补零** → 得 FCS
4. 发送序列 = 原数据 + FCS；验算：整体模 2 除除数余 0

补 r 个 0 相当于把数据左移 r 位，低 r 位空出来正好放余数。接收方把收到的整串再除同一个除数，数据部分本来就能除尽，能影响余数的只剩校验码，所以余数为 0 就判无错。模 2 除法不借位，每一步只按最高位对齐做异或。

**自编例题**：数据 1010，生成多项式 X³+X+1（除数 1011，r=3）。
- 补零：1010 000
- 1010000 ÷ 1011（模 2）：
  - 最高位对齐 1011：1010 ⊕ 1011 = 0001，后面落下的 000 照抄 → 0001000
  - 再对最高位的 1 对齐 1011：1000 ⊕ 1011 = 0011 → 0000011
  - 剩的位数已不足 4 位，停止，余数 = **011**
- 发送序列 = 1010**011**；接收方 1010011 ÷ 1011 余 0 ✔

（手算时逐位落下异或，保持对齐；商不关心，只留余数。）

### ② CSMA/CD 最小帧长 & 检测时间

**触发条件**：给链路长度、速率，求最小帧长；或问最迟多久检测到碰撞。

**步骤**：
1. 传播时延 τ = 距离 / 传播速率（2×10⁸ m/s 或题目给定）
2. 争用期 = 2τ；**最小帧长 = 速率 × 2τ**（单位对齐：速率 b/s × 时间 s = bit）
3. 反向题：帧长已知求最大网段长度：L_min / 速率 ≥ 2 × (距离/传播速率) → 解距离
4. "最迟检测到碰撞的时刻"= 发送开始后 **2τ**（一去一回）

帧不能太短的原因，要结合最坏情形理解：设总线上相距最远的两台主机为 A 和 B，单程端到端传播时延为 τ。t=0 时 A 开始发送，它的信号还没传到 B；B 在 t=τ−δ（信号即将到达前的一刹那）监听信道，仍以为空闲，于是也开始发送，双方信号在 t=τ−δ/2 时相遇碰撞。碰撞信号再传回 A 时已经是 t=2τ−δ，δ 可以任意小，因此**最迟要经过接近 2τ（一个往返）发送方才能发现本次发送存在冲突**。如果帧的发送时延小于 2τ，帧在冲突信号传回前就发完了，发送方会误判成功，停发之后再收到冲突信号也无从补救。所以帧的发送时延必须不短于争用期 2τ，即最小帧长 = 速率 × 2τ；反过来说，只要一个争用期内没有检测到冲突，本次发送就不会再发生冲突。

![CSMA/CD 争用期的最坏情形时空图](/assets/img/csreview/csma-cd.2.png)
_A 在 t=0 发送，B 在 t=τ−δ 误判空闲后发送，t=τ−δ/2 相撞；B 在 t=τ、A 在 t=2τ−δ 才各自检测到冲突并停发_

**自编例题**：10 Mb/s 以太网，端到端传播时延 τ = 25.6 μs。
争用期 2τ = 51.2 μs；最小帧长 = 10×10⁶ × 51.2×10⁻⁶ = **512 bit = 64 B**（即标准值）。

**自编例题 2**：帧长 512 B、速率 100 Mb/s、传播速率 2×10⁸ m/s，求最大网段长度。
τ ≤ (512×8 / 100×10⁶) / 2 = 20.48 μs；距离 ≤ 2×10⁸ × 20.48×10⁻⁶ ≈ **4096 m**（理论值，实际受标准约束更短）。

### ③ 冲突域 / 广播域与设备判断

**触发条件**：给拓扑（Hub/SW/Router 混合），问冲突域数、广播域数或转发行为。

**步骤**：
1. 集线器：不隔任何域——Hub 连的所有主机算**一个**冲突域
2. 交换机：**每端口一个**冲突域；广播域不隔（VLAN 除外）
3. 路由器：每接口一个广播域
4. 判断转发：SW 查 MAC 表（无表项泛洪）；Router 查路由表（广播不出）

冲突域按设备层次分：集线器只放大信号、不识别帧，任何时刻只允许一个端口发送，连在它上面的主机共享一个冲突域；交换机每个端口独立收发，端口之间不会碰撞，所以一个端口一个冲突域。广播域看路由器：路由器不转发广播帧，每个接口隔出一个广播域，集线器和交换机都不隔广播域。

**自编例题**：H1、H2 —Hub— SW，SW 另两端口接 H3、R：
- 冲突域：{H1,H2} 一个 + H3 一个 + R 一个 = **3 个**
- 广播域：R 另一侧若有网，则共 **2 个**

### ④ 以太网帧字段速查

- 最小 64 B（不含前导码）、最大 1518 B（14 B 头 + 1500 数据 + 4 B FCS）
- 数据 < 46 B 必填充；FCS 不含前导码
- 类型 0x0800 IPv4 / 0x0806 ARP（联动 12 篇 ARP 广播帧）

这几个长度都由字段相加得到：帧头 6+6+2 = 14 B，FCS 4 B，数据取 46~1500 B，整帧就是 64~1518 B。数据不足 46 B 时补填充，保证整帧不小于 64 B；接收方按类型/长度字段确定真实数据的范围，多出的填充由上层忽略。

### ⑤ CSMA/CD 退避等待时间（872 大题小问）

**触发条件**：给出最小帧长（或链路长度与速率）、随机退避数 r，求等待多久再监听信道。

**步骤**：
1. 先求**争用期**（以太网称时隙时间）：争用期 = 2τ = **最小帧长（bit）/ 数据传输速率**
2. 截断二进制指数退避：第 i 次冲突后取 k = min(i, 10)，从 {0,1,…,2ᵏ−1} 中随机取 r
3. **等待时间 = r × 争用期**（注意是 r 倍**争用期 2τ**，不是 r 倍单程传播时延 τ）
4. 单位核对：bit ÷ (b/s) = s，再乘 r

退避的作用是把刚发生碰撞的各站错开。第 i 次冲突后 r 从 {0,1,…,2ᵏ−1} 中随机取，碰撞次数越多取值范围越大，可选的等待时间越分散，再次碰撞的概率越低；k 到 10 后不再增长，防止等待时间无上限。以太网把争用期 2τ 直接当作一个时隙，退避倍数 r 乘的就是这个时隙。

**自编例题**：以太网最小帧长 512 bit、速率 10 Mb/s，截断二进制退避中抽到 r = 100，求需等待多久再监听信道。
争用期 = 512 / (10×10⁶) = 51.2 μs；等待时间 = 100 × 51.2 μs = 5120 μs = **5.12 ms**。

### ⑥ SR / GBN 窗口上限计算

**触发条件**：给序号位数 n，求 SR/GBN 最大发送窗口；或给窗口反求最少序号位数。

**步骤**：
1. SR 约束 W_T + W_R ≤ 2ⁿ，一般取 W_T = W_R，故 **W_T ≤ 2ⁿ⁻¹**
2. GBN 接收窗口恒为 1，约束 **W_T ≤ 2ⁿ − 1**（留 1 个序号区分新帧与重传旧帧）
3. 反向题：W_T 已知求最小 n——SR 解 2ⁿ ≥ 2W_T；GBN 解 2ⁿ ≥ W_T + 1

序号必须能区分同一时刻在传的所有帧，否则接收方拿到一个序号时，分不清它是新帧还是重传的旧帧。SR 中发送窗口和接收窗口里的帧同时存在、互不重复，最多 W_T + W_R 个，而 n 位序号一共只有 2ⁿ 个取值，所以 W_T + W_R ≤ 2ⁿ；两边平分得到 W_T = W_R ≤ 2ⁿ⁻¹。GBN 接收窗口恒为 1，约束就退化成 W_T ≤ 2ⁿ − 1。停等是两者特例：发送窗口 1，只需 1 位序号（0/1 交替）。

**自编例题**：序号 4 位（0~15），SR 最大发送窗口 = 2⁴⁻¹ = **8**；同题改问 GBN，则 = 2⁴ − 1 = **15**。

**自编例题 2**：SR 协议发送窗口为 16，最少序号位数？2ⁿ ≥ 2×16 = 32 → n = **5**。

### ⑦ 停等信道利用率

**触发条件**：给出发送速率、帧长、RTT（或单向传播时延）。

**步骤**：
1. T_D = 帧长 / 发送速率；T_A = 确认帧长 / 发送速率（ACK 很短常忽略）
2. U = T_D / (T_D + RTT + T_A)
3. 若问"至少多大窗口才能占满信道"：W ≥ ⌈(T_D + RTT + T_A) / T_D⌉，再与序号上限取小

**自编例题**：1000 km 链路，传播速率 2×10⁸ m/s（RTT = 10 ms），发送速率 1 Mb/s，帧长 1000 B。
T_D = 1000×8 / 10⁶ = 8 ms；U = 8 / (8 + 10) ≈ **44.4%**（忽略确认帧时延）。

### ⑨ 802.11 发送耗时（CSMA/CA 计算题）

**触发条件**：给出各间隔（DIFS/SIFS）与帧发送时间，求成功交付一帧的总时间或画时序。

**步骤**：
1. 空闲后等 **DIFS** → 发数据帧
2. 接收方隔 **SIFS** 回 ACK（SIFS < DIFS，保证 ACK 不被抢）
3. **总时间 = DIFS + T_数据 + SIFS + T_ACK**；若含 RTS/CTS 则为 DIFS + T_RTS + SIFS + T_CTS + SIFS + T_数据 + SIFS + T_ACK
4. 排序题记口诀：**SIFS < PIFS < DIFS**（短 = 优先级高）；"退避"出现在检测到忙之后，正常成功流程不含退避时间

完整一次成功交付的时序是：站监听到信道空闲，持续空闲满 DIFS 后发出数据帧；接收方收完校验无误，等 SIFS（比 DIFS 短，别的站还没等到 DIFS 结束）即回 ACK；发送方收到 ACK，本轮交付结束。若中途信道变忙，退避计时器冻结，信道空闲满 DIFS 后继续倒计时——这就是"碰撞避免"在时间轴上的形态：没有任何时刻允许"边发边听"。

**自编例题**：DIFS = 128 μs，SIFS = 28 μs，数据帧发送时间 200 μs，ACK 发送时间 10 μs，忽略传播时延与退避。
总时间 = 128 + 200 + 28 + 10 = **366 μs**。

| 8 | PPP 提供可靠传输，出错会重传 | ✗ | PPP 只 CRC 检错、不重传 |
| 9 | PPP 的 LCP 负责为终端分配 IP 地址 | ✗ | IP 地址由 NCP（IPCP）分配，LCP 管链路建立与参数协商 |
| 10 | 透明传输意味着链路上不会发生传输差错 | ✗ | 透明解决帧定界不误判，与是否出错无关 |
| 11 | 异步链路 PPP 用零比特填充，同步链路用字节填充 | ✗ | 反了：异步用字节填充、同步用零比特填充 |
| 12 | 以太网帧的 FCS 由 CRC 计算得到，用于检测差错 | ✓ | FCS 即 CRC 余数，接收方再除同一除数验证 |
| 13 | 以太网中 2 字节字段 ≥ 0x0600 表示类型，< 0x0600 表示长度 | ✓ | Ethernet II 用类型、802.3 用长度 |
| 14 | 曼彻斯特编码属于数据链路层功能 | ✗ | 属物理层编码，链路层不负责编码 |
| 15 | 集线器可以隔离冲突域 | ✗ | Hub 全端口一个冲突域；隔离冲突域靠交换机 |
| 16 | 交换机默认可以隔离广播域 | ✗ | 不隔离，需 VLAN 或路由器 |
| 17 | 以太网 MAC 帧有专门的帧结束定界符 | ✗ | 无；靠帧间间隙与物理层编码定界 |
| 18 | 截断二进制指数退避中，退避时间 = r × 争用期 | ✓ | r 随机取自 {0,…,2ᵏ−1}，k = min(i,10) |
| 19 | 最小帧长 = 数据传输速率 × 单程传播时延 τ | ✗ | 应为速率 × 2τ（往返争用期），否则检测不到碰撞 |
| 20 | 链路层 ARQ 与 TCP 可靠传输使用同一套滑动窗口机制 | ✓ | 思想相同：校验/序号/确认/重传；TCP 编号按字节、作用于端到端 |
| 21 | 802.11 无线局域网也使用 CSMA/CD 检测碰撞 | ✗ | 无线无法边发边检测（信号衰减+隐蔽站），用 CSMA/CA 事先避免 |
| 22 | 三种帧间间隔中 DIFS 最短 | ✗ | 反了：SIFS 最短，DIFS 最长（SIFS < PIFS < DIFS） |
| 23 | 802.11 接收方收到数据帧后回 ACK 属于链路层功能 | ✓ | 802.11 在链路层确认重传；以太网才"不确认、差错交上层" |
| 24 | CSMA/CA 中数据帧应使用 SIFS 间隔发送 | ✗ | 数据帧用 DIFS；SIFS 留给 ACK/CTS 等高优先级帧 |

## 7. 本节易错点

常见坑：
- CRC 忘**补 r 个 0** 再除，或余数不足 r 位没**高位补零**——两处都导致发送序列错
- "CRC 能纠正错误"：考纲内错，CRC 只检错（发现错 → 丢弃，可靠由上层保证）
- "GBN 发送窗口最大 2ⁿ"：错，是 2ⁿ − 1；SR 才与接收窗口对半分序号空间（2ⁿ⁻¹），口诀**GBN 减一、SR 减半**
- "停等协议无需序号"：错，需要 0/1 交替序号，否则无法区分新帧和超时重传的旧帧
- "SR 接收方不缓存失序帧"：错，只有 GBN 不缓存；SR 靠缓存 + 逐个确认换取"只重传一帧"
- 最小帧长用 **τ 而不是 2τ**：错，检测碰撞需往返，公式 = 速率 × **2τ**
- 64 B 是"帧长下限"含 MAC 头与 FCS，不含 8 B 前导码；数据段下限 46 B 是另一回事，两个数别混
- "交换式全双工以太网仍需 CSMA/CD"：错，全双工无碰撞，CSMA/CD 不适用（考试常以此设选择题）
- "发送前监听到信道空闲，本次发送就不会冲突"：错——信号在链路上有传播时延，别的站可能在信号到达前也判空闲并发送，所以才需要"边发边听"和 2τ 争用期；要等发送后一个争用期内无冲突才锁定安全
- "集线器能隔离冲突域"：错，Hub 是物理层广播，全端口一个冲突域；隔离冲突域是交换机的能力
- 冲突域数数把"交换机整体"算一个：错，按**端口**数
- "LCP 负责分配 IP 地址"：错，分配 IP 是 NCP（IPCP）的事，LCP 只管链路建立与 MRU/认证
- "PPP 是可靠传输协议"：错，PPP 只检错不重传，可靠性交上层
- "退避等待时间 = r × τ"：错，是 r × **争用期 2τ**，单位与数值都别少乘 2
- "曼彻斯特编码是链路层功能"：错，属物理层；以太网帧的层次判断题高频设错点
- 以太网帧 2 字节字段一律当类型：错，**< 0x0600 是长度、≥ 0x0600 才是类型**
- "802.11 用 CSMA/CD"：错，无线用 **CSMA/CA**；CD 需要"边发边听"，无线信号衰减大听不了，且隐蔽站监听无效
- 三种 IFS 排序记反：正确是 **SIFS < PIFS < DIFS**——ACK/CTS 用 SIFS，轮询用 PIFS，数据帧用 DIFS
- 把 802.11 当"不可靠交付"：错，802.11 链路层有**确认重传**；只有有线以太网才"CRC 检错丢弃、可靠交上层"
- 耗时计算漏掉 ACK 前的 SIFS：结构是 **DIFS + 数据 + SIFS + ACK**，两个间隔一前一后别漏一个
