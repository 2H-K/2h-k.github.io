## 2. 程序怎么进内存：装入、链接与连续分配

### 2.1 地址的三种"定死"时机

重定位 = 把逻辑地址（程序视角，从 0 编起）变换成物理地址（真实内存单元）。

| 装入方式 | 何时完成变换 | 代价/限制 |
|---|---|---|
| 绝对装入 | 编译期就定死物理地址 | 只适用单道/专用系统 |
| 可重定位装入（静态重定位） | 装入时**一次性**完成变换 | 装入后**不能移动**——与紧凑、对换、虚拟存储全部无缘 |
| 动态运行时装入（动态重定位）【必背】 | 运行时才变换：物理地址 = 重定位寄存器（基址）+ 逻辑地址 | 需硬件支持；**是紧凑、对换、请求分页的共同前提** |

链接解决的是"多个目标模块（＋库函数）何时拼成一个完整装入模块"，三方式：

| 链接方式 | 链接时机 | 特点 |
|---|---|---|
| 静态链接 | 运行**前**就把所有模块链接成一个整体 | 链接后不可拆；某模块更新要重新整体链接 |
| 装入时动态链接 | **边装入边链接**：装入时发现引用了尚未装入的模块，才链接它 | 模块改了只需重链它自己，便于修改更新与模块共享 |
| 运行时动态链接 | 装入时不链全，**运行中执行到对某模块的调用时**才链接它 | 没被调用的模块根本不装入——省内存、按需加载 |

> 辨析关键：装入时动态链接链接的是"要装入的**整个模块**"，运行时动态链接只链接"真正被调用到的模块"，后者粒度更细。

### 2.2 连续分配三阶段

- 单一连续分配：内存分系统区 + 用户区，一道程序独占用户区。单道批处理，了解即可。
- 固定分区：用户区预先划成若干**固定**分区（大小可相等可不等）。程序小于分区 → **内零头**（分区内部浪费）。
- 动态分区【主体】：不预划，进程要多少给多少，用空闲分区表/链记账，分配时切一块、回收时归并。

### 2.3 动态分区分配四算法

| 算法 | 从哪块切 | 特点 |
|---|---|---|
| 首次适应 FF | 空闲区按**地址递增**排，取第一个够用的 | 简单；高地址端留大块；低地址端反复被切、查找开销增大 |
| 循环首次适应 NF | 从**上次位置**接着往下找（空闲区循环排列） | 空闲区分布更均匀；**大块很快被切碎**，后到的大作业可能没块 |
| 最佳适应 BF | 取**最小的**够用块（空闲区按容量递增排） | 每次留下的零头最小，但**产生大量小外零头** |
| 最坏适应 WF | 取**最大的**块 | 零头仍够用可再分；**大块消耗快**，大作业后头无块 |

例（初始空闲块 {100K, 500K, 200K, 300K, 600K}）：

| 作业 | FF | BF | WF |
|---|---|---|---|
| 212K | 500K → 288K | 300K → 88K | 600K → 388K |
| 417K | 600K → 183K | 500K → 83K | 500K → 83K |

### 2.4 碎片与两条出路

- **外零头**：分区之间的小空闲块——总容量够、单块不够用（动态分区、分段产生）。
- **内零头**：分给进程但用不上的部分（固定分区、分页产生）。
- 出路一 **紧凑（拼接）**：移动已分配分区，把外零头拼成大块。前提：**动态重定位**（静态重定位的进程不能搬）；代价：移动开销大。
- 出路二 **对换（swapping）**：把内存中暂时不运行的进程换出到外存**对换区**（对换区采用连续分配、追求速度），要运行时再换入——这正是 01 篇中级调度的机制本体，靠它浮动调节**多道程序度**。
- 粒度辨析：对换以**整个进程**为单位换出（进程级、中级调度），是虚拟存储的**前身**；后来的请求分页以**单个页**为单位部分换出（§5），不必搬动整个进程。

## 3. 分页：等大切块

### 3.1 概念与地址结构

- 进程逻辑空间切成等大的**页**，内存切成同大的**页框（帧）**，页装进帧、**离散存放**——用"每页都能找到家"替代"整体必须连续"。
- 页大小典型 4KB = 2¹²：页大小是 2^k → 逻辑地址**低 k 位是页内偏移，高位是页号**。
- **一维地址**【辨析】：页式逻辑地址就是一个数（如 0x2A7F），系统按位数**自动**拆出页号和偏移；分段才是用户显式给两维（§4）。
- 碎片口径：**无外零头，有内零头**——只有最后一页可能装不满，平均浪费半页。

### 3.2 页表与基本地址变换

页表：每页一行，记该页**所在页框号**；页表寄存器 PTBR 存页表基址与长度。

```text
逻辑地址 → 拆（页号 P, 偏移 W）
  → P ≥ 页表长度？→ 越界中断（页式只查页号，偏移天然 < 页大小）
  → 查页表[P] 得页框号 F
  → 物理地址 = F × 页大小 + W（位拼接：F 拼在高位 | W 低位）
```

例：页大小 4KB，逻辑地址 0x2A7F → 页号 0x2、偏移 0xA7F；页表项 2→6 → 物理地址 **0x6A7F**。
十进制同法：页大小 1KB，逻辑地址 2500 → 页号 2500 div 1024 = 2、偏移 2500 mod 1024 = 452。

### 3.3 快表 TLB：把两次访存压回一次

- 问题：页表放在内存 → 每次取数**两次访存**（查页表 + 取数）。
- **快表 TLB**（translation lookaside buffer）【必背】：一组**相联存储器**，缓存**最近使用的页表项副本**（页号→页框号）。命中则免查内存页表；未命中查页表并回填。
- 有效访问时间（TLB 查询 t₀、访存一次 t、命中率 a）【必背公式】：

```text
EAT = a × (t₀ + t) + (1−a) × (t₀ + 2t) = t₀ + 2t − a·t
```

例：t₀ = 20ns、t = 100ns、a = 90% → EAT = 0.9×120 + 0.1×220 = **130ns**（无快表 200ns）。

### 3.4 多级页表：给页表也分页

- 问题：32 位地址、4KB 页、4B 页表项 → 页数 2²⁰ → **页表 4MB**，且要求**连续存放**、每进程一份——页表自己成了"大程序"。
- 方案：页表本身也分页。地址结构 **外层页号 10 位 | 内层页号 10 位 | 偏移 12 位**：外层页表仅 1024 项（4KB 一页装下），二级页表各自离散存放、按需建立。
- 代价：**空间省了，访存多了**——无快表时取一次数要 **3 次访存**（查外层 + 查二级 + 取数），多级页表下快表更不可少。

## 4. 分段与段页式：按逻辑切

### 4.1 分段

- 按程序**逻辑意义**划分：主程序段、子程序段、数据段、栈段……段内连续、段间离散。
- 段表：**段长 + 基址**。逻辑地址**二维** (S, W)：用户显式给出段号与段内偏移。
- 变换：查段表[S] → **越界检查 W < 段长**（页式的偏移天然小于页大小、免查；段式必须查）→ 物理地址 = 基址 + W。
- 共享与保护：按**逻辑单位**共享/保护，分段天然方便（页无逻辑意义、难共享）；前提是**可重入代码（纯代码）**——运行中自身不被修改，各进程只配私有数据区。

### 4.2 分页 vs 分段

| 维度 | 分页 | 分段 |
|---|---|---|
| 划分依据 | **物理**划分，对用户**透明** | **逻辑**划分，用户**可见** |
| 大小 | 固定（系统/硬件定） | 不定（按逻辑意义） |
| 地址空间 | **一维**（一个数自动拆） | **二维**（段号 + 偏移显式给） |
| 碎片 | 内零头（最后一页） | 外零头 |
| 出发点 | 系统管理：提高内存利用率 | 用户需要：模块化、共享、保护 |

### 4.3 段页式

先分段、段内再分页：逻辑地址 = (段号 S, 段内页号 P, 页内偏移 W)；每进程一张段表（指向**每段一张页表**）。变换无快表要 **3 次访存**（查段表 → 查页表 → 取数）。碎片：段内按页分配 → **有内零头、无外零头**。

## 5. 虚拟存储与请求分页

### 5.1 动机与理论根基

- 常规存储管理两特征：**一次性**（作业一次全装入）、**驻留性**（装入后全程赖在内存）——大作业装不下、多道度上不去，与死锁预防"一次申请全部"是同一种浪费。
- **局部性原理**【必背】：**时间局部性**——刚被访问的指令/数据很快再次被访问（循环、重复引用）；**空间局部性**——刚被访问单元附近的单元很快被访问（顺序执行、数组遍历）。所以**一次只装一部分，大体也够用**——虚拟存储的理论根基。

### 5.2 虚拟存储器定义

基于局部性原理：作业装入时**部分装入**、运行中**按需调入**、内存不够时**换出**，从**逻辑上**扩充内存容量。三特征——

1. **多次性**：作业分多次调入内存（对"一次性"）；
2. **对换性**：运行中可换入换出（对"驻留性"）；
3. **虚拟性**：逻辑容量 >> 物理容量，容量上限由**地址结构（机器位数）**决定——32 位机 4GB；实际可用 ≤ min(2ⁿ, 内存 + 对换区)。

虚拟存储器有**三种实现方式**：**请求分页**（主流，本篇 §5.3 展开）、**请求分段**（缺段中断，配合动态链接与共享段，见 §10）、**请求段页式**——都是在基本离散分配方式上再加"按需调入 + 置换"功能。

> 教材差异注记：汤书把各策略揉在 5.2/5.3 展开；Stallings 8.2 按"取页/放置/置换/驻留集管理"四类策略组织，框架更清楚——两书口径一致，只是组织方式不同，复习时可互为对照。

### 5.3 请求分页：分页 + 请求调页 + 页面置换

请求页表在基本页表上扩四个字段【辨析】：

| 字段 | 作用 |
|---|---|
| 状态位 P（存在位） | 该页是否已在内存——缺页中断的开关 |
| 访问字段 A | 记录最近是否被访问（Clock/近似 LRU 的原料） |
| 修改位 M | 被改过 → 淘汰时必须写回外存；没改 → 直接丢弃 |
| 外存地址 | 该页在磁盘上的位置 |

### 5.4 缺页中断：机制链

```text
地址变换 → 查页表发现 P = 0 → 产生缺页中断
  → 保护 CPU 现场，转缺页中断处理程序
  → 内存有空闲页框？
     有 → 直接分配
     无 → 按置换算法选一页淘汰（M = 1 先写回外存）
  → 从外存调入所缺页（期间请求进程**阻塞**、让出 CPU；磁盘 I/O 完成后由中断唤醒、回就绪队列重新排队）→ 修改页表（P = 1，填页框号）
  → 恢复现场，重新执行被中断的那条指令
```

缺页中断 vs 一般中断【辨析·必背】：
- 一般中断在**指令周期结束后**检查响应；缺页中断在**指令执行期间**产生并立即处理；
- 一条指令可能**多次缺页**（指令、操作数跨页）；
- 缺页中断属于**内中断（异常/故障）**，信号来自 CPU 内部而非外设。

### 5.5 缺页率的代价：EAT 的缺页版

```text
EAT = (1−p) × ma + p × 缺页处理时间
```

ma = 100ns、缺页处理 8ms：p = 10⁻⁴ → EAT ≈ 100ns + 800ns = **0.9μs，放大 9 倍**。缺页处理是毫秒级磁盘 I/O，缺页率必须压到 10⁻⁵ 量级，EAT 才接近无缺页水平——这就是 §6 置换算法与 §7 工作集存在的意义。

## 6. 页面置换算法：谁出局

### 6.1 OPT 最佳置换

淘汰**以后最长时间不再被访问**的页。缺页率最低，但需要"未来知识"、**无法实现**——定位是其他算法的**性能基准**（本篇主例上 OPT 3 帧仅缺 7 次）。

### 6.2 FIFO 与 Belady 异常

淘汰**最早进入内存**的页。实现最简单（一个队列），但与访问局部性无关——最早进来的页可能马上要用。

**Belady 异常**【必背】：FIFO 算法下，**页框增多、缺页次数反而可能增加**。主例（访问串 1,2,3,4,1,2,5,1,2,3,4,5）：

```text
3 页框 FIFO：缺页 9 次
  1F 2F 3F 4F(逐1) 1F(逐2) 2F(逐3) 5F(逐4) 1H 2H 3F(逐1) 4F(逐2) 5H
4 页框 FIFO：缺页 10 次 ← 页框多了，缺页反而多了
```

3 帧完整推演（列为三个页框，格内数字 = 该框当前存放的页，— = 空框）：

### 6.3 LRU 最近最久未使用

淘汰**过去最长时间未被访问**的页——OPT 往前看（未来），LRU 往回看（历史），局部性好的程序上两者接近。
- **栈式算法**：帧数越多、驻留页集合只增不减（嵌套）→ **没有 Belady 异常**（同串 4 帧仅缺 8 次）。
- 代价：每条访存指令都要更新计数器/栈，纯软件实现开销大 → 现实系统用 Clock 近似。

### 6.4 Clock 置换（NRU，近似 LRU）

每页一个**引用位 A**（被访问时硬件置 1），页框排成环形，扫描指针逐帧走：

```text
指针所指帧：A = 1 → 清 0，指针前移（给它一次机会）
           A = 0 → 淘汰该页，装入新页，指针前移
```

| 4 | F（逐 2） | 5 | 3 | 4 |
| 5 | H | 5 | 3 | 4 |

主例 3 帧缺页 9 次——性能逼近 LRU，开销只要一位。

**改进型 Clock**（增强型二次机会）：简单 Clock 只看引用位 A，改进型再把**修改位 M**也用上，按 (A, M) 把帧中页面分四类：

| A | M | 含义 | 真要淘汰时的代价 |
|---|---|---|---|
| 0 | 0 | 最近没访问、也没修改 | **最小**：直接淘汰，不用写盘 |
| 0 | 1 | 最近没访问、但修改过 | 淘汰前必须**写回外存** |
| 1 | 0 | 最近访问过、没修改 | 很可能很快再用，不该淘汰 |
| 1 | 1 | 最近访问过、且修改过 | 不该淘汰；真淘汰时还要写盘 |

扫描分两圈（从指针当前位置开始）：

```text
第一圈：只找 (0,0)，找到立即淘汰；遇到其他组合一律跳过，不动任何位
第二圈：第一圈失败才启动——找 (0,1)，找到淘汰（先写回）；
        途中把经过的 A=1 页的访问位清 0
若第二圈仍失败：所有页 A 已被清 0，再从第一圈扫起，必能找到 (0,0) 或 (0,1)
```

例：3 帧、指针指帧1，帧中状态 页2(1,1)、页5(1,0)、页7(0,1)，缺页需装入页9：

| 圈次 | 帧1 页2 | 帧2 页5 | 帧3 页7 | 结果 |
|---|---|---|---|---|
| 第一圈 | (1,1) 跳过 | (1,0) 跳过 | (0,1) 跳过 | 失败 |
| 第二圈 | 清 A →(0,1)，跳过 | 清 A →(0,0)，跳过 | (0,1) **淘汰（写回）** | 装入页9，指针前移到帧1 |

- 为什么第二圈要顺手清 A：第一圈跳过的全是 A=1 的页，清 0 后变成 (0,0)/(0,1)，保证再扫一圈必有结果、不会死循环。
- 相比简单 Clock 的好处：除了"最近用没用"还考虑"脏不脏"——脏页淘汰要一次写盘 I/O，被排到第二圈，能省一次磁盘写；代价是最坏要扫近两圈，队列大时扫描更贵。

### 6.5 置换范围与调入策略

**局部置换**只在**本进程驻留集**内挑淘汰页，**全局置换**在整个空闲帧池挑。驻留集（进程实际占有的帧集合）怎么定、淘汰范围怎么给，组成三种管理方式：

| 管理方式 | 做法 | 评价 |
|---|---|---|
| 固定分配 + 局部置换 | 进程帧数运行期不变，缺页只在自己帧内淘汰 | 简单、进程互不影响；帧数事先难定——太少频繁缺页、太多浪费 |
| 可变分配 + 全局置换 | OS 维护空闲帧池：缺页先取空闲帧，池子空了就从别的进程借帧 | 最灵活、最常用；进程互相影响、缺页率波动大 |
| 可变分配 + 局部置换 | 缺页先局部置换；OS 持续观察各进程缺页率，再单独增减它的帧数 | 最合理但实现最复杂；抖动被限制在单个进程内 |

调入策略：**请求调页**（缺了才调，主流）与**预调页**（预测调入，常配合程序启动）。

> 衔接 §7：正因为全局置换允许一个进程"偷"其他进程的帧，它缺页太多会连带压低别人的驻留集——**全局置换比局部置换更容易引发系统级抖动**；局部置换下再严重的缺页也只拖垮它自己。

## 7. 抖动与工作集

**抖动（thrashing）**【必背】机制链：

```text
进程分到的页框 < 它的工作集
  → 刚换出的页马上又要用 → 频繁缺页
  → CPU 大部分时间在等调页 → CPU 利用率骤降
  → 调度器误判"CPU 空闲"，提高多道程序度、再挤进新进程
  → 内存更紧张、缺页更频繁 → 恶性循环
```

- **工作集** W(t, Δ)：时刻 t 之前 Δ 次访问（工作窗口）内进程**实际访问页面的集合**，是局部性原理的量化。Δ 太小装不下局部性 → 频繁缺页；Δ 太大把久未用的页也算进来 → 浪费内存。
- 结论【必背】：**驻留集 ≥ 工作集**，进程才能有效运行；多道程序度受"Σ工作集 ≤ 物理内存"约束，OS 按工作集给进程分配帧。
- 加载控制一行：低于抖动线才准入新进程——**L=S 准则**（缺页平均间隔 = 缺页处理时间）、**50% 准则**（分页设备利用率 ≤ 50%）。

## 8. 典型题型与方法

**题型① 地址变换计算**（页式/段式/段页式通用）：
入口三步——①页大小 = 2^k → 低 k 位是偏移；②按位拆页号/偏移（十六进制按位数直接拆，十进制 div/mod）；③查表得页框号（段式先查段长做越界判断）→ 拼接物理地址。段页式先查段表定位该段的页表，再查页表。

**题型② EAT 计算**：先问两件事——有没有快表？有没有缺页？TLB 版 `t₀ + 2t − a·t`；缺页版 `(1−p)·ma + p·缺页处理`。口径：TLB **命中还要 1 次访存取数**，别把 hit 算成 0 次访存。

**题型③ 置换算法推演大题**：表格法——列是页框、行是访问序列，每格标 F/H 与被逐页号。OPT 往**后**找下次使用最远的驻留页；LRU 往**前**找最久未用的驻留页；FIFO 只看进入次序、与访问无关。Belady 判断题只对 FIFO 成立。改进 Clock 别忘扫过的 A 要清 0。

**题型④ 动态分区分配**：先按算法排空闲区（FF/NF 地址序、BF 容量升序、WF 容量降序），逐作业切割更新；回收时检查**前邻、后邻**是否空闲，能合则合（最多三区并一块）。问"某作业能否装入"：外零头**总容量**够 ≠ **单块**够，分别判断。

**题型⑤ 页表/位数计算**：页表项数 = 2^页号位数；页表大小 = 项数 × 项长；页号位数 = log₂(逻辑空间 / 页大小)。多级页表拆分：先定偏移位数（由页大小），剩下的位数按"每级页表恰好一页装得下"分配。

**题型⑥ 概念辨析**：页/段（一维二维、透明可见、内零头外零头）、缺页中断/一般中断（执行期间、可多次、内中断）、抖动/缺页多（抖动是缺页率高到 CPU 利用率崩溃的恶性循环，缺页多未必抖）、虚拟容量/物理容量（上限由地址位数定）。

## 9. 易错点

- "分页消除所有碎片"：错，分页**无外零头但仍有内零头**（最后一页平均半页）；产生外零头的是动态分区与分段。
- "页是逻辑划分、段是物理划分"：正好说反——页是**物理**划分（用户透明），段是**逻辑**划分（用户可见）。
- "页式逻辑地址是二维的"：错，页式是**一维**地址，页号由系统按位数自动拆出；分段才是二维。
- 内外零头张冠李戴：**内**零头在**分配出去的块内部**浪费，**外**零头散在**块与块之间**。
- "快表命中就不用访问内存"：错，TLB 命中仍要 **1 次**访存取数据（省掉的只是查内存页表那次）；未命中共 2 次访存。
- "缺页中断是外部中断"：错，它是**内中断（异常/故障）**，且在指令执行期间处理，一条指令可多次缺页。
- 缺页中断处理完"继续执行下一条指令"：错，要**重新执行被中断的那条指令**（它的访存还没完成）。
- "虚拟存储器容量 = 内存 + 外存"：错，上限由**机器地址位数**决定，是 min(2ⁿ, 内存 + 对换区)。
- "页框越多缺页一定越少"：错，Belady 异常**仅 FIFO** 可能出现（页框增多缺页反而增多）；LRU 是栈式算法，没有此异常。
- LRU 与 LFU 混淆：LRU 看**最近**是否用过，LFU 看**频率**——LFU 会把"过去热、现在冷"的页一直赖在内存。
- Clock 手推时"位 1 直接淘汰"：错，位 1 是**清 0 让路**、指针继续走；位 0 才淘汰。
- 改进型 Clock 淘汰顺序写成 (0,0)→(1,0)→(0,1)：错，是 **(0,0)→(0,1)** 两类循环扫描——先扫完"没动过"的，再把"要写回"的往后排。
- "抖动就是缺页多"：错，抖动是缺页率高到系统忙于调页、CPU 利用率崩溃的**恶性循环状态**；根因是驻留集 < 工作集。
- "静态重定位的进程可以紧凑/对换"：错，搬动需要**动态重定位**支撑，静态重定位装入后地址就定死了。
- 最佳适应选"最大的块"：错，BF 选**最小的够用块**；选最大的是 WF（最坏适应）。
