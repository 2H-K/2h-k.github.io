## 1. 为什么先学“概述”

操作系统不是一组彼此孤立的算法，而是一套管理计算机资源、为程序提供服务的系统软件。后面看到的进程、分页、文件目录和设备驱动，分别是在回答同一个问题的不同侧面：

> **怎样让多个程序方便、正确、高效、安全地使用有限的硬件资源？**

因此，本篇不展开计算题，只建立四件事：操作系统管理什么、提供什么服务、为什么需要这些机制，以及本博客各篇如何衔接。

## 2. 操作系统是什么

### 【必背】定义与地位

操作系统（Operating System，OS）是**控制和管理整个计算机系统的硬件与软件资源，合理地组织计算机工作流程，并为用户和其他软件提供方便接口与环境的系统软件**。

它位于用户/应用程序与计算机硬件之间：

```text
用户 / 应用程序
      │  用户接口、系统调用
      ▼
操作系统：处理机｜内存｜文件｜I/O｜保护
      │
      ▼
硬件：CPU｜主存｜磁盘｜键盘网卡等设备
```

“系统软件”说明 OS 不是普通应用；“控制和管理资源”说明 OS 的核心职责；“提供接口和环境”说明 OS 还要隐藏硬件细节、降低应用开发难度。

### 【辨析】操作系统的两个基本观点

| 观点 | 关注点 | 典型表述 |
|---|---|---|
| 资源管理器 | 资源如何分配、回收、保护和调度 | 管理 CPU、内存、文件和设备 |
| 用户与硬件之间的接口 | 程序如何使用硬件而不直接操作硬件 | 提供命令接口、程序接口和系统调用 |

二者不是互相排斥的定义：**资源管理是内核的核心工作，接口是资源管理对用户呈现出来的方式。**

## 3. 操作系统管理哪些资源

| 资源类别 | OS 管理的对象 | 后文对应 |
|---|---|---|
| 处理机 | 进程、线程、就绪队列、CPU 时间 | 02–04 |
| 内存 | 地址空间、页表、页面、分配与回收 | 05 |
| 外存与文件 | 文件、目录、磁盘块、空闲空间 | 06 |
| I/O 设备 | 中断、驱动、缓冲、设备分配 | 07 |
| 保护与安全 | 权限、隔离、访问控制、审计 | 安全科与相关专题 |

这张表是后续学习的导航：程序先要作为进程运行，运行时要获得内存，数据要通过文件保存，设备访问则由 I/O 子系统完成。

## 4. 操作系统的功能

### 【必背】四项核心功能

1. **处理机管理**：创建和撤销进程，组织进程并发，进行进程同步、通信和调度，处理死锁。
2. **存储器管理**：分配和回收内存，完成地址转换和存储保护，利用虚拟存储器扩大逻辑地址空间。
3. **文件管理**：组织文件和目录，管理外存空间，提供文件存取、共享和保护。
4. **设备管理**：管理 I/O 设备，提供设备分配、驱动、中断处理、缓冲和设备独立性。

此外，OS 还承担**提供用户接口、保护系统安全、处理错误和记录运行信息**等职责。

### 【辨析】操作系统的目标

操作系统的功能可以从三个目标理解：

- **方便性**：向上层提供抽象和接口，让用户与应用程序不必直接操作复杂硬件；
- **有效性**：合理分配和调度资源，提高 CPU、内存、设备等资源的利用率；
- **可扩充性**：采用模块化、分层和接口化设计，便于增加功能、移植和维护。

“功能”回答操作系统**做什么**，“目标”回答为什么这样设计。考试中不要把二者混为一谈。

## 5. 操作系统的发展与分类

### 【了解】从手工操作到现代操作系统

| 阶段 | 主要特点 | 解决的问题 |
|---|---|---|
| 手工操作 | 用户手工装入程序、运行并取走结果 | 计算机空闲时间长，人与机器交互效率低 |
| 单道批处理 | 作业成批输入，内存中一次运行一道作业 | 减少人工操作，但 I/O 时 CPU 仍可能空闲 |
| 多道批处理 | 内存中同时放入多道程序，交替使用 CPU | 提高资源利用率和系统吞吐量 |
| 分时系统 | 多个用户通过时间片轮流获得 CPU | 追求交互性和响应时间 |
| 实时系统 | 在规定时间内响应并完成任务 | 追求及时性和可预测性 |

现代系统通常同时具有多种特征，例如通用操作系统可以支持多道程序、分时交互、网络服务和实时任务。分类是观察角度，不是互相排斥的标签。

## 6. 操作系统结构：内核到底怎么组织

### 【必背】内核与操作系统的关系

**内核（kernel）是操作系统中最核心、最接近硬件并运行在特权级的部分**，负责进程与线程管理、内存管理、设备管理、中断处理、文件系统核心机制和保护等工作。

操作系统的范围通常比内核更宽：还包括系统程序、命令解释器、库、服务和用户工具。可以记成：

```text
操作系统 = 内核 + 系统程序/服务 + 用户接口与工具
```

系统调用是用户程序进入内核的受控入口；用户程序、Shell 和普通库函数不等于内核。

### 【辨析】几种典型内核结构

| 结构 | 内核中包含什么 | 优点 | 缺点/代价 | 典型理解 |
|---|---|---|---|---|
| **大内核（宏内核、单体内核）** | 进程、内存、文件、设备驱动等大部分服务都在内核态运行 | 调用路径短，性能高 | 内核庞大，模块间耦合强；一个组件出错可能影响整个系统 | Linux、传统 UNIX 通常归入此类；“宏内核/单体内核”是常见同义称呼 |
| **分层结构** | 按层次组织，各层只依赖更低层 | 接口清晰，易验证、调试和维护 | 层次划分困难，跨层调用可能降低灵活性和效率 | 由硬件层逐步向上提供服务 |
| **微内核** | 内核只保留最基本机制，如地址空间、线程、IPC、基本调度；文件系统、驱动等放到用户态服务器 | 内核小，隔离性、可靠性和可移植性较好 | 用户态服务之间需要 IPC，通信和上下文切换带来额外开销 | QNX、MINIX 体现此类思想 |
| **模块化内核** | 核心内核加可动态装载/卸载的功能模块 | 兼顾性能、扩展性和维护性 | 模块仍可能运行在内核态，错误影响范围较大 | 是实现方式或设计特征，可与大内核结合，不是与微内核并列的唯一分类 |

> **高频对比句**：大内核（宏内核、单体内核）把更多服务放在内核态，性能通常较好但内核复杂；微内核把更多服务移到用户态，隔离性和可扩展性较好但 IPC 成本更高。分层结构强调组织方式，模块化强调扩展方式，二者都可以与大内核结合，并不是“大内核/微内核”之外的第三种内核范式。

这里采用考研教材更常见的“大内核（宏内核）—微内核”对比。**模块化内核**保留为补充概念：它描述内核功能能否按模块装载、卸载，不直接回答“多数操作系统服务运行在内核态还是用户态”。

### 内核态服务与用户态服务

```text
用户态：应用程序、Shell、系统工具、部分服务进程
              │ 系统调用 / IPC
              ▼
内核态：调度、地址空间、内存保护、中断、设备访问、IPC 原语
              │ 特权指令
              ▼
硬件：处理器、主存、磁盘和各种 I/O 设备
```

这里的“内核态”是处理器运行状态，“微内核/单体内核”是内核组织结构，不能把两个维度混为一谈。

## 7. 操作系统的基本特征

### 【必背】并发、共享、虚拟、异步

- **并发**：多个程序在同一时间间隔内交替执行。并发是宏观概念；单核 CPU 上通常是交替运行，不是严格意义上的同时运行。
- **共享**：系统中的资源可被多个并发执行的程序共同使用。共享分为互斥共享和同时共享：**互斥共享**（如打印机）一段时间内只允许一个进程**物理上**访问——宏观"同时"、微观交替，须靠互斥访问技术保证；同时共享（如磁盘、内存）多个进程可在同一时间段内交叉访问，由 OS 协调分配保证各自正确。
- **虚拟**：把一个物理实体变成若干个逻辑上的对应物，例如虚拟处理器、虚拟内存和虚拟设备。
- **异步**：并发程序以不可预知的速度推进，执行顺序和完成时间可能不同，但 OS 要保证运行结果在规则范围内正确。

四个特征的关系可以这样记：

```text
并发是前提 → 资源需要共享 → 资源不足时用虚拟扩充 → 并发执行天然具有异步性
```

其中，**并发和共享是最基本的特征**；虚拟和异步是由它们引出的重要特征。

## 8. 操作系统的运行环境

### 【必背】用户态与内核态

为防止应用程序随意破坏系统，处理器通常设置用户态和内核态。应用程序运行在用户态，不能直接执行特权指令或访问受保护资源；操作系统内核运行在内核态，可以执行特权操作。

**特权指令**＝执行后将影响整个系统安全与稳定的指令，只允许在内核态执行，典型例子：关中断/开中断、设置时钟、启动 I/O、修改内存映射寄存器、切换处理器态、装载 PSW。用户态程序一旦执行特权指令，硬件立即产生异常、被迫转入内核态处理。当前处于哪种状态由 **PSW（程序状态字）的模式位**指示；进程执行系统调用或因时钟/ I/O 中断时，都会强制从用户态切换到内核态（选择题"下列哪项是特权指令"就按上面清单对号）。

程序需要 OS 服务时，通过**系统调用**进入内核：

```text
用户程序
  │ 调用库函数/系统调用接口
  ▼
陷入指令（trap）切换到内核态
  ▼
内核检查参数并执行服务
  ▼
返回用户态，用户程序继续运行
```

### 【辨析】中断、异常与系统调用

| 机制 | 主要来源 | 是否可预知 | 典型例子 |
|---|---|---|---|
| 中断 | 外部硬件事件 | 通常不可预知 | 时钟中断、I/O 完成中断 |
| 异常 | CPU 执行当前指令时发现的问题 | 通常与当前指令相关 | 缺页、除零、非法指令 |
| 系统调用 | 用户程序主动请求 OS 服务 | 可由程序主动发起 | open、read、fork |

系统调用不是普通函数调用：它会触发从用户态到内核态的受控切换。具体的系统调用、I/O 软件层次和中断处理，在 07 篇集中复习。
