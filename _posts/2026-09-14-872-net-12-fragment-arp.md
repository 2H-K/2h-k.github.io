## 2. 知识框架

```
IP 分片：链路层帧有长度上限 MTU（以太网 1500 B）
  数据报总长 > MTU → 分片，每片独立路由，只在目的主机重组
  三字段控制分片：
    标识（同一数据报的各片相同）
    标志 DF（Don't Fragment）=1 禁止分片；MF（More Fragment）=1 后面还有片
    片偏移（以 8 B 为单位，指出该片在原数据中的相对位置）
  分片对象是"数据部分"，IP 首部每片都完整复制一份

ARP（地址解析协议）：IP 地址 → MAC 地址
  同网段：ARP 请求（广播）→ 目的主机 ARP 响应（单播）
  跨网段：对"默认网关"做 ARP，MAC 逐跳更换，IP 端到端不变
  口诀：IP 定终点，MAC 定下一跳（联动 13 篇）

ICMP（网际控制报文协议）：网络层协议，IP 协议字段 = 1
  差错报告：终点不可达 / 时间超过 / 参数问题 / 改变路由（源点抑制不常用）
  查询：回送请求/应答（ping）、时间戳请求/应答
  应用：ping（回送请求+应答）、traceroute（TTL 递增 + 终点不可达）
```

- 分片三大计算字段单位：**总长度 1 B、首部长度 4 B、片偏移 8 B**
- 除最后一片外，每片的数据部分必须是 **8 B 的整数倍**——片偏移按 8 B 计数的必然要求

## 3. 简答与名词解释

### 必背

- **IP 分片**：当 IP 数据报总长度超过链路 MTU 时，路由器（或源主机）把**数据部分**切成若干片，每片加上完整 IP 首部独立传输。同一数据报的各片具有**相同标识**；除最后一片外 MF=1；片偏移以 **8 B** 为单位标明各片在原数据中的起始位置。分片可能在源主机或途中路由器发生，但**重组只在最终目的主机**进行——各片独立选路，中途路由器看不到完整数据报。路由器转发时才分片的场景要连着转发动作记：先 TTL 减 1，发现总长超出接口 MTU 才分片——每片**重填总长度、MF、片偏移**（标识三片相同），且**每片都要单独重算首部校验和**（每片首部已不同），再逐片封装转发（联动 13 篇逐跳改写）。
- **ARP 的作用与流程**：ARP 把同一局域网上的 **IP 地址解析为 MAC 地址**。流程：①主机 A 先查本机 **ARP 高速缓存**，命中则直接取出 MAC；②未命中则**广播发送 ARP 请求**（目的 MAC 全 1，"谁有这个 IP"）；③局域网上**所有**主机都收到，只有 IP 匹配的 B **单播回送 ARP 响应**（携带自己的 MAC）；④A 把映射写入缓存（有生存期）。跨网段时 A 解析的是**默认网关**的 MAC，网关转发时再逐跳解析。
- **ICMP 差错报告报文**：ICMP 用于主机/路由器传递**网络层控制和差错消息**，封装在 IP 中（协议字段 1）。差错报告四类：**终点不可达**（无法交付）、**时间超过**（TTL=0 或分片重组超时）、**参数问题**（首部字段有错）、**改变路由/重定向**（告知更优下一跳）。差错报告只报告不纠正，且**不对 ICMP 差错报文本身再发差错报告**。
- **ICMP 查询报文与应用**：查询两类：**回送请求/应答**、**时间戳请求/应答**。**ping** 用回送请求/应答测试连通性（IP 层直接调用 ICMP，无端口、无 UDP/TCP）；**traceroute** 让源主机发 TTL=1,2,3… 的分组，沿途路由器返回"时间超过"暴露自己的地址，到达终点时用不可达端口触发"终点不可达"从而定位终点。

### 辨析

- **ARP 请求广播 vs ARP 响应单播**：请求帧目的 MAC = FF-FF-FF-FF-FF-FF（广播，人人收到）；响应是单播回给请求者。跨网段 ARP 的目标是网关——"广播只在本网段传播，路由器隔离广播域"。
- **IP 地址 vs MAC 地址的角色**：IP 端到端不变（NAT 除外），MAC 逐跳改变；IP 负责全局定位，MAC 负责本段送达。ARP 是两者的翻译官，只翻译**同一链路上**的地址。
- **ICMP 差错报告 vs ICMP 查询**：差错报告是路由器/主机**主动上报异常**（单向）；查询是**一问一答**配对使用（双向）。前者常考"哪几种 + 何时发"，后者常考 ping/traceroute。
- **ping vs traceroute**：ping 测连通性与往返时延（ICMP 回送请求/应答）；traceroute 追踪路径逐跳路由器（TTL 递增 + 时间超过报文）。ping 只关心终点，traceroute 刻意让中途路由器"报错"。
- **DF=1 且超 MTU 的后果**：路由器不能分片，丢弃该数据报并回送"终点不可达（需要分片但 DF 置位）"ICMP 报文——PMTU 发现的原理。

### 了解

- 分片重组超时：目的主机收到 MF=1 的片后启动重组定时器，超时未收齐则丢弃已收分片，并可回"时间超过"（重组超时）
- 四种不发送 ICMP 差错的情况：①对 ICMP 差错报文；②对目的地址是广播/组播的数据报；③对作为链路层广播的数据帧；④对非首片分片（片偏移≠0）
- 代理 ARP、免费 ARP（IP 冲突检测）为课外拓展
- traceroute vs tracert 实现差异：Unix/Linux `traceroute` 默认用 **UDP 高端口**探测，终点靠"端口不可达（Type 3/code 3）"结束；Windows `tracert` 用 **ICMP 回送请求**探测，终点收到回送应答即结束。中途各跳一律回"**时间超过（Type 11）**"，ping 用回送请求/应答（Type 8/0）。

## 5. 计算与方法

### ① IP 分片计算（本章压轴，与 07/13 篇联动）

**触发条件**：给出待发送数据总长（常含 TCP 首部 20 B）与链路 MTU，求分片情况。

**步骤**：
1. **先扣 IP 首部**：每片可装数据上限 = MTU − 20（IP 首部），向下取整到 **8 的倍数**（片偏移要求）
2. 分片对象：应用数据 + TCP 首部 20 B（TCP 报文段整体是 IP 的"数据"）
3. 分片数 n = ⌈数据总长 / 每片容量⌉；前 n−1 片装满，最后一片装剩余
4. 每片填表：总长 = 数据片长 + 20；MF（最后一片 0 其余 1）；片偏移 = 本片数据起点 / 8
5. 检验：各片数据之和 = 原数据总长；片偏移递增 = 前片数据长 / 8

**自编例题**：TCP 报文段共 820 B（含 20 B TCP 首部），MTU = 380 B，IP 首部 20 B。
- 每片容量 = 380 − 20 = 360 B → 向下取 8 的倍数 = **360 B**（360 ÷ 8 = 45 整除，无需再调）
- 分片数 = ⌈820 / 360⌉ = **3 片**：360 + 360 + 100
- 各片参数：

| 片 | 总长度 | 数据 | MF | 片偏移 |
|---|---|---|---|---|
| 1 | 380 | 360 | 1 | 0 |
| 2 | 380 | 360 | 1 | 45 |
| 3 | 120 | 100 | 0 | 90 |

**自编例题 2（必踩坑版）**：题目说"应用层交付 800 B 数据，TCP 头 20 B，IP 头 20 B，MTU=576"。
- IP 的"数据"= 800 + 20 = **820 B**（应用数据连 TCP 首部一起被分片）
- 每片容量 = 576 − 20 = 556 → 取 8 的倍数 **552 B**（556/8=69.5 → 552 = 69×8）
- 分片数 = ⌈820/552⌉ = **2 片**：552 + 268；第二片偏移 = 552/8 = 69

### ② ARP 跨网段流程（综合题常考一跳）

**触发条件**：主机 A（网 1）发数据给主机 B（网 2），问 MAC/IP 如何变化。

**步骤**：
1. A 判断 B 不在同网（掩码与运算）→ 交给网关 R
2. A 对 **R（网关）**做 ARP：请求广播，R 回单播；帧：源 MAC=A，目的 MAC=R
3. R 路由转发到网 2：**重写帧头**，对 B 做 ARP（或查缓存），帧：源 MAC=R'，目的 MAC=B
4. 全程 **源/目的 IP 一直是 A 和 B**；**MAC 每段链路换一对**

### ③ ICMP 应用机制

**触发条件**：问 ping/traceroute 用了什么报文/机制、哪种 Type。

**ping**：发送 ICMP **回送请求（Type 8）** → 目的回 **回送应答（Type 0）**；测 RTT、丢包；**无需端口号**（不上 UDP/TCP，直接封装于 IP）。

**traceroute（Unix/Linux）/ tracert（Windows）** 共用"TTL 递增 + 逐跳报错"原理：
1. 发 TTL=1 分组 → 第一跳路由器 TTL 减为 0，回 **时间超过（Type 11）**，暴露其地址
2. TTL=2 → 第二跳回时间超过……逐跳描绘路径
3. 到达终点判定结束，两者实现不同：
   - **Unix traceroute**：发 **UDP** 报文到不可达的大端口（如 33434 起），终点回 **终点不可达（Type 3，code 3 端口不可达）**
   - **Windows tracert**：发 **ICMP 回送请求（Type 8）**，终点直接回 **回送应答（Type 0）**

## 6. 本节易错点

常见坑：
- 分片计算**忘减 IP 首部 20 B**，或**忘记把 TCP 首部 20 B 算进"数据"**——两个 20 B 一个都不能少
- 每片容量**没向下取 8 的倍数**：MTU−20 不整除 8 时必须截到 8 的倍数，否则片偏移没法表示
- "分片在目的主机重组"：对；"中间路由器可重组"：错——各片独立选路，可能走不同路径
- "片偏移以字节为单位"：错，以 **8 B** 为单位；算完记得除 8
- "ARP 响应也是广播"：错，**请求广播、响应单播**
- "跨网段通信 ARP 解析目的主机的 MAC"：错，解析的是**网关**的 MAC；MAC 不出网段
- "ICMP 有端口号"：错，ICMP 是网络层协议直接封装于 IP（协议字段 1），**无端口**
- "ping 用了 UDP"：错，ping 直接用 ICMP 回送请求/应答
- "对 ICMP 差错报文再发 ICMP 差错报告"：错，四种不发送情形之首
- "TTL=0 源主机收到通知是终点不可达"：错，是**时间超过**
