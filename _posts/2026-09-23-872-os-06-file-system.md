## 2. 文件与打开：从用户视角说起

### 2.1 文件与文件系统

- **文件是什么**：以计算机硬盘为载体、存储在计算机上的**相关信息的集合**（具有文件名的一组信息）。最小分配单位是**盘块（块）**。
- **文件系统**【必背】：OS 中负责管理文件的软件机构，管理文件存储空间（外存块的分配回收）、实施按名存取（目录检索）、完成保护与共享。理解成"外存的记账系统 + 名字到盘块的翻译器"。
- 逻辑结构（用户看到什么）与物理结构（系统怎么存）是两条线【辨析】：用户按**记录/字节**组织文件，系统按**盘块**存放，两者的映射就是本篇的分配方式。

### 2.2 文件的逻辑结构 / 文件组织方式（给用户看）

**逻辑结构 = 用户视角上记录怎么排**，和物理结构（§4 的盘块分配）是两条独立线：一条管"记录怎么组织、凭什么定位记录"，一条管"这些记录落到哪些盘块"。

本节只有两个考点：**给定一个组织方式，能一句话说清定义；给定一个场景，能说清该选哪个、依据是什么**。不考代码，考的是判据。

主线按 Stallings 的五分法（老师上课的分类，教材 12.2 节），另加汤小丹的**无结构文件**，一共六类。

| 组织方式 | 一句话定义 | 典型场景 | 选它的依据 |
|---|---|---|---|
| **无结构文件（流式文件）**【汤】 | 不划分记录，整个文件就是一串字节（字符）的集合，长度按字节计 | 文本、源码、可执行文件；UNIX 所有文件 | 内容本身没有记录边界、长度不定，解释交给上层工具 |
| **堆文件 pile** | 记录按到达顺序堆积，无次序；每条记录由一串数据项组成，不同记录可有不同的域 | 日志、审计记录、邮件暂存等"先采集后处理"的数据 | 空间利用好、追加修改容易；只能穷举查找 |
| **顺序文件 sequential** | 记录等长、格式固定，由数量固定、长度固定、顺序固定的域组成，按关键域排序存放 | 批处理主文件、工资单与计费、磁带上的文件 | 批量顺序处理最快（连续块一次读入）；定长可直接算地址 |
| **索引顺序文件 indexed sequential** | 顺序文件 + 稀疏索引：按关键域排序分块，索引只记每块第一条记录的键，插入先进溢出文件 | 大主文件以顺序处理为主、偶尔按键定位（ISAM） | 折中：按键查找由 N 降到 √N 量级，主体仍顺序存放 |
| **索引文件 indexed** | 记录不排序、位置任意，只能经索引表访问；索引项 = 关键域 + 地址，可建多张索引 | 变长记录、需按多个关键字随机检索、频繁插删 | 位置不受限，插删不必挪动记录；代价是索引占空间 |
| **直接文件（散列文件） direct / hashed** | 关键域的值经散列函数直接算出记录地址 | 符号表、按键等值查找、不要求顺序的表 | 一次散列一次 I/O，平均接近常数；冲突要溢出处理 |

#### 2.2.1 无结构文件（流式文件）【汤小丹】

- **定义**：文件是"一组相关信息的集合"，但内部**不划分记录**，就是一串字节；读写以字节为单位，文件长度按字节数计。
- **场景**：纯文本、源代码、可执行文件、配置文件；UNIX 干脆把目录、设备都抽象成字节流文件。
- **依据**：内容本身没有固定的记录边界、记录长度可变，硬划记录反而添麻烦，把解析交给应用（按换行/分隔符自己切）。
- **对照**：有结构文件（记录型）才谈得上"记录组织方式"，下面五类都在有结构文件的范围内；两者怎么选，判据是"内容里有没有固定的记录边界"。

#### 2.2.2 堆文件（pile）：逻辑上就是顺序文件的"串结构"

- **定义**：最简单的组织形式。数据按它们到达的顺序被收集，每条记录由一串数据项组成；不同记录可以有**不同的域**，或者域相似但**顺序不同**。
- **域的自描述**：每个域都要能自我描述，包含域名和值；域的长度要么由分隔符隐式指定，要么明确包含在某个子域里，要么取该域类型的默认长度。
- **检索方式**：记录之间没有结构关系，**只能穷举**——找某条记录要逐条检查直到命中或查完全文；要找"某域取值等于某值"的所有记录，也必须查完整个文件。
- **场景与依据**：适合数据在处理前先采集并存储、或数据难以组织的场合；保存大小与结构各不相同的数据时**空间使用情况很好**，且**易于追加与修改**。
- **局限**：除这些受限用途外对多数应用不适用，因为不支持按键快速定位，读一条记录也要付出扫描代价。
- **与汤本对齐**：汤小丹把它叫**堆积文件**，并把"按到达先后、无排序"的组织形式归为顺序文件的**串结构**。答题时按 Stallings 说"堆文件（pile）"，紧跟一句"逻辑上即顺序文件的串结构"，两本书就都点到了。

#### 2.2.3 顺序文件（sequential）

- **定义**：最常用的组织形式。每条记录使用同一种固定格式，**所有记录长度相同**，由相同数量、长度固定的域按特定顺序组成；域的**域名和长度是文件结构的属性**，记录里只存各域的值。
- **关键域**：唯一标识一条记录，通常是第一个域；记录按关键域排序存放——文本按字母序，数字按数值序。
- **定长带来什么**：第 i 条记录位置 = 起点 + (i-1)×记录长度，**按记录号一次 I/O 直接算出地址**，所以顺序文件也能随机访问；若记录变长，序号不能直接换算，只能从头顺扫，这就是"定长"是硬要求的原因。
- **场景**：批处理主文件，按关键域整批处理（计费、工资单、成绩单），磁带等顺序介质；读法是"读一块 → 连续处理一批"。
- **代价**：插入删除要挪动后续记录或重写整个文件，顺序查找平均 N/2 次；维护难，于是引出下面两种。

#### 2.2.4 索引顺序文件（indexed sequential）

- **结构**：主文件（顺序存放）+ 索引（稀疏索引）+ 溢出文件，三件套。
- **索引项**：键 = 每组（每块）第一条记录的关键域，指针 = 该组的起始地址。
- **查找**：查索引定位到组，组内顺扫；比较次数从 N 降到 **√N** 量级。
- **算一遍**：10000 条记录，顺序查找平均 5000 次；分成 100 组（每组 100 条），先查索引（平均 50）再组内（平均 50）→ 平均 **100** 次。
- **插入**：直接追加进**溢出文件**，不破坏主文件顺序；但溢出链变长会拖慢查找，需要周期性**重组**（把主文件与溢出文件合并重排）。
- **场景与依据**：文件很大、以顺序处理为主但偶尔按键定位——纯顺序查找太慢，纯索引又让索引本身过大且失去连续 I/O，"顺序 + 稀疏索引"正好折中，对应 ISAM 一类实现。
- **汤本对齐**：汤小丹同样叫索引顺序文件，并区分**一级索引 / 多级索引**，多级索引就是"索引的索引"。

#### 2.2.5 索引文件（indexed）

- **定义**：记录**不按关键域排序**、位置任意，只能通过索引访问；索引项 = 关键域 + 记录地址。
- **完全索引与部分索引**：完全（稠密）索引为每条记录设一项；部分（稀疏）索引只为每组"锚点"记录设项，组内再顺扫。
- **多张索引**：可为不同关键域各建一张索引（如按学号、也按姓名），一个文件对应多套检索入口。
- **场景与依据**：记录变长、需按多个关键字随机检索、插删频繁又不想挪动数据——记录位置不受限，插删只改索引项；代价是索引本身占空间并要维护，**顺序遍历变成按索引顺序跳读**，失去顺序文件的连续 I/O。
- **辨析**：索引文件 ≠ 索引顺序文件。前者记录无序、全靠索引；后者记录有序、索引只作"分组入口"。

#### 2.2.6 直接文件（散列文件）

- **定义**：用关键域的值经**散列函数**直接算出记录所在地址（块/桶），既不排序也不建索引。
- **场景与依据**：按键等值的高频访问、不要求顺序的场景（符号表、目录、查找表）；理想情况一次散列算地址、一次 I/O 命中，平均接近常数。
- **代价**：不同键可能散列到同一地址（冲突），要溢出链/开放定址等办法；散列函数设计直接影响均匀性；**不支持范围查询和顺序扫描**，因为记录顺序与键序无关。

#### 2.2.7 选型判据与答题模板

依次问四个问题，基本就能定：

1. **内容里有没有固定的记录边界？** 没有 → 无结构文件（流式）。
2. **记录结构与顺序统一吗？** 不统一、只追加不按键查 → 堆文件。
3. **记录是否等长、是否按关键域排序？** 是，且以整批顺序处理为主 → 顺序文件。
4. **文件很大、以顺序为主但还要按键定位？** → 索引顺序文件。
5. **记录变长、要按多个关键字随机查、插删频繁？** → 索引文件。
6. **只要按键等值快速命中、不要顺序和范围？** → 直接文件（散列）。

压成一句答题模板：

```text
记录无边界、按字节用 → 无结构（流式）
结构不统一、先堆后排 → 堆文件（顺序文件的串结构）
等长 + 按关键域排序 + 批量顺序为主 → 顺序文件
大文件 + 顺序为主 + 按键定位 → 索引顺序文件
变长 / 多关键字 / 频繁插删 → 索引文件
按键等值、不要顺序 → 直接（散列）文件
```

两条底层判据记住就够用：**记录长度是否固定**决定"能不能直接算出地址"；**是否按键随机访问**决定"要不要索引"。

#### 2.2.8 两本教材的术语对照

| 本笔记（Stallings 主线） | 汤小丹对应说法 | 要点 |
|---|---|---|
| 无结构文件 stream file | 无结构文件（流式文件） | 两边一致；汤把"有无结构"作为第一层分类 |
| 堆文件 pile | 堆积文件（堆），归入顺序文件的**串结构** | 汤把"按到达顺序"看作顺序结构的一种 |
| 顺序文件 sequential | 顺序文件（**串结构**与**顺序结构**两支） | 串结构看堆文件；顺序结构才按关键域排序 |
| 索引顺序文件 indexed sequential | 索引顺序文件（一级/多级索引） | 名称相同，汤强调索引层数 |
| 索引文件 indexed | 索引文件 | 汤强调索引表项 = 关键字 + 记录地址 |
| 直接文件 / 散列文件 direct, hashed | 直接文件（又称散列文件） | 名称与思路一致 |

- 汤小丹的主干是**顺序、索引、索引顺序**三类，堆与直接文件作为补充出现；Stallings 明确列五类。答题时按老师的五分法走，末尾用括号带上汤的叫法，两边都不丢分。
- 附：**访问方式**与组织方式配套——顺序文件配顺序访问（定长还能直接访问），索引/索引顺序配索引访问，散列文件配直接（散列）访问；记录成块（块因子）决定一次 I/O 能带进多少条记录，归 §10 回教材。

### 2.3 FCB 与索引结点：文件的"身份证"

- **FCB（文件控制块）**：存放文件全部描述信息，基本信息（名、物理位置、结构）、存取控制信息（权限）、使用信息（时间、当前状态）。**目录文件 = FCB 的有序集合**（目录也是文件）。
- **索引结点（i-node）**：检索目录时只比**文件名**，FCB 其余字段是陪跑，把它们抽出去放进 i-node，目录项瘦身为"**文件名 + i-node 编号**"。
- **提速原理**：目录项变瘦 → 目录占块少 → 检索的磁盘 I/O 次数减少（算例见 §6.3）。
- **两个索引结点**：**外存索引结点**（磁盘 i-node，长期保存）与**内存索引结点**（打开文件时从外存复制进来的副本）。内存索引结点比外存索引结点**多两个字段**：**当前打开文件的计数**（有多少进程正打开该文件）与**当前文件在内存中的物理地址**（数据块在内存中的位置）。
- 三个"计数"别混：**外存 i-node 的链接计数 links**（硬链接数，减到 0 才释放盘块）、**内存索引结点的当前打开文件的计数**（关到最后一个进程才回收）、**系统打开文件表的引用计数**（关到最后一个进程表项撤销才回收），名字与所在位置各不相同。

### 2.4 打开文件表：按名存取只付一次代价

```text
open(path) → 按名逐级检索目录 → 找到 FCB / 索引结点
  → 复制到内存打开文件表（系统表 + 进程表各一表项）
  → 返回文件描述符 fd
  → 之后 read/write/close 全用 fd 定位，不再检索目录
close → 进程表项撤销，系统表引用计数减到 0 才真正撤销
```

- 这就是 02 篇 PCB"打开文件表"的本体；**打开一次、反复使用**是文件读写的效率前提。
- 02 篇的管道就是这种"共享文件"：写端写入、读端读出，定长缓冲满了写者阻塞，文件机制在进程通信里的化用。

## 3. 文件系统的层次结构与磁盘布局

### 3.1 文件系统的层次结构【必背概念】

文件系统模型分为**三层**（自底向上），中间的软件集合层内部再细分为四个子层：

```text
③ 文件系统接口（最高层）：命令接口（终端命令）＋程序接口（系统调用 open/read/write/close）
② 对对象操纵和管理的软件集合（核心层），自顶向下四个子层：
     逻辑文件系统       按符号文件名访问、管理记录与文件、文件保护（§6、§7.2）
     基本 I/O 管理程序  逻辑块号→物理块号、空闲盘块管理、I/O 缓冲指定（§4、§5）
     基本文件系统层     内存 ⇄ 磁盘之间数据块的交换
     I/O 控制层         磁盘驱动程序等设备驱动程序（07 篇）
① 对象及其属性（最低层）：文件、目录、磁盘存储空间
```

- 一句话：**逻辑文件系统管"名字、记录与保护"，下面三层管"盘块与物理"**；某层软件只能调用同层或更低层的模块。
- 对应关系：逻辑文件系统 = 目录（§6）与保护（§7.2）、基本 I/O 管理程序 = 分配方式（§4）与空间管理（§5）、I/O 控制层 = I/O（07 篇），这一张图就是本篇的目录。

> **另一套口径对照**（自顶向下 7 层）：用户接口 → 文件目录系统 → 存取控制验证 → 逻辑文件系统与文件信息缓冲区 → 物理文件系统 → 辅助分配模块 → 设备管理模块。对应关系：目录、存取控制两层合入上面的"逻辑文件系统"；物理文件系统、辅助分配对应"基本 I/O 管理程序"；设备管理对应"基本文件系统层 + I/O 控制层"。两套说法只是切分粗细不同，职责完全对齐，答题先看题目用哪套名词。

### 3.2 文件系统在磁盘上的布局

```text
引导块 | 超级块 | i-node 区（索引结点表） | 数据区
```

- **引导块**：本分区/本卷开头存放的引导代码，格式化文件系统时写入；可独立于本文件系统内容。Unix 卷布局里它常在分区第 0 块，对应下面的 **PBR**，不是整盘第 0 扇区的 MBR。
- **超级块**：文件系统的"总说明书"，盘块总数、空闲块数、i-node 总数与起点、空闲盘块号栈（成组链接法 §5.3 的"栈"就住在这里）等。
- **i-node 区**：所有文件的索引结点集中连续存放，按编号可直接定位。
- **数据区**：文件数据块与目录文件的数据块（目录也是文件，数据块里放目录项）。
- 记忆：`引导 → 超级 → 索引 → 数据`；挂载（mount）时先读超级块、定位根目录 i-node，再把该文件系统挂到目录树某节点上，与根文件系统融为一体。

### 3.3 操作系统引导【必背】

考纲第 1 章条目，落点在本篇：先分清「整盘入口」和「分区入口」，再背链式流程。口径按传统 **BIOS + MBR**；UEFI 另见文末一句。

```text
整盘第 0 扇区（不属于任何分区）
  MBR = 磁盘引导程序 446 B + 分区表 64 B + 55AA
每个分区第 0 扇区
  PBR = 分区引导程序 + 本分区文件系统参数
活动分区根目录
  启动管理器（完整 OS 初始化程序）
```

| 名词 | 位置 | 存什么 | 干什么 |
|---|---|---|---|
| **MBR 主引导记录** | 整盘第 0 扇区（LBA 0），512 B，**不属于任何分区** | **磁盘引导程序**（主引导程序）446 B + **分区表** 4×16 B + 结束标志 `55AA` | 整盘入口：找到活动分区，把它的首扇区读进内存 |
| **磁盘引导程序** | MBR 前 446 字节 | 可执行代码 | 扫分区表，定位活动分区，加载该分区的 PBR |
| **分区表** | MBR 偏移 446 起 64 字节 | 最多 4 个主分区项：起止、类型、活动标志（`80h`） | 告诉磁盘引导程序 OS 在哪个分区 |
| **PBR 分区引导记录**（也称 VBR） | **每个分区**的第一个扇区 | 分区引导程序 + 本分区文件系统参数（BPB） | 在本分区根目录找启动管理器并执行 |
| **启动管理器** | 活动分区根目录（如 `bootmgr` / GRUB） | 完整 OS 初始化程序 | 加载内核，真正开机 |

【必背】链式流程：

```text
加电 → CPU 从 ROM 执行 BIOS（先 POST 自检，再按启动顺序选设备）
  → 把磁盘第 0 扇区（MBR）读入内存，执行磁盘引导程序
  → 按分区表找到活动分区
  → 读入该分区的 PBR 并执行
  → PBR 从根目录找到启动管理器
  → 启动管理器完成操作系统初始化
```

两层不要混【辨析】：

- **MBR 管整盘，PBR 管单个分区**。每个分区都有自己的 PBR；单系统启动只用活动分区那一份。
- 「磁盘引导程序 / 主引导程序」= MBR 里那 446 字节代码；「分区引导程序」= PBR 里的代码。前者找分区，后者找启动管理器。
- 上面 §3.2 的 **引导块** 是 Unix 卷布局用语，对应分区开头的 PBR 这一层；整盘第 0 扇区是 MBR，格式化分区清不掉它。
- 活动分区 ≠ 主分区：主分区是分区表里的类型；活动是分区表项上的可引导标志。一块盘可以有多个主分区，引导时只认标了活动的那一个。

> **简答收束**：BIOS 把 MBR 读进内存；MBR 里的磁盘引导程序按分区表找到活动分区；活动分区的 PBR 再从根目录拉起启动管理器。UEFI 走 ESP 分区里的 `.efi` 文件，考研简答仍按 BIOS+MBR 这条链写。

## 4. 外存分配方式：文件怎么上盘

### 4.1 连续分配

- 逻辑连续 → 物理连续：FCB 记**起始块号 + 长度**。
- 优点：支持**直接（随机）存取**（起始块 + i 偏移一次定位）、顺序访问速度最快（几乎不寻道）。
- 缺点：**外零头**（同动态分区，需要紧凑）、**文件难动态增长**（后面被占）、必须预知大小。
- **内部碎片（块内碎片）**：文件长度不是盘块整数倍时，最后一块装不满，平均浪费半块。它与块大小反向相关：块越大内碎片越多；块越小则块数多，FAT / 位示图与 I/O 次数随之上升——块大小就是这两头的权衡。
- **碎片的两类处理**：**外部碎片**可由离散分配（链接、索引）直接消除，或靠**碎片整理**（移动数据重排空闲区；耗时，且 SSD 不宜做物理紧凑）；**内部碎片**整理无效，只能调小块大小，或让块尾零头在相邻文件间共用。
- 定位：同 05 篇动态分区是"内存的连续方案"，这里是"外存的连续方案"，结论可以整体平移。

### 4.2 链接分配：隐式链接与显式链接 FAT

| | 隐式链接 | 显式链接（FAT） |
|---|---|---|
| 指针放哪 | 每个盘块**末尾**存下一块号 | 指针集中抽出来放 **FAT 表**（文件卷一张） |
| 访问第 i 块 | 从头顺链读盘，**i 次磁盘 I/O** | FAT 开机调入**内存常驻**，内存里顺链查 i 次（无访盘），数据块**只读盘 1 次** |
| 随机存取 | 不支持 | 支持 |
| 代价 | 每块尾部损耗 | FAT 本身占外存 + 常驻内存（与盘块总数成正比） |

- **为什么隐式链接要 i 次访盘**：下一块的块号存在当前块的**末尾**，想拿到它必须先**读出当前块**；访问第 i 块只能从链头逐块读入（读块 1 得块 2 的号、读块 2 得块 3 的号……），共 i 次，这正是它不能随机访问的根因。
- FAT 是 MS-DOS/早期 Windows 的方案；"链接分配不支持随机访问"这句口径**只对隐式链接成立**：FAT 恰恰是为了随机访问才把指针集中到内存。
- 两者共同点：离散存放、**无外零头**、文件易扩展。

#### FAT 表的结构与文件的定位

FAT 的表项序号即盘块号，表项内容为该盘块的后继盘块号。目录项（FCB）中只记文件的**起始盘块号**，读取文件时由起始块号出发，沿 FAT 逐项取得后继，直至链尾标志。表项取值的约定：

| 表项值 | 含义 |
|---|---|
| 0 | 该盘块空闲，可参与分配 |
| 正整数（块号） | 该盘块的后继盘块号 |
| EOF（约定值，如 −1） | 该盘块是文件的最后一个盘块（链尾） |
| 坏块标记 | 该盘块损坏，不参与分配 |

随机存取第 i 块的过程：由目录项取得起始盘块号 → 在内存中沿 FAT 顺链查找至第 i 块 → 读该数据块。链查找在内存中进行，次数与块序号成正比（O(i)），省去的是隐式链接中逐块读盘的 i−1 次磁盘 I/O；与索引分配的 O(1) 直接定位相比，FAT 仍属链式结构，长文件靠后块的定位较慢。

表项位数决定文件卷可寻址盘块数的上限：FAT12 表项 12 位，最多表示 4096 个盘块号（配 1KB 盘块时卷容量上限 4MB）；FAT16、FAT32 依次为 16 位、32 位，名称即由此而来。

#### FAT 自身占盘块数的计算（必背题型）

FAT 覆盖整个文件卷，表项数等于盘块总数；FAT 自身也存放在盘块中，同样计入表项的覆盖范围。计算步骤：

1. 盘块总数 = 磁盘容量 ÷ 盘块大小；
2. 表项长度按题面给定（常见 2B 或 4B；FAT12/16/32 即表项 12/16/32 位）；
3. FAT 总容量 = 盘块总数 × 表项长度；
4. FAT 占用盘块数 = FAT 总容量 ÷ 盘块大小，向上取整；
5. 校验：表项位数应足以表示盘块总数；若题目给出的是**不含 FAT 的数据区容量**，盘块总数须满足"数据块数 + FAT 占块数"，需解一次方程后回代。

例：磁盘容量 4MB，盘块 1KB，每个盘块号占 2B。

- 盘块总数 = 4MB ÷ 1KB = 4096 块；
- FAT 容量 = 4096 × 2B = 8KB，占 8 个盘块；
- 可供文件数据使用的盘块 = 4096 − 8 = 4088 块；
- 校验：16 位盘块号最多表示 65536 个块号，覆盖 4096 块绰绰有余，表项数与全盘块数一致，无需迭代。

### 4.3 索引分配

- 每文件一张**索引块**（盘块号数组），FCB 记索引块地址。支持直接存取、无外零头、易扩展。
- 访问第 i 块：先读索引块、再读数据块，**2 次访盘**（索引块常驻内存后 1 次）。
- 大文件问题：一张索引块装不下 → 链接式索引、多重索引、**混合索引**（主流）。

### 4.4 混合索引（UNIX）

i-node 中放 **10 个直接地址 + 1 一次间接 + 1 二次间接 + 1 三次间接**（一次间接块 = 纯地址块）：

```text
直接地址：i-node 里直接记 10 个数据块号 → 小文件一次定位
一次间接：地址块记 1024 个数据块号
二次间接：地址块记 1024 个"一次间接地址块号"
三次间接：再套一层
```

计算例【必背题型】（块 4KB、地址项 4B → 每地址块装 4KB/4B = 1024 = 2¹⁰ 项）：

| 层 | 块数 | 容量 |
|---|---|---|
| 10 直接 | 10 | 40KB |
| 一次间接 | 1024 | +4MB |
| 二次间接 | 1024² | +4GB |
| 三次间接 | 1024³ | +4TB |

最大文件 = (10 + 1024 + 1024² + 1024³) × 4KB。

访问次数（i-node 已在内存）：直接块 **1** 次、一次间接 **2** 次（读地址块 + 数据块）、二次 **3** 次、三次 **4** 次。

> **解题四步**：① 地址块可装项数 = 块大小 / 地址长度（4KB/4B = 1024）；② 按 10 直接 + 1024 + 1024² + 1024³ 分层算块数；③ 最大文件 = 总块数 × 块大小；④ 问访问次数：层数 + 1 次访盘（直接块 1 次，k 级间接 k+1 次）。链路：`字节数 → 总块数 → 逐层扣减 → 定位层级 → 数访盘次数`。

**小综合例题**：块 4KB、地址项 4B，i-node 用 10 直接 + 1 一次间接 + 1 二次间接。文件 5MB，问用到哪几层索引？读最后一个字节几次访盘？

- 总块数 = 5MB ÷ 4KB = **1280 块**；
- 前 10 块走直接，余 1270 块；一次间接只装 1024 块，余 1270 − 1024 = **246 块**，故还需**二次间接**；
- 最后一个字节落在第 1280 块，走二次间接：读二次间接地址块 → 读一次间接地址块 → 读数据块，共 **3 次**访盘（i-node 已在内存）。

> 注记：直接地址个数各教材/真题不统一（常见 10、12，另有 7、9 等变体），做题**以题干给出的地址项分配为准**；本篇例按经典的 10 项。

### 4.5 四方式对比总表

| 维度 | 连续 | 隐式链接 | 显式 FAT | 索引 |
|---|---|---|---|---|
| 随机存取 | ✓（最好） | ✗ | ✓ | ✓ |
| 外零头 | **有** | 无 | 无 | 无 |
| 文件增长 | 难 | 易 | 易 | 易 |
| 访问第 i 块的访盘次数 | 1 | i | 1（查 FAT 在内存） | 2（索引在内存则 1） |
| 额外开销 | 无 | 块尾指针 | FAT 表 | 每文件索引块 |

### 4.6 逻辑结构 → 物理分配的对应（横向对照）

上面四方式比较的是"物理侧内部谁好谁坏"，这一节反过来问：**给定一种逻辑结构，通常配哪种分配方式**。先把话说清：逻辑结构管"记录怎么排、凭什么定位记录"，物理分配管"这些块落到哪些盘块"，**两者是独立的两条轴，可以自由组合**，下表是常见搭配，不是强制绑定。

| 逻辑结构 | 首选分配 | 次选分配 | 理由 | 提醒 |
|---|---|---|---|---|
| 无结构文件（流式） | 需增长且要随机 → **索引分配**；定长只读 → **连续分配** | 显式链接 FAT | 流式文件既按偏移随机读、又常追加，索引兼顾随机与增长；定长只读用连续最快 | **隐式链接不支持随机定位**，不能当次选 |
| 堆文件 | **链接分配**（隐式、显式均可） | 索引分配 | 记录无序、只追加、几乎全表扫描，追加一块接一块最省 | 查找慢由逻辑结构决定，换分配方式也救不回来 |
| 顺序文件（顺序结构） | **连续分配** | 显式链接 FAT；会持续插入的改用索引 | 逻辑相邻即物理相邻 → 顺序读最快，定长还能按记录号算地址 | 难增长、有外零头；增长型顺序文件其实该走索引顺序 |
| 索引文件 | **索引分配** | 连续分配（记录位置固定时） | 记录离散存放、靠索引表定位，索引分配天然支持随机存取 | **逻辑结构的"索引表" ≠ 物理的"索引块"**，别混答 |
| 索引顺序文件 | **主文件连续 + 索引块用索引分配** | 主文件连续 + 溢出区用链接 | 兼顾整批顺序读（主文件连续）与按键定位、插入（索引 + 溢出区） | 溢出链过长要**重组**，否则查一次得扫整条链 |
| 直接文件（散列） | **连续分配**（散列结果即块号，可直接算） | 索引分配 / 显式 FAT | 散列函数算出来的就是地址，要求"可计算寻址" | 隐式链接不行；冲突另设溢出区 |

- 压成一句判据：**文件会不会长、要不要随机定位、能不能忍外零头**——这三者决定分配方式，而它们正是逻辑结构给定的。
- 现实系统很少只用一种：连续段（extents）、主文件连续 + 索引块、FAT 都是混合方案；答题先写"两条轴独立"，再给搭配，别写成"逻辑结构决定物理结构"。

## 5. 文件存储空间的管理：空闲块怎么记账

> 本节按**王道/408 的四分法**组织（空闲表、空闲链表、位示图、成组链接），Stallings 与之只是分类粒度与译名不同；有重合的方法在旁边附上它的叫法，答题一律用王道口径。

### 5.1 空闲表与空闲链表

- **空闲表**：{起始块号, 空闲块数}，适用**连续分配**；分配算法同 05 篇动态分区（首次/最佳适应），回收考虑**合并相邻空闲区**。
- **空闲链表**：空闲盘块链 / 空闲盘区链，链上逐块（逐区）分配回收，简单但效率低。
  - **空闲盘区链**（以连续空闲区为单位串起来），别名 **链接空闲区**（Stallings）：每区带宽和指向下一区的指针，与"空闲表 + 链起来"是同一思路。
  - **空闲盘块链**（以单块为单位），别名 **空闲块列表**（Stallings）：把空闲块号集中记在磁盘保留区；本章的**成组链接法**是它的改进实现。

### 5.2 位示图法（Stallings 称**位表** Bit Table）

每一位对应一个盘块：0 = 空闲、1 = 已占（或相反，看题目口径）。

```text
每行（每字）n 位，从 0 编号：
  盘块号 b → 字号 i = b div n，位号 j = b mod n
  反向：b = n × i + j
从 1 编号时整体平移 1：i = (b−1) div n + 1，j = (b−1) mod n + 1
```

- 位示图大小：**块数 ÷ 8 = 字节数**。例：磁盘 320MB、盘块 512B → 640K 块 → 位示图 640K bit = **80KB**。
- 优点：容易找相邻空闲块（连续多个 0）、占用空间小。
- 口径警告【辨析】：先看题目"从 0 还是从 1 开始编号"，两种公式的差 1 是设错重灾区。

### 5.3 成组链接法（UNIX，离散分配的记账法）

记 `S.free` 为长度 100 的**空闲盘块号栈数组**（元素 `S.free(0)` ~ `S.free(99)`，其中 `S.free(0)` 是栈底），`n` 为栈中当前空闲盘块号个数（兼作栈顶指针）；每 100 个空闲块为一组（**末组可不足 100，以 `S.free(0)=0` 作链尾结束标志**）：

```text
分配一块：
  n > 1 → 弹栈一块
  n = 1 → 这块是"索引块"：先把它记的下一组 100 个块号读入栈，再分配它
回收一块：
  n < 100 → 直接压栈
  n = 100（栈满）→ 先把栈中 100 个块号写进新回收的块，再把它压栈（栈里只剩它）
```

> **手推要盯两个临界**：分配时 **n=1**（先读索引块再分配它）、回收时 **n=100 栈满**（先写出栈内容再压新块），写清每步栈内块号和 n。

迷你推演（栈容量 5，初始 {5,4,3,2,1}，n=5）：

- 分配 2 块：弹 1、弹 2 → {5,4,3}，n=3；
- 连续分配到临界：弹 3、弹 4 → {5}，n=1；再分配 → 先把 5 号块内容（设为 {10,9,8,7,6}）读入栈，再分配 5 号 → 栈变 {10,9,8,7,6}；
- 回收撞栈满：栈 {7,6,5,4,3} n=5 时回收 2 号 → 把栈内容写入 2 号块，栈变 {2}，n=1。

- 呼应 05 篇：请求分页从外存调页，读的就是文件区/对换区里这些被记账的盘块，UNIX 中**对换区连续分配求快，文件区离散分配求空间利用**，两种记账并行。

## 6. 文件目录：从名字到盘块

### 6.1 目录结构三级跳

| 结构 | 机制 | 缺陷 |
|---|---|---|
| 单级目录 | 全系统一张表 | 查找慢、**重名冲突**、不能分类 |
| 两级目录 | 主文件目录 MFD + 各用户 UFD | 解决重名与隔离；仍不便共享和灵活组织 |
| **树形目录** | 目录 → 子目录 → 文件；绝对路径 / 相对路径 | 路径逐级检索 I/O 多（见 §6.3） |

- 树形解决重名（不同目录下可同名）、便于分类管理；代价是深路径检索。
- **当前目录**：每操作都从根开始 → 引入"当前目录"，相对路径省掉前缀逐级查找，直接省磁盘 I/O。
- "树形解决了共享问题"：错，树形解决的是**重名与分类**；共享靠基于索引结点或符号链接的方式（无环图）。

### 6.2 目录实现：线性表与哈希表

| 实现 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| **线性表** | 目录项（文件名 + 指针/i-node 号）顺序存放 | 简单；增删目录项方便 | 按名查找要**顺序扫描**，大目录慢；建文件还需先查重名 |
| **哈希表** | 文件名 → 哈希值 → 指向目录项 | 查找**接近 O(1)**，插入删除简单 | 有**哈希冲突**；表长固定、扩容/重建麻烦 |

- 内存里还会缓存**目录项（dentry）**：把最近访问过的目录项留在内存，减少目录检索的磁盘 I/O。
- 一句话：线性表"简单但慢"，哈希表"快但要处理冲突"；ext 系列文件系统用哈希实现目录。

### 6.3 目录检索 I/O 计算

- 检索路径的方法模板：路径每经过一级目录 = 查该级目录文件（可能多块）+ 读该级 FCB/i-node；**目录项越瘦，读的块越少**。
- 提速算例：640 个文件的目录，FCB 64B、盘块 1KB → 目录 40 块，平均检索 20 块；改用 16B 目录项 → 10 块，平均 5 块 + 读 1 块磁盘 i-node = **6 块**（20 → 6）。

算例拆解：

- FCB 版：每块可放目录项 = 1KB ÷ 64B = **16**；目录占块 = 640 ÷ 16 = **40 块**；顺序查找平均读 40 ÷ 2 = **20 块**；
- 瘦身为 16B 后：每块可放 1KB ÷ 16B = **64** 项；目录占块 = 640 ÷ 64 = **10 块**；平均读 10 ÷ 2 = **5 块**；再读 1 块磁盘 i-node → **6 块**；
- 换数据照套：`每块项数 = 盘块 ÷ 目录项`、`占块 = 文件数 ÷ 每块项数`、`平均 = 占块 ÷ 2`（索引结点版再 +1）。

> **比较题口径**：先算每块装多少目录项，再算平均读几块；当前目录只省掉路径前缀部分。

## 7. 文件共享与保护

### 7.1 基于索引结点方式（硬链接）与基于符号链接方式（软链接）

一句话定位：共享有两种做法——**让多个目录项指向同一个索引结点**（基于索引结点方式，即硬链接），或者**新建一个专门存路径名的文件去指向目标**（基于符号链接方式，即软链接）。

| | 基于索引结点方式（硬链接） | 基于符号链接方式（软链接） |
|---|---|---|
| 实现 | 多个目录项指向**同一 i-node**，i-node 里记**链接计数 links**；不新建 i-node、不复制数据块 | 新建一个 **LINK 类型文件**（自己有 i-node 和数据块），内容是**目标的路径名** |
| 共享的是什么 | 共享同一 i-node → 权限、属主、大小、时间戳、数据块都是**同一份** | 只共享"指向关系"：链接文件有自己的 i-node 与权限，访问时才按路径去找目标 |
| 名字的地位 | 多个名字**地位平等**，没有"原件/副本"之分，删任一个都只是 links 减 1 | 有"原件/快捷方式"之分，删原件后链接文件还在，但**悬空** |
| 删除共享文件 | links 减 1，**减到 0 才真删** | 删原件只删原件，访问链接时报错（悬空） |
| 跨文件系统 | **不能**：目录项存的是 i-node 号，而 i-node 号只在**本卷内唯一** | **能**：存的是路径名，可跨文件系统、跨挂载点 |
| 链接目录 | **不允许**（会让目录树成环） | **允许**（但要处理解析与循环） |
| 访问代价 | 与普通文件**相同**：按名检索到目录项即可拿到 i-node | 先读链接文件拿到路径，再**重新逐级检索目录**，多一次（或多次）访盘 |

两种走法差在哪一步：

```text
硬链接：路径 → 目录项 → i-node → 数据块            （与普通文件完全同一路径）
软链接：路径 → 链接文件（i-node + 数据块里存路径） → 重新解析该路径 → 目标目录项 → i-node → 数据块
```

**链接计数 links 的生命周期**（只在硬链接里存在）

- 创建硬链接：在目标目录里加一个目录项，i-node 的 links **+1**，数据块一份不动。
- 删除或重命名一个名字：目录项消失，links **−1**；links 减到 0，i-node 与数据块才可回收。
- 目录也有 links：每个子目录的 `..` 都指向父目录，所以父目录的 links = 2（`.` 与 `..` 两个名字）+ 子目录个数——这也是硬链接不宜指向目录的现实原因之一。

**links = 0 不等于立刻释放**【易错】

- 能否回收要两个条件同时满足：**链接计数 links = 0** 且**没有进程打开**（打开计数 / 打开文件表引用计数为 0）。
- 进程仍持有 fd 时删除文件（unlink）：目录项没了、links 归 0，但盘块**不释放**，进程可以继续读写，close 之后才真正回收。这是"删除已打开文件"的标准行为。
- 对应 §2.3 的三个计数：links 在**外存 i-node** 上、打开计数在**内存 i-node** 上、引用计数在**系统打开文件表**里，位置不同、回收时机也不同。

**符号链接的解析细节**

- 链接文件里存的是路径名，可以写**绝对路径**（跨卷、挂载点都行），也可以写**相对路径**（相对链接文件所在目录解析，整目录搬迁不易断）。
- 访问时先读出这个路径，再**从目录树重新解析**，所以每一步都要查目录，代价高于硬链接。
- **悬空**（dangling）：目标被删或改名后，链接文件自身还在，访问时解析失败报错（如 ENOENT）。
- **循环**：符号链接可以链目录、可以互相指向形成环，内核在路径解析时限制跳转层数（如超限报 ELOOP），不会真的死循环。

**场景与取舍**

- 同一文件要多个入口、且都在同一卷内、不想多占空间 → 硬链接（快、一致，但受卷和目录限制）。
- 要跨卷共享、链接目录、或给"可能还不存在/会被替换"的目标留一个入口（如配置切换、版本切换）→ 软链接（灵活、但有悬空与额外 I/O 的代价）。
- 题目出现"链接计数 / ln"想硬链接，出现"路径名 / ln -s"想软链接。

**简答收束（三句话）**：硬链接是在目录层加一个指向同一索引结点的名字，靠 links 计数决定何时回收，不复制数据、访问代价与普通文件相同，但只能在同一文件系统内且不能链目录；软链接是新建一个存路径名的链接文件，访问时重走路径解析，可跨卷、可链目录，代价是多一次目录检索，并要处理悬空与循环；两者都实现"多个名字共享一份数据"，区别在共享发生在**目录项层（同一 i-node）**还是**路径层（另一个文件）**。

**复制文件与基于索引结点的硬链接的辨析**【易混】

| | 复制 | 硬链接 |
|---|---|---|
| 盘块与 i-node | 新建**独立**的 i-node 与数据块，内容各一份 | 共享**同一个** i-node 与数据块，内容只有一份 |
| 修改一致性 | 改一份，另一份**不变** | 改任一份，**两份同时变**（本就是同一份） |
| 删除一份 | 另一份**完整保留** | 仅 links 减 1，减到 0 才释放；links > 0 前数据仍在 |
| 占用空间 | 增加一份数据块 | 只增加一个目录项，几乎不占空间 |
| 目录项与 i-node 的关系 | 目录项 1 — 1 | 目录项 n — 1（多个名字对应一个 i-node） |

- 判断口诀：改一个另一个也变、删一个另一个还在 → 硬链接；改删互不影响 → 复制。
- "无环图目录结构"词条见 §10 低频清单。

### 7.2 保护

- 常用手段：UNIX **9 位权限 rwx**（属主/组/其他三类 × 读/写/执行）、口令、加密；细粒度模型（访问矩阵、ACL、能力表）与安全科 03 篇（访问控制模型，尚未成文）分工，OS 篇记机制即可。
- **可控制的访问类型**（6 种）：**读**（取文件内容）、**写**（修改内容）、执行（装入内存运行）、添加（只许在文件末尾追加，是写的受限版）、删除（删文件、释放空间）、列表清单（列文件名与属性）。高层操作可由低层组合：复制 = 读 + 新建写，故有读权限者天然能复制、打印。
- 【辨析】rwx 三者**没有高低等级之分**，是互相独立的权限位；八进制 r=4、w=2、x=1 只是**位权**不是等级。论危害**写权限最大**（可篡改甚至清空文件）。对目录而言 rwx 含义另算：目录 w = 可增删/重命名目录项，反而最危险；x = 能否进入目录访问其中文件。

## 8. 收尾：可靠性与一致性（低频）

- **可靠性**：磁盘容错 SFT-I（镜像）、SFT-II（双工）、后备系统，词条进 §10 低频清单，RAID 完整机制归 07 篇。
- **一致性**：崩溃后 FAT/位示图可能与实际不符 → 一致性检查（计数比对，如 dup 块）；事务与检查点保证"一组操作要么都做要么都不做"。

## 9. 最容易写错的二十五处（速查清单）

1. "目录不是文件"：错，目录文件就是 FCB（或瘦目录项）的集合，和普通文件一样占盘块、走打开机制。
2. 用了索引结点后"目录项不含文件信息"：瘦身前 = 完整 FCB；瘦身后 = 文件名 + i-node 编号；FCB 没消失，只是搬进 i-node。
3. 逻辑结构与物理结构混答：逻辑是用户视角的记录组织，物理是外存盘块分配，先分边。
4. 各层职责混淆：目录找 FCB、存取控制判权限、逻辑层做"记录→逻辑块"、物理层做"逻辑块→物理块"。
5. "链接分配都不支持随机访问"：错，只对隐式链接成立；FAT 支持。
6. FAT 指针"查一次读一次盘"：错，FAT 常驻内存，数据块只需 1 次访盘。
7. "索引分配访问任何块都要 2 次访盘"：索引块不常驻时 2 次、常驻后 1 次；混合索引按层加。
8. 混合索引算最大文件漏掉直接块：最大文件 =（直接块数 + 各间接层块数之和）× 块大小。
9. 1024² 与 1024³ 搞反：一次间接 ×1024、二次 ×1024²、三次 ×1024³，层数即方次。
10. 位示图 0/1 起始口径不分：b = n×i + j（从 0）与 b = n(i−1)+j（从 1）差 1，先看题。
11. 成组链接回收"栈满直接压栈"：错，栈满先把栈内容写进新回收块，栈里只留新块。
12. 成组链接分配"栈空才特殊"：错，特殊在 n=1，最后一块是索引块，先读下一组再分配。
13. "树形目录解决了共享问题"：错，解决重名与分类；共享靠基于索引结点或符号链接的方式。
14. "r=4、w=2、x=1 说明读等级最高"：错，是位权不是等级；论危害写权限最大。
15. "哈希目录一定比线性表好"：错，哈希有冲突、扩容重建代价；线性表胜在简单。
16. "硬链接可以跨文件系统/链接目录"：错，都不能；用软链接。
17. 删除有硬链接的文件"直接释放盘块"：错，links > 0 只减计数，减到 0 才释放。
18. "打开文件后每次读写仍要查目录"：错，open 付一次，之后用 fd。
19. "关闭文件就释放所有内存结构"：错，close 撤进程表项；系统表等引用计数为 0 才撤销。
20. 索引结点提速原理答"查找更快"：错，原理是目录项变瘦 → 占块少 → 磁盘 I/O 次数减少。
21. "引导块 = MBR"：错。§3.2 引导块是分区/卷开头，对应 PBR；MBR 是整盘第 0 扇区，不属于任何分区。
22. "磁盘引导程序存在活动分区里"：错。磁盘引导程序在 MBR 前 446 字节；活动分区里是 PBR 和启动管理器。
23. "活动分区就是主分区"：错。主分区是分区表类型；活动是可引导标志。引导只认标了活动的那一个。
24. "links 减到 0 就立即释放盘块"：错，还要打开计数为 0；进程仍持有 fd 时可继续读写，close 之后才回收。
25. "删掉原件后符号链接会自动消失"：错，链接文件仍在，只是悬空，访问时路径解析失败报错。
