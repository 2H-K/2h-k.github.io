## 2. 知识框架

```
应用层 ———— 报文 message      （HTTP DNS FTP SMTP POP3 SNMP DHCP）
传输层 ———— 报文段 segment    （TCP UDP：端到端、进程→进程）
网络层 ———— 数据报 datagram   （IP：主机→主机、路由选择）
数据链路层 —— 帧 frame        （以太网：相邻结点、差错控制）
物理层 ———— 比特 bit          （比特流传输、编码调制）
```

- 两条主线：**数据流向**（发送方自上而下封装，接收方自下而上解封装）+ **各层对等实体**按协议通信
- **OSI 七层**（自下而上）：物理 → 数据链路 → 网络 → 运输 → 会话 → 表示 → 应用；五层教学模型 = OSI 去掉会话/表示层；TCP/IP 四层 = 应用 / 运输 / 网际 / 网络接口
- **层对应关系**：OSI 会话+表示+应用 → 合并为 TCP/IP 应用层；数据链路+物理 → 合并为网络接口层；网络↔网际、运输↔运输一一对应。问"表示层干什么"：数据格式变换、加密解密、压缩解压（会话层管会话的建立/管理/终止）

### 2.1 分层地图

| 层 | 地位 / 解决什么 | 核心概念·协议 | 主要考法 | 笔记 |
|---|---|---|---|---|
| 应用 | 人与网络的接口：把底层能力包装成服务 | DNS、DHCP、HTTP(S)、P2P/BitTorrent、SMTP/POP3/IMAP、FTP/TELNET/SNMP | 递归vs迭代、DORA四步、RTT计算、报文分析、P2P分发时间 | → 02-05 |
| 传输 | **进程→进程**：端到端的可靠/高效交付 | TCP、UDP、端口、滑动窗口、拥塞控制 | 序号/窗口计算、握手挥手、cwnd折线分析 | → 06-09 |
| 网络 | **主机→主机**：跨网寻址与路由 | IP、CIDR、ARP、ICMP、RIP、OSPF、BGP | 子网划分、分片计算、路由表更新（RIP/BGP考点在此） | → 10-12 |
| 链路 | **相邻结点**：成帧、差错控制、介质访问 | 以太网、CSMA/CD、CRC、交换机 | 最小帧长、设备辨析、交换机转发/泛洪 | → 13-14 |
| 物理 | 比特流透明传输 | 编码调制、Nyquist、Shannon | 编码计算、信道容量 | → 15 |

### 2.2 层与层之间：谁提供服务，谁使用服务

**相邻层之间是垂直的服务关系；同一层的对等实体之间是水平的协议关系。**

```text
发送端                                      接收端
应用层实体 ──使用传输层服务──▶ 传输层实体  ...  对等传输层实体
    ▲ 提供给应用层的服务                         │ 按 TCP/UDP 协议通信
    │                                            ▼
传输层实体 ──使用网络层服务──▶ 网络层实体  ...  对等网络层实体
    ▲ 提供给传输层的服务                         │ 按 IP 协议通信
    │                                            ▼
网络层实体 ──使用链路层服务──▶ 链路层实体  ...  对等链路层实体
    ▲ 提供给网络层的服务
    │
链路层实体 ──使用物理层服务──▶ 物理层实体
```

更准确地说，每一层同时扮演两个角色：

- **向下使用服务**：本层通过下层提供的接口获得传输、寻址或发送比特等能力；
- **向上提供服务**：本层把自己的功能封装成服务，通过层间接口交给上层；
- **同层按协议通信**：发送端和接收端的同层对等实体遵循同一协议，逻辑上直接通信，但实际数据必须经过下层传送。

例如，浏览器发送 HTTP 请求时：

```text
HTTP 使用 TCP 提供的可靠字节流服务
TCP 使用 IP 提供的尽力而为主机到主机服务
IP 使用链路层提供的逐跳帧传输服务
链路层使用物理层提供的比特传输服务
```

因此不要写成“TCP 为 HTTP 提供协议”：**TCP 是传输层协议，TCP 向 HTTP 提供的是传输服务；HTTP 与对端 HTTP 实体之间才是应用层协议关系。** 同理，IP 向 TCP 提供网络层服务，链路层向 IP 提供逐跳传输服务。

### 分层的好处
（1）**各层之间是独立的**。某一层并不需要知道它的下一层是如何实现的，而仅仅需要知道该层通过层间的接口（即界面）所提供的服务。由于每一层只实现一种相对独立的功能，因而可将一个难以处理的复杂问题分解为若干个较容易处理的更小一些的问题。这样，整个问题的复杂程度就下降了。
（2）**灵活性好**。当任何一层发生变化时（例如由于技术的变化），只要层间接口关系保持不变，则在这层以上或以下各层均不受影响。此外，对某一层提供的服务还可进行修改。当某层提供的服务不再需要时，甚至可以将这层取消。
（3）**结构上可分割开**。各层都可以采用最合适的技术来实现。
（4）**易于实现和维护**。这种结构使得实现和调试一个庞大而又复杂的系统变得易于处理，因为整个的系统已被分解为若干个相对独立的子系统。
（5）**能促进标准化工作**。因为每一层的功能及其所提供的服务都已有了精确的说明。
分层时应注意使每一层的功能非常明确。若层数太少，就会使每一层的协议太复杂。但层数太多又会在描述和综合各层功能的系统工程任务时遇到较多的困难。通常各层所要完成的功能主要有以下一些（可以只包括一种，也可以包括多种）：
① **差错控制** 使相应层次对等方的通信更加可靠。
② **流量控制** 发送端的发送速率必须使接收端来得及接收，不要太快。
③ **分段和重装** 发送端将要发送的数据块划分为更小的单位，在接收端将其还原。
④ **复用和分用** 发送端几个高层会话复用一条低层的连接，在接收端再进行分用。
⑤ **连接建立和释放** 交换数据前先建立一条逻辑连接，数据传送结束后释放连接。
分层当然也有一些缺点，例如，有些功能会在不同的层次中重复出现，因而产生了额外开销。

### 服务关系与协议关系对照

| 关系 | 方向 | 参与者 | 说明 |
|---|---|---|---|
| **服务** | 垂直、上下层 | 下层服务提供者 → 上层服务使用者 | 下层隐藏实现细节，通过接口提供功能 |
| **协议** | 水平、同层 | 本端对等实体 ↔ 对端对等实体 | 规定消息格式、含义、时序和动作 |
| **封装** | 发送端自上而下 | 上层数据交给下层 | 下层通常添加本层首部，形成报文段、数据报、帧 |
| **解封装** | 接收端自下而上 | 下层数据交给上层 | 下层去除本层控制信息，再交付上层 |

> **考试口诀**：下层给上层提供服务，上层使用下层服务；同层对等实体遵守协议。发送端自上而下封装，接收端自下而上解封装。

## 3. 网络性能指标：术语、定义与公式

本节是**全卷性能词汇的唯一定义处**。后面任何一篇出现这些词，都不再重复解释，只回指这里。

### 3.0 先抓两个核心指标

```text
评价网络的性能，主要是两个指标：带宽 和 时延
  │  带宽 bandwidth —— 能力：这条信道"最多能跑多快"（上限）
  │  时延 delay     —— 代价：一个比特"要跑多久"（从发送到收到）
  ▼
由此派生出一组必须分清的量：
  速率 data rate     链路上实际每秒推多少比特          bit/s
  吞吐量 throughput  单位时间真正通过网络的信息量     bit/s
  时延带宽积 BDP     带宽 × 单向传播时延 = 管子里能装多少比特  bit
  窗口下限（≠ BDP）  带宽 × RTT ≈ 2×BDP = 跑满带宽要发多大窗口    bit
  往返时间 RTT       从发出到收到确认的总时间         s
  信道利用率         有数据通过的时间占比            无量纲
```

### 3.1 速率（数据率、比特率）

【必背】**速率**：网络中数据的**传送速率**，也称**数据率（data rate）**或**比特率（bit rate）**，指单位时间内通过某一信道的**比特数**，单位是 **bit/s**，常写作 **b/s** 或 **bps**。

三个必须记住的点：

- **b 是比特（bit），不是字节（Byte）**。`1 Byte = 8 bit`，所以 `1 MB/s = 8 Mb/s`。速率题给的单位是 b/s 时要先换算，别把字节直接除以速率。
- **速率是"实际推得有多快"，不是"能推多快"**。能推多快是带宽（§3.2）。
- 描述的是链路上**单位时间推送的比特数**，与"链路上同时能容纳多少比特"（= 时延带宽积，§3.5）**不是一回事**：前者是流量，后者是存量。

### 3.2 带宽（bandwidth）：两种含义，必须分清

【必背】**带宽（bandwidth）**这个词有**两种含义**，取决于语境：

| 含义 | 语境 | 定义 | 单位 |
|---|---|---|---|
| ① **频带宽度**（频域称谓） | 通信 / 信号领域 | 某个信号所具有的**频带宽度**，即信号**最高频率与最低频率之差** | **Hz**（kHz/MHz/GHz） |
| ② **最高数据率**（时域称谓） | 计算机网络 / 数据通信 | 某信道传送数据的能力，即在**单位时间内网络中的某信道所能通过的"最高数据率"** | **bit/s**（b/s、bps） |

**在本课程的"网络带宽"语境中，默认指第②种。**【必背】网络带宽表示在单位时间内网络中的某信道所能通过的"最高数据率"，单位 bit/s。

判别方法（题干里通常有信号词）：

- 出现"**某信号**具有的频带宽度""信号频谱""频率范围""载波带宽" → 第①种，单位 **Hz**；
- 出现"**信道**传送数据的能力""单位时间通过的最高数据率""链路带宽""提高带宽" → 第②种，单位 **bit/s**。

三条派生结论：

- 第②种是**上限值**：实际跑多快看速率/吞吐量，永远 `实际值 ≤ 带宽`。
- "提高网络带宽"是**扩容**（换更高规格的介质/接口/编码），"提高频带宽度"是**换信号本身**——两件事，别混。
- 单位陷阱：带宽题一律用 **b/s**；`MB/s` 与 `Mb/s` 差 8 倍。

### 3.3 吞吐量（throughput）

【必背】**吞吐量（throughput）**是**单位时间内通过网络的比特数**，即在单位时间内网络实际通过的信息量，单位 **bit/s**。

【辨析】带宽、速率、吞吐量三者常被混为一题，必须按下面这张表对号：

| 指标 | 含义 | 单位 | 性质 | 由什么决定 |
|---|---|---|---|---|
| **带宽** | 信道所能通过的**最高**数据率 | bit/s | **能力上限** | 介质、编码、接口规格 |
| **速率** | 链路上**实际**传送的比特率 | bit/s | 瞬时/实际值 | 信道能力 + 当前拥塞 + 协议开销 |
| **吞吐量** | 单位时间内**通过整个网络**的信息量 | bit/s | 端到端实测 | **沿途瓶颈链路** |

大小关系：**带宽 ≥ 速率；吞吐量 ≤ 速率**。端到端路径上的**最慢一跳（瓶颈链路）决定吞吐量**。

吞吐量低于速率的常见原因（简答可写）：

- 中间结点**排队时延**上升 → 转发速率下降（§3.4）；
- 协议开销：首部、**确认帧**、**重传**都占用链路带宽；
- 接收端处理不过来时发送端须降速（协议一致要求）。

### 3.4 时延（delay）：四种时延

【必背】**时延（delay）**是数据从发送端到接收端所经历的时间。它由四部分组成：

```text
单跳路径上，时延怎么产生的：

发送端                    链路                 结点（路由器）        接收端
  │  ①发送时延  │  ②传播时延  │  ④排队时延 │  ③处理时延  │
  ├──把比特"推"入信道──▶ 沿介质跑 ──▶ 在队列里等 ──▶ 检查首部/定转发 ──▶
```

| 时延类型 | 定义 | 公式 | 由什么决定 | 与距离 |
|---|---|---|---|---|
| **① 发送时延**<br>transmission delay | 从发送端**发送数据**到**第一个比特离开发送端**所需的时间 | `分组长度 / 发送速率` | 数据**长度**、链路**发送速率** | **无关** |
| **② 传播时延**<br>propagation delay | 数据**第一个比特**从发送端出发到**最后一个比特**到达接收端所需的时间 | `信道长度 / 电磁波传播速率` | **距离**、介质的**传播速率** | **正比** |
| **③ 处理时延**<br>processing delay | 数据进入结点（路由器）后，**检查首部、差错检测、决定转发到哪个接口**所需的时间 | 无固定公式 | 结点处理速度、协议复杂度 | 一般**很小**，题中常忽略 |
| **④ 排队时延**<br>queuing delay | 数据在结点的**输入/输出队列中等待转发**所需的时间 | 无固定公式 | **队列长度**、转发速率（即拥塞程度） | 变差**最大、最难精确计算** |

**必背公式**：`发送时延 = 数据（分组）长度 / 发送速率`，`传播时延 = 信道长度 / 信道传播速率`。电磁波传播速率真空中约 `3×10⁸ m/s`，介质中约 `2×10⁸ ~ 3×10⁸ m/s`，**题目未特别说明时按 2×10⁸ m/s 取值**。

四条必须分清的判据：

- **发送时延只看"多长的包、多快的链路"，与距离无关**——加带宽、减包长都能压小它。
- **传播时延只看"多远的路、多快的波"，与包长和带宽都无关**——只能靠缩短距离或换传播更快的介质来压小它。
- **排队时延是唯一无法提前算出、且波动最大的一项**：链路不拥塞时接近 0，拥塞时可能非常大，队列满了分组还会被**丢弃**（这正是 09 篇拥塞控制的起点）。
- 处理时延最小但存在：路由器每跳都要检查一次首部，端到端时延是**所有跳的累加**。

【必背】**端到端总时延 = 各跳（发送 + 传播 + 处理 + 排队）时延之和。** 因为每跳都贡献一次排队与处理，所以"中间结点多"会让总时延显著变大。

> **配套辨析**：卫星链路省掉的是中间结点的**存储转发（排队 + 处理）时延**，但**传播时延剧增**——见 15 篇 §3。

### 3.5 时延带宽积（带宽时延积，BDP）

【必背】**时延带宽积**（又称**带宽时延积**、BDP，Bandwidth-Delay Product）= `带宽 × 传播时延`，它的物理意义是"**链路上正在传播的比特数**"，即**以比特为单位的链路长度**。

```text
BDP = 带宽 (bit/s) × 传播时延 (s) = bit
      ↑ 这里的"传播时延"一律指【单向】传播时延

物理图景：发送方连续不断地推比特
  t=0        第一个比特出发
  t=t_p      最后一个比特到达对端
  此时链路上从"第一个比特"到"最后一个比特"之间挤满了比特，
  数量正好 = 速率 × 单向传播时延 = BDP
```

四条必记结论：

1. **它的单位是 bit，不是 s**——它是"量"，不是"时间"。**不要与"总时延"混淆**。
2. **公式只有一个，没有第二种写法**：考纲与教材口径就是 `带宽 × 单向传播时延`。英文资料里常见的 `带宽 × RTT` 是**另一个量**（见下面 §3.5.1），**不是本公式的另一种记法**。
3. 链路越长、带宽越高，这个值越大；**卫星链路上是个巨大数字**（100 Mb/s × 单向 250 ms ≈ 3 MB，见 09 篇）。
4. **物理含义要说准**：`BDP` 是"**单向**管道里此刻正在飞的比特数"，不是窗口大小、不是缓冲区大小、不是总数据量。

### 3.5.1 什么时候该 ×2：识别表

`带宽 × RTT` 这个量确实存在，但它是**另一个问题**的答案——**"要把这条管道灌满，发送窗口至少要能装下多少数据"**。因为一个发送窗口要覆盖**一去一回**，所以：

```text
窗口下限 = 带宽 × RTT ≈ 2 ×（带宽 × 单向传播时延） = 2 × 时延带宽积

      发送方
        ├── 窗口里的数据 ────▶  ① 单向：带宽 × 单向传播时延  = 时延带宽积
        ◀── 确认回来 ────────┘  ② 往返：再加同样多            = 窗口下限
```

**做题判据：先看题目问什么，再看题目给了什么。**

| 题干问的是 | 该乘哪个 | 公式 |
|---|---|---|
| "**时延带宽积**是多少""链路能容纳多少比特""管道体积""以比特为单位的链路长度" | **单向**传播时延 | `带宽 × 单向传播时延` |
| "**发送窗口/缓冲区至少要多大**才能跑满带宽""要连续发多久才能传完 M 比特" | **RTT** | `带宽 × RTT` |
| "**利用率**是多少"（窗口固定） | 先求窗口下限，再用 `窗口 / 窗口下限` | 09 篇 §5③ |

| 题干给的是 | 问时延带宽积 | 问窗口下限 |
|---|---|---|
| **单向传播时延 / 单程 / 距离 ÷ 传播速率** | **直接乘** | **×2** 后再乘 |
| **RTT / 往返时间 / 双向时延** | **÷2** 后再乘 | **直接乘** |
| **距离 + 传播速率**（要自己先算） | 算出的就是单向值，直接乘 | 算出的 ×2 |

**一句话记忆**：**题目里只要出现"窗口""缓冲区""跑满""利用率"，基本就要 ×2；出现"时延带宽积""链路长度""容纳多少比特"，就是单向不乘 2。**

⚠️ 最常见的两个坑：

- 题目给了 **RTT** 却问**时延带宽积** → 忘记 ÷2，结果算大一倍；
- 题目给了**单向传播时延**却问**发送窗口** → 忘记 ×2，结果算小一半。

> 英文技术文档（RFC 6349、Wikipedia）把 `带宽 × RTT` 也叫 BDP，是因为它们关心的就是**窗口/缓冲区**该设多大。本博客统一按教材口径：**提到"时延带宽积"一律乘单向传播时延**；09、15 篇出现的 `带宽 × RTT` 一律明确写成"**窗口下限**"，不叫 BDP。

#### 自编判例（两道题对比）

同一组条件：`100 Mb/s`，单向传播时延 `250 ms`（GEO 卫星，RTT = 500 ms）。

```text
题目 A：问"该链路的时延带宽积是多少"
  → 100×10⁶ × 0.25 s = 25×10⁶ bit = 3.125 MB        【单向，不乘 2】

题目 B：问"发送窗口至少要设多大才能跑满带宽"
  → 100×10⁶ × 0.5 s  = 50×10⁶ bit = 6.25 MB          【RTT，乘 2】
  两者关系：6.25 = 2 × 3.125
```

### 3.6 往返时间 RTT

【必背】**往返时间（Round-Trip Time, RTT）**是从发送方**发送数据开始**，到发送方**收到对端发回的确认（响应）为止**所经历的总时间。

```text
RTT ≈ 2 × 单向传播时延
     + 沿途各结点的处理时延与排队时延（往返各一份）
     + 确认帧的发送时延与传播时延
```

| 要点 | 说明 |
|---|---|
| **RTT 是往返，单向传播时延是单程** | 题目只给传播时延时：`RTT ≈ 2 × 单向传播时延` |
| RTT 随拥塞波动 | 它包含**排队时延**，拥塞时排队时延上升 → RTT 变大（这就是 09 篇 RTO 难设定的原因） |
| RTT 是许多算法的时钟 | HTTP 持久连接首字节时间、TCP 重传计时、停等协议信道利用率都以 RTT 为尺度（02、07、09 篇反复用） |

- 典型值：局域网毫秒级；**GEO 卫星单向传播约 240 ms，RTT 约 480 ~ 500 ms**（15 篇）。

### 3.7 信道利用率

【必背】**信道利用率（channel utilization）**是**信道上有数据通过的时间占总时间的比例**：

```text
信道利用率 = 有数据通过的时间 / 总时间
           = 发送时间 / (发送时间 + 空闲时间)
```

对"发一帧 → 等确认 → 再发"这种**一问一答**式的停等协议，利用率还要把等待确认的时间算进空闲：

```text
停等协议：U = T_D / (T_D + RTT + T_A)
  T_D —— 发送一帧（数据帧）的发送时延
  T_A —— 发送确认帧的发送时延
```

【辨析】三条：

- **利用率是无量纲的比例（0~1），吞吐量的单位是 bit/s**——问"多少"前先看问的是比例还是速率。
- **一问一答天然浪费带宽**：即使忽略传播时延，U 也只有 **50%**（一半时间在路上等确认）；再算上传播时延占比会更低。利用率是"对比协议好坏"的工具，**不是"效率越高越好"**——100% 利用率的信道没有余量，一有突发就丢包。
- 想提高利用率只有两条路：**开更大的窗口**（连续发多个分组）或**流水线**，而不是提高带宽——对比见 07 篇（停等/GBN/SR）与 14 篇。

### 3.8 性能指标速查表

| 指标 | 一句话 | 公式 | 单位 | 主要受谁影响 |
|---|---|---|---|---|
| 速率（数据率） | 链路每秒实际推多少比特 | 观察量 | bit/s | 信道能力、拥塞、协议开销 |
| 带宽（网络义） | 信道所能通过的**最高**数据率 | 上限值 | bit/s | 介质、编码、接口 |
| 频带宽度（信号义） | 信号占的频率范围 | `f_max − f_min` | **Hz** | 信号本身 |
| 吞吐量 | 单位时间**通过整个网络**的信息量 | 观察量 | bit/s | **瓶颈链路** |
| 发送时延 | 第一个比特离开发送端 | `分组长度 / 发送速率` | s | **分组长度**、速率 |
| 传播时延 | 比特在链路上跑完全程 | `信道长度 / 传播速率` | s | **距离**、传播速率 |
| 处理时延 | 结点检查首部、差错检测、定转发 | — | s | 结点处理速度 |
| 排队时延 | 在队列里等转发 | — | s | **拥塞程度** |
| 时延带宽积 BDP | 单向管道里在途的比特数 | `带宽 × 单向传播时延` | **bit** | 带宽、距离 |
| （窗口下限） | 跑满带宽所需发送窗口 | `带宽 × RTT` ≈ 2×BDP | **bit** | 同上（→ 09 篇） |
| 往返时间 RTT | 发出到收到确认的总时间 | `≈ 2 × 单向传播时延` | s | 距离、拥塞 |
| 信道利用率 | 有数据的时间占比 | `发送/(发送+空闲)` | 无量纲 | 协议交互方式、窗口大小 |

### 3.9 名词见名即答（考前默写这十条）

刷题时看到这些名词就应当能立刻答出，答不出说明本节没读透：

1. **速率**——数据传送速率，又称数据率/比特率，单位 bit/s、b/s 或 bps。
2. **带宽（网络义）**——单位时间内某信道所能通过的"最高数据率"，单位 bit/s。
3. **带宽（频域义）**——信号所具有的频带宽度，即最高频率与最低频率之差，单位 **Hz**。
4. **吞吐量**——单位时间内通过网络的比特数，由沿途**瓶颈链路**决定。
5. **时延**——数据从发送端到接收端所经历的时间，分**四种**。
6. **发送时延** = 分组长度 / 发送速率，**与距离无关**。
7. **传播时延** = 信道长度 / 传播速率，**与分组长度和带宽无关**。
8. **排队时延**——在结点队列中等待转发的时间，**变化最大、最难精确计算**，拥塞到极限就是丢包。
9. **时延带宽积** = 带宽 × **单向**传播时延 = 管道里正在传播的比特数，**单位是 bit**；`带宽 × RTT` 是"窗口下限"，是另一个量、约为它 2 倍（§3.5.1）。
10. **RTT**——从发送数据开始到**收到确认**为止的总时间，约为**单向传播时延的 2 倍**。

## 4. 简答与名词解释

### 必背

- **协议定义什么**：协议是控制两个**对等实体**进行通信的规则集合，规定通信实体在**发送和/或接收消息或其他事件时应采取的动作**，也规定消息格式、含义以及动作发生的时序。协议本身不是"交换的对象"、不是"信息内容"，也不是主机的物理位置。
- **协议三要素**：①**语法**——数据与控制信息的结构或格式；②**语义**——需要发出何种控制信息、完成何种动作、做出何种响应；③同步（时序）——事件实现顺序的详细说明。
- **协议 vs 服务**：协议是**水平**方向对等实体间的通信规则；服务是**垂直**方向下层经层间接口向上层提供的功能。本层协议的实现要靠下层提供的服务，本层服务的实现又依赖本层协议。
- **服务提供者与使用者**：在相邻层中，**下层是服务提供者，上层是服务使用者**；但每一层又会向自己的上层提供服务、向自己的下层请求服务。例如传输层使用网络层服务，同时向应用层提供进程到进程的传输服务。

### 典型选择题

**在以下选项中，哪个是协议中定义的？**

A. 在发送和/或接收消息或其他事件时采取的行动

B. 通信实体之间交换的对象

C. 交换信息的内容

D. 主机的位置

**答案：A。**协议定义的是通信实体在特定消息或事件发生时的行为规则；B 是消息/数据本身，C 是消息的具体内容，D 属于寻址、拓扑或网络配置等问题，不是协议定义的核心对象。

> **做题口诀**：看到"收到什么之后做什么、何时发送、如何响应"选协议；看到"交换了什么东西"是消息，看到"消息具体写了什么"是内容，看到"主机在哪里"是地址或位置。

### 辨析

- 面向连接 vs 无连接：TCP=先建连接、可靠有序；IP/UDP=尽最大努力交付
- 性能指标：带宽/速率/吞吐量/时延/RTT/利用率 → **全部定义与公式见 §3，本篇唯一出处**
- OSI vs TCP/IP：定位与差异 → 见 §5 对比表

### 了解

- 本节暂无。刷题遇到新词条（如中继器、单工/半双工）记一行词条加出处即可。

## 5. 易混对比表

| 维度 | OSI | TCP/IP | 五层教学模型 |
|---|---|---|---|
| 层数 | 7 | 4 | 5 |
| 网络层 | 连接+无连接 | 无连接 | 无连接 |
| 传输层 | 面向连接 | 面向连接+无连接 | 面向连接+无连接 |
| 定位 | 理论标准 | 事实标准 | 教学折中 |

| 层 | PDU | 设备 | 地址 |
|---|---|---|---|
| 应用 | 报文 | — | — |
| 传输 | 报文段 | — | 端口号 |
| 网络 | IP数据报 | 路由器 | IP地址 |
| 链路 | 帧 | 交换机/网桥 | MAC地址 |
| 物理 | 比特 | 集线器/中继器 | — |

- 电路交换：**建立连接 → 通话 → 释放连接**三阶段；通话期间独占通路、带宽固定，时延小且有序，但线路利用率低 → 传统电话网
- 报文交换：**整个报文**存储转发；无须建连，但大报文在结点缓存排队久、时延大，不适合实时通信
- 分组交换：报文切成**分组**（加首部）存储转发；**统计复用**按需动态分配带宽、链路利用率高、出错重传开销小，但有排队时延、首部开销，需处理失序/分片 → 计算机网络

**路由器的四个组成部分**【必背，常以"路由器由哪几部分组成""不包括哪个"出选择】：
1. **输入端口**——把进入线上的比特接收进来，做**物理层处理**（再生、时钟同步、信号强度/码元判别）与**链路层处理**（剥掉封装、差错检测），再用查表把目的 MAC 换成出接口 MAC；查表后若是单播帧就**经交换结构转发**，若是广播帧则**复制到除入端口外的所有出端口**（因为路由器不转发广播）
2. **交换结构**——把输入端口的分组**移到选定的输出端口**，可用内存、总线或互连网络实现；正是它把"并行处理"变为"串行转发"（多输入同时映射到同一输出时要在输出排队）
3. **路由选择处理器（路由处理机）**——运行**路由选择算法**，与相邻路由器交换路由信息、**维护并更新路由表**，并负责**网络层协议的控制与差错报告**（如 ICMP 不可达、超时）
4. **输出端口**——当分组进入输出端口后被**缓存排队**，按链路需要的速率成帧、做物理层编码与发送；这也是**排队时延主要产生**的部位

> 记法：**进（输入端口）、换（交换结构）、算（路由处理器）、出（输出端口）**——"不进不换不算不出"。选择问"不包括"时，常见干扰项是"差错检测/ARP 解析/路由表更新"，其中差错检测属输入端口、路由表更新属路由处理器；**帧的转发/重写 MAC 属于输入端口**而非交换结构。

## 6. 计算与方法

**时延计算五步法**（公式定义在 §3.4、§3.5、§3.6，这里只讲步骤）：

```text
第 1 步  画时间轴/传输示意图，标出发送端、链路、结点、接收端
第 2 步  算每一段的 发送时延 = 分组长度 / 速率   （长度先 ×8 换算成 bit）
第 3 步  算每一段的 传播时延 = 距离 / 传播速率     （2×10⁸ ~ 3×10⁸ m/s）
第 4 步  沿路径逐段累加；中间结点另加 处理时延 + 排队时延（常给"忽略"）
第 5 步  单程算完，若问 RTT 记得 ×2 + 确认帧开销
```

- **单位换算**：`1000 B` ÷ `1 Mb/s` → 先把 1000 B 变成 8000 bit，`8000/10⁶ = 8 ms`。凡是 B 与 b 混给的，先统一到 bit。
- **典型问法对照**：问"何时到达对端"→ 逐段累加发送 + 传播；问"最后一个比特何时收完"→ 还要把最后一跳的发送时延加进去；问"**时延带宽积**"→ 查 §3.5（**乘单向传播时延**）；问"**窗口要多大才跑满**"→ 查 §3.5.1（**乘 RTT，是 2 倍**）；问"利用率"→ 查 §3.7。
- **停止等待的时间账**（07 篇、14 篇复用）：`总耗时 = T_D + RTT + T_A`，`U = T_D /(T_D + RTT + T_A)`。

**判断某功能属于哪一层**：看 PDU 名称 → 看服务对象（进程/主机/相邻结点）→ 看设备。

## 7. 本节易错点

- **发送时延和距离有关吗？传播时延和带宽有关吗？** 发送时延 = 分组长度/带宽，**与距离无关**；传播时延 = 距离/传播速率，**与带宽无关**——两句话常互换设错
- **"带宽"就是 Hz**：错。频带宽度才用 Hz；**网络带宽的单位是 bit/s**，说的是信道的最高数据率
- **时延带宽积的单位是秒**：错，单位是 **bit**；它是"链路上同时存在的比特数"，不是"总时延"
- **时延带宽积 = 带宽 × RTT**：错。**教材的时延带宽积 = 带宽 × 单向传播时延**，是管道里在途的比特数。`带宽 × RTT` 是**另一个量**——**跑满带宽所需的发送窗口/缓冲区下限**，约为前者的 **2 倍**（判别表见 §3.5.1）
- **题干给了 RTT 就直接乘**：错，要先看问的是时延带宽积（**÷2**）还是窗口下限（**直接乘**）；反之给的是单向传播时延，问窗口要**×2**
- **RTT 是单程还是往返**：是**往返**，从发出数据到**收到确认**为止；`RTT ≈ 2 × 单向传播时延`
- **带宽 = 速率 = 吞吐量**：错。带宽是**上限**，速率是链路实际值，吞吐量是端到端值且受**瓶颈链路**限制（§3.3 表）
- **排队时延可以提前算出来**：错，它是四种时延里**最不确定**的一项，拥塞到队列满就变成**丢包**
- **发送时延算完就是总时延**：错，端到端总时延是**所有跳**（发送+传播+处理+排队）之和，每跳都有排队和处理
- **提高信道利用率总是好的**：错，100% 利用率的信道没有突发余量；利用率是**协议对比工具**，不是越高越好
- **时延和带宽是一回事**：错——带宽是"能跑多快"，时延是"要跑多久"，**提高带宽不能降低传播时延**（卫星链路的道理）
- **设备各归哪一层？** 集线器/中继器=物理层，网桥/交换机=链路层，路由器=网络层——"交换机 TTL−1"之类错都源于归层错
- **协议是水平的还是垂直的？服务呢？** 协议是水平方向对等实体间的规则，服务是垂直方向下层经接口给上层；"传输层为应用层提供协议"这种表述必错
- 计算速率题一律用 **b/s**，注意 MB/s 与 Mb/s 差 8 倍
- **实际运行的因特网用哪个体系？** OSI 是"理论标准"、TCP/IP 是"事实标准"、五层模型是教学折中——问实际采用，答 TCP/IP
