## 2. 文件与打开：从用户视角说起

### 2.1 文件与文件系统

- **文件是什么**：以计算机硬盘为载体、存储在计算机上的**相关信息的集合**（具有文件名的一组信息）。最小分配单位是**盘块（块）**。
- **文件系统**【必背】：OS 中负责管理文件的软件机构——管理文件存储空间（外存块的分配回收）、实施按名存取（目录检索）、完成保护与共享。理解成"外存的记账系统 + 名字到盘块的翻译器"。
- 逻辑结构（用户看到什么）与物理结构（系统怎么存）是两条线【辨析】：用户按**记录/字节**组织文件，系统按**盘块**存放——两者的映射就是本篇的分配方式。

### 2.2 文件的逻辑结构（给用户看）

| 结构 | 组织方式 | 适用 |
|---|---|---|
| 顺序文件 | 记录按序排列，定长记录可按记录号直接计算定位 | 批量存取、顺序设备（磁带）；插入删除难 |
| 索引文件 | 变长记录 + 索引表（键 → 指针，定长有序） | 变长记录的快速随机检索 |
| 索引顺序文件 | 记录**分组**，索引只记每组第一条记录的键 | 大文件的折中：比较次数从 N 降到 **√N** 量级 |

**√N 优化算一遍**：10000 条记录，顺序查找平均 5000 次；分成 100 组（每组 100 条），先查索引（平均 50）再组内（平均 50）→ 平均 **100** 次。
- UNIX 把一切文件视为**无结构的字节流**——逻辑结构简单到极致，复杂性交给上层工具。

### 2.3 FCB 与索引结点：文件的"身份证"

- **FCB（文件控制块）**：存放文件全部描述信息——基本信息（名、物理位置、结构）、存取控制信息（权限）、使用信息（时间、当前状态）。**目录文件 = FCB 的有序集合**（目录也是文件）。
- **索引结点（i-node）**：检索目录时只比**文件名**，FCB 其余字段是陪跑——把它们抽出去放进 i-node，目录项瘦身为"**文件名 + i-node 编号**"。
- **提速原理**：目录项变瘦 → 目录占块少 → 检索的磁盘 I/O 次数减少（640 文件算例见 §6.3）。
- i-node 分两态：**磁盘 i-node**（在外存）与**内存 i-node**（打开后调入，多出引用计数、修改标志、上锁字段）。

### 2.4 打开文件表：按名存取只付一次代价

```text
open(path) → 按名逐级检索目录 → 找到 FCB / 索引结点
  → 复制到内存打开文件表（系统表 + 进程表各一表项）
  → 返回文件描述符 fd
  → 之后 read/write/close 全用 fd 定位，不再检索目录
close → 进程表项撤销，系统表引用计数减到 0 才真正撤销
```

- 这就是 01 篇 PCB"打开文件描述符表"的本体；**打开一次、反复使用**是文件读写的效率前提。
- 02 篇的管道就是这种"共享文件"：写端写入、读端读出，定长缓冲满了写者阻塞——文件机制在进程通信里的化用。

## 3. 文件系统的层次结构与磁盘布局

### 3.1 文件系统的层次结构【必背概念】

汤小丹把文件系统模型分为**三层**（自底向上），中间的软件集合层内部再细分为四个子层：

```text
③ 文件系统接口（最高层）：命令接口（终端命令）＋程序接口（系统调用 open/read/write/close）
② 对对象操纵和管理的软件集合（核心层），自顶向下四个子层：
     逻辑文件系统       按符号文件名访问、管理记录与文件、文件保护（§6、§7.2）
     基本 I/O 管理程序  逻辑块号→物理块号、空闲盘块管理、I/O 缓冲指定（§4、§5）
     基本文件系统层     内存 ⇄ 磁盘之间数据块的交换
     I/O 控制层         磁盘驱动程序等设备驱动程序（06 篇）
① 对象及其属性（最低层）：文件、目录、磁盘存储空间
```

- 一句话：**逻辑文件系统管"名字、记录与保护"，下面三层管"盘块与物理"**；某层软件只能调用同层或更低层的模块。
- 对应关系：逻辑文件系统 = 目录（§6）与保护（§7.2）、基本 I/O 管理程序 = 分配方式（§4）与空间管理（§5）、I/O 控制层 = I/O（06 篇）——这一张图就是本篇的目录。

> **王道口径对照**（自顶向下 7 层）：用户接口 → 文件目录系统 → 存取控制验证 → 逻辑文件系统与文件信息缓冲区 → 物理文件系统 → 辅助分配模块 → 设备管理模块。对应关系：目录、存取控制两层合入汤的"逻辑文件系统"；物理文件系统、辅助分配对应"基本 I/O 管理程序"；设备管理对应"基本文件系统层 + I/O 控制层"。两套说法只是切分粗细不同，职责完全对齐——答题先看题目用哪套名词。

### 3.2 文件系统在磁盘上的布局

```text
引导块 | 超级块 | i-node 区（索引结点表） | 数据区
```

- **引导块**：存放引导程序，开机先读它（可独立于本文件系统，常在第 0 块）。
- **超级块**：文件系统的"总说明书"——盘块总数、空闲块数、i-node 总数与起点、空闲盘块号栈（成组链接法 §5.3 的"栈"就住在这里）等。
- **i-node 区**：所有文件的索引结点集中连续存放，按编号可直接定位。
- **数据区**：文件数据块与目录文件的数据块（目录也是文件，数据块里放目录项）。
- 记忆：`引导 → 超级 → 索引 → 数据`；挂载（mount）时先读超级块、定位根目录 i-node，再把该文件系统挂到目录树某节点上，与根文件系统融为一体。

## 4. 外存分配方式：文件怎么上盘

### 4.1 连续分配

- 逻辑连续 → 物理连续：FCB 记**起始块号 + 长度**。
- 优点：支持**直接（随机）存取**（起始块 + i 偏移一次定位）、顺序访问速度最快（几乎不寻道）。
- 缺点：**外零头**（同动态分区，需要紧凑）、**文件难动态增长**（后面被占）、必须预知大小。
- 定位：同 04 篇动态分区是"内存的连续方案"，这里是"外存的连续方案"——结论可以整体平移。

### 4.2 链接分配：隐式链接与显式链接 FAT

| | 隐式链接 | 显式链接（FAT） |
|---|---|---|
| 指针放哪 | 每个盘块**末尾**存下一块号 | 指针集中抽出来放 **FAT 表**（文件卷一张） |
| 访问第 i 块 | 从头顺链读盘，**i 次磁盘 I/O** | FAT 开机调入**内存常驻**，内存里顺链查 i 次（无访盘），数据块**只读盘 1 次** |
| 随机存取 | 不支持 | 支持 |
| 代价 | 每块尾部损耗 | FAT 本身占外存 + 常驻内存（与盘块总数成正比） |

- **为什么隐式链接要 i 次访盘**：下一块的块号存在当前块的**末尾**，想拿到它必须先**读出当前块**；访问第 i 块只能从链头逐块读入（读块 1 得块 2 的号、读块 2 得块 3 的号……），共 i 次——这正是它**不能随机访问**的根因。
- FAT 是 MS-DOS/早期 Windows 的方案；"链接分配不支持随机访问"这句口径**只对隐式链接成立**——FAT 恰恰是为了随机访问才把指针集中到内存。
- 两者共同点：离散存放、**无外零头**、文件易扩展。

### 4.3 索引分配

- 每文件一张**索引块**（盘块号数组），FCB 记索引块地址。支持直接存取、无外零头、易扩展。
- 访问第 i 块：先读索引块、再读数据块——**2 次访盘**（索引块常驻内存后 1 次）。
- 大文件问题：一张索引块装不下 → 链接式索引、多重索引、**混合索引**（主流）。

### 4.4 混合索引（UNIX）

i-node 中放 **10 个直接地址 + 1 一次间接 + 1 二次间接 + 1 三次间接**（一次间接块 = 纯地址块）：

```text
直接地址：i-node 里直接记 10 个数据块号 → 小文件一次定位
一次间接：地址块记 1024 个数据块号
二次间接：地址块记 1024 个"一次间接地址块号"
三次间接：再套一层
```

计算例【必背题型】（块 4KB、地址项 4B → 每地址块装 4KB/4B = 1024 = 2¹⁰ 项）：

| 层 | 块数 | 容量 |
|---|---|---|
| 10 直接 | 10 | 40KB |
| 一次间接 | 1024 | +4MB |
| 二次间接 | 1024² | +4GB |
| 三次间接 | 1024³ | +4TB |

最大文件 = (10 + 1024 + 1024² + 1024³) × 4KB。
访问次数（i-node 已在内存）：直接块 **1** 次、一次间接 **2** 次（读地址块 + 数据块）、二次 **3** 次、三次 **4** 次。

> 教材差异注记：直接地址个数各教材/真题不统一（常见 10、12，另有 7、9 等变体），做题**以题干给出的地址项分配为准**；本篇例按汤书/UNIX 经典的 10 项。

### 4.5 四方式对比总表

| 维度 | 连续 | 隐式链接 | 显式 FAT | 索引 |
|---|---|---|---|---|
| 随机存取 | ✓（最好） | ✗ | ✓ | ✓ |
| 外零头 | **有** | 无 | 无 | 无 |
| 文件增长 | 难 | 易 | 易 | 易 |
| 访问第 i 块的访盘次数 | 1 | i | 1（查 FAT 在内存） | 2（索引在内存则 1） |
| 额外开销 | 无 | 块尾指针 | FAT 表 | 每文件索引块 |

## 5. 文件存储空间的管理：空闲块怎么记账

### 5.1 空闲表与空闲链表

- **空闲表**：{起始块号, 空闲块数}，适用**连续分配**；分配算法同 04 篇动态分区（首次/最佳适应），回收考虑**合并相邻空闲区**。
- **空闲链表**：空闲盘块链 / 空闲盘区链，链上逐块（逐区）分配回收，简单但效率低。

### 5.2 位示图法

每一位对应一个盘块：0 = 空闲、1 = 已占（或相反，看题目口径）。

```text
每行（每字）n 位，从 0 编号：
  盘块号 b → 字号 i = b div n，位号 j = b mod n
  反向：b = n × i + j
从 1 编号时整体平移 1：i = (b−1) div n + 1，j = (b−1) mod n + 1
```

- 位示图大小：**块数 ÷ 8 = 字节数**。例：磁盘 320MB、盘块 512B → 640K 块 → 位示图 640K bit = **80KB**。
- 优点：容易找相邻空闲块（连续多个 0）、占用空间小。
- 口径警告【辨析】：先看题目"从 0 还是从 1 开始编号"，两种公式的差 1 是设错重灾区。

### 5.3 成组链接法（UNIX，离散分配的记账法）

记 `S.free` 为长度 100 的**空闲盘块号栈数组**（元素 `S.free(0)` ~ `S.free(99)`，其中 `S.free(0)` 是栈底），`n` 为栈中当前空闲盘块号个数（兼作栈顶指针）；每 100 个空闲块为一组（**末组可不足 100，以 `S.free(0)=0` 作链尾结束标志**）：

```text
分配一块：
  n > 1 → 弹栈一块
  n = 1 → 这块是"索引块"：先把它记的下一组 100 个块号读入栈，再分配它
回收一块：
  n < 100 → 直接压栈
  n = 100（栈满）→ 先把栈中 100 个块号写进新回收的块，再把它压栈（栈里只剩它）
```

迷你推演（栈容量 5，初始 {5,4,3,2,1}，n=5）：
- 分配 2 块：弹 1、弹 2 → {5,4,3}，n=3
- 连续分配到临界：弹 3、弹 4 → {5}，n=1；再分配 → 先把 5 号块内容（设为 {10,9,8,7,6}）读入栈，再分配 5 号 → 栈变 {10,9,8,7,6}
- 回收撞栈满：栈 {7,6,5,4,3} n=5 时回收 2 号 → 把栈内容写入 2 号块，栈变 {2}，n=1

- 呼应 04 篇：请求分页从外存调页，读的就是文件区/对换区里这些被记账的盘块——UNIX 中**对换区连续分配求快，文件区离散分配求空间利用**，两种记账并行。

## 6. 文件目录：从名字到盘块

### 6.1 目录结构三级跳

| 结构 | 机制 | 缺陷 |
|---|---|---|
| 单级目录 | 全系统一张表 | 查找慢、**重名冲突**、不能分类 |
| 两级目录 | 主文件目录 MFD + 各用户 UFD | 解决重名与隔离；仍不便共享和灵活组织 |
| **树形目录** | 目录 → 子目录 → 文件；绝对路径 / 相对路径 | 路径逐级检索 I/O 多（见 §6.3） |

- 树形解决重名（不同目录下可同名）、便于分类管理；代价是深路径检索。
- **当前目录**：每操作都从根开始 → 引入"当前目录"，相对路径省掉前缀逐级查找，直接省磁盘 I/O。

### 6.2 目录实现：线性表与哈希表

| 实现 | 机制 | 优点 | 缺点 |
|---|---|---|---|
| **线性表** | 目录项（文件名 + 指针/i-node 号）顺序存放 | 简单；增删目录项方便 | 按名查找要**顺序扫描**，大目录慢；建文件还需先查重名 |
| **哈希表** | 文件名 → 哈希值 → 指向目录项 | 查找**接近 O(1)**，插入删除简单 | 有**哈希冲突**；表长固定、扩容/重建麻烦 |

- 内存里还会缓存**目录项（dentry）**：把最近访问过的目录项留在内存，减少目录检索的磁盘 I/O。
- 一句话：线性表"简单但慢"，哈希表"快但要处理冲突"；ext 系列文件系统用哈希实现目录。

### 6.3 目录检索 I/O 计算

- 检索路径的方法模板：路径每经过一级目录 = 查该级目录文件（可能多块）+ 读该级 FCB/i-node；**目录项越瘦，读的块越少**。
- 提速算例：640 个文件的目录，FCB 64B、盘块 1KB → 目录 40 块，平均检索 20 块；改用 16B 目录项 → 10 块，平均 5 块 + 读 1 块磁盘 i-node = **6 块**（20 → 6）。
- 算例拆解（把"结果"还原成"模板"）：
  - 每块可放目录项数 = 盘块大小 ÷ 单个目录项大小 = 1KB ÷ 64B = **16**；目录占块 = 640 ÷ 16 = **40 块**；顺序查找平均读 40 ÷ 2 = **20 块**。
  - 瘦身为 16B 后：每块可放 1KB ÷ 16B = **64** 项；目录占块 = 640 ÷ 64 = **10 块**；平均读 10 ÷ 2 = **5 块**；再读 1 块磁盘 i-node → **6 块**。
  - 换数据照套：`每块项数 = 盘块 ÷ 目录项`、`占块 = 文件数 ÷ 每块项数`、`平均 = 占块 ÷ 2`（索引结点版再 +1）。

## 7. 文件共享与保护

### 7.1 硬链接 vs 符号链接

| | 硬链接（基于索引结点共享） | 符号链接（sym link） |
|---|---|---|
| 实现 | 多个目录项指向**同一 i-node**，i-node 记**链接计数 links** | 新建一个 LINK 类型文件，内容是**目标的路径名** |
| 删除共享文件 | links 减 1，**减到 0 才真删** | 原文件可删，链接文件**悬空**（访问时报错） |
| 跨文件系统 | **不能**（目录项存 i-node 号，仅本文件系统内唯一） | **能**（存的是路径名，可跨文件系统/挂载点，也可链接目录） |
| 访问代价 | 与普通文件相同 | 要先读链接文件拿到路径，再重新检索目录——**多一次（或多次）访盘** |

- 口径：硬链接快但不能跨盘、不能链目录（会成环，目录树变无环图才允许）；符号链接灵活但有悬空与额外 I/O 的代价。
- "无环图目录结构"词条见 §11 低频清单。

### 7.2 保护

- 常用手段：UNIX **9 位权限 rwx**（属主/组/其他三类 × 读/写/执行）、口令、加密；细粒度模型（访问矩阵、ACL、能力表）与安全科 03 篇（访问控制模型）分工，OS 篇记机制即可。
- **可控制的访问类型**（6 种）：**读**（取文件内容）、**写**（修改内容）、**执行**（装入内存运行）、**添加**（只许在文件末尾追加，是写的受限版）、**删除**（删文件、释放空间）、**列表清单**（列文件名与属性）。高层操作可由低层组合：复制 = 读 + 新建写，故有读权限者天然能复制、打印。
- 【辨析】rwx 三者**没有高低等级之分**，是互相独立的权限位；八进制 r=4、w=2、x=1 只是**位权**不是等级。论危害**写权限最大**（可篡改甚至清空文件）。对目录而言 rwx 含义另算：目录 w = 可增删/重命名目录项，反而最危险；x = 能否进入目录访问其中文件。

## 8. 收尾：可靠性与一致性（低频）

- **可靠性**：磁盘容错 SFT-I（镜像）、SFT-II（双工）、后备系统——词条进 §11，RAID 完整机制归 06 篇（Stallings 11.6）。
- **一致性**：崩溃后 FAT/位示图可能与实际不符 → 一致性检查（计数比对，如 dup 块）；事务与检查点保证"一组操作要么都做要么都不做"。

## 9. 典型题型与方法

**题型① 混合索引计算**（最高频大题）：
四步——①地址块可装项数 = 块大小 / 地址长度（4KB/4B = 1024）；②按 10 直接 + 1024 + 1024² + 1024³ 分层算块数；③最大文件 = 总块数 × 块大小；④问访问次数：层数 + 1 次访盘（直接块 1 次，k 级间接 k+1 次），前提是 i-node 已在内存。

**题型① 小综合（照做一遍）**：块 4KB、地址项 4B，i-node 用 **10 直接 + 1 一次间接 + 1 二次间接**。文件 5MB，问用到哪几层索引？读最后一个字节几次访盘？
- 解：①总块数 = 5MB ÷ 4KB = **1280 块**；②前 10 块走直接，余 1270 块；③一次间接只装 1024 块，余 1270 − 1024 = **246 块**，故还需**二次间接**；④最后一个字节落在第 1280 块，走二次间接：读二次间接地址块 → 读一次间接地址块 → 读数据块，共 **3 次访盘**（i-node 已在内存）。
- 链路：`字节数 → 总块数 → 逐层扣减 → 定位层级 → 数访盘次数`，这四步能套所有混合索引题。

**题型② 位示图**：先确认编号口径（0/1 起始）→ 盘块号 ↔ (字号, 位号) 互算（div/mod）；问位示图大小：块数 ÷ 8 换字节。位示图本身也占盘块时注意"从哪一块开始放位示图"的附加条件。

**题型③ 成组链接推演**：盯住两个临界——分配时 **n=1**（先读索引块再分配它）、回收时 **n=100 栈满**（先写出栈内容再压新块）。手推时写清每步栈内块号和 n。

**题型④ 目录检索 I/O 比较**：FCB 版每级"目录块 × 命中前比较 + FCB 块"；索引结点版"瘦目录项算块数 + 1 块 i-node"。先算每块装多少目录项，再算平均读几块；当前目录只省掉路径前缀部分。

**题型⑤ 分配方式访问计算**：连续 1 次；隐式链接第 i 块 i 次；FAT 查链在内存、数据 1 次；索引首次 2 次（索引块 + 数据）。先问"索引/FAT 是否已在内存"再作答——这是答案分档的开关。

**题型⑥ 共享方式辨析**：删除后果（links 减一 vs 悬空）、能否跨文件系统/链接目录、访问是否多读盘。题目出现"链接计数/ln"想硬链接，出现"路径名/ln -s"想符号链接。

**题型⑦ 层次结构 / 目录实现概念题**：给一个"删除 D:/xx/yy"的场景，按汤口径三层/四子层（或王道 7 层）逐层说职责；或问线性表/哈希目录的取舍——线性表简单但查名慢，哈希查找快但有冲突与扩容问题。

## 10. 易错点

- "目录不是文件"：错，目录文件就是 FCB（或瘦目录项）的集合，和普通文件一样占盘块、走打开机制。
- "用了索引结点后目录项就不含文件信息了"：看清前后——瘦身前目录项 = **完整 FCB**（名 + 全部描述信息）；瘦身后目录项 = **文件名 + i-node 编号**。FCB **没有消失**，只是被搬进了 i-node，目录项只留"名字 → 编号"这一层索引（选择题常在这里挖坑）。
- 逻辑结构与物理结构混答：逻辑结构是**用户视角的记录组织**，物理结构是**外存盘块分配**——题问"用户/系统"先分边。
- 文件系统各层职责混淆：**目录系统**按路径找 FCB，**存取控制**判权限，**逻辑层**做"记录号→逻辑块号"，**物理层（基本 I/O 管理程序）**做"逻辑块号→物理块号"——别把"找目录"和"转地址"混一层。
- "链接分配都不支持随机访问"：错，只对**隐式链接**成立；FAT 把指针集中到内存，支持随机访问。
- FAT 的指针"查一次读一次盘"：错，FAT **开机后常驻内存**，顺链查全在内存，数据块只需 1 次访盘。
- "索引分配访问任何块都要 2 次访盘"：看口径——索引块不常驻时 2 次；常驻（或已读入）后 1 次；混合索引还要按层加。
- 混合索引算最大文件漏掉直接块：最大文件 = **（直接块数 + 各间接层块数之和）× 块大小**，直接块不参与"每块 1024 项"的除法。
- 1024² 与 1024³ 层级搞反：一次间接 ×1024，二次 ×1024²，三次 ×1024³——层数就是方次。
- 位示图 0/1 起始口径不分：b = n×i + j（从 0）与 b = n(i−1)+j（从 1）差 1，先看题目再套。
- 成组链接回收时"栈满直接压栈"：错，栈满要先**把栈内容写进新回收块**，栈里只留这个新块号。
- 成组链接分配时"栈空才特殊"：错，特殊在 **n=1**——最后一块是索引块，要先读入下一组再分配它。
- "树形目录解决了共享问题"：错，树形解决的是**重名与分类**；共享靠硬链接/符号链接（无环图）。
- "r=4、w=2、x=1 说明读权限等级最高"：错，这是**位权**不是等级，rwx 互相独立、无高低之分；论危害写权限最大，目录的写权限更是能增删整个目录项。
- "哈希目录一定比线性表好"：错，哈希查找虽快，但有**冲突**、表长固定、扩容重建的代价；线性表胜在简单。
- "硬链接可以跨文件系统/链接目录"：错，都不能；跨盘、链目录用**符号链接**。
- 删除有硬链接的文件"直接释放盘块"：错，links > 0 只减计数，**减到 0** 才释放。
- "打开文件后每次读写仍要查目录"：错，open 只付一次目录检索代价，之后用 fd 直接访问打开文件表。
- "关闭文件就释放所有内存结构"：错，close 撤进程表项；系统打开文件表要等**引用计数为 0** 才撤销。
- 索引结点提速原理答"查找更快"：错，原理是**目录项变瘦 → 目录占块少 → 检索的磁盘 I/O 次数减少**。
