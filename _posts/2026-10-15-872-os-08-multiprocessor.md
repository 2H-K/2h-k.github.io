## 3. 多处理机操作系统的四个特征

> 教材主线：本节按教材小节顺序展开，四条依次是**进程的并行性、进程间同步、进程通信、处理机及进程调度**（具体章号见文末出处汇总）。第四条即本篇核心，单独放到 §4 展开。

### 3.1 特征的①：进程的并行性

【必背】**并行性**是指两个或多个事件在**同一时刻**发生；**并发**是指多个程序在**同一时间间隔**内运行。单处理机系统在宏观上可以让多个程序"同时"运行，但微观上每一时刻只有一道程序在执行，它们只能是**分时地交替执行**；只有把可并发执行的进程分配到**多个处理机**上，才能实现**真正的并行执行**。

一句话得分句：**并发是"时间间隔"上的宏观概念、只强调程序在执行上是并发的；并行是"同一时刻"上的微观概念、强调同一时刻真的在执行**。并发性是 OS 的基本特征，并行性是多处理机系统的特征。

辨析（选择高频）：三组不要混。

| 概念 | 判断口径 |
|---|---|
| 单处理机 + 多道程序 | 只有**并发**，没有并行（微观交替） |
| 多处理机 + 同一进程的多个线程 | 可以**既并行又并发**：不同线程占不同核 |
| 多核 + 一个线程（单线程程序） | 单个线程内部不可能并行 |

### 3.2 特征的②：进程间同步——为什么必须出现"自旋"

【必背】**自旋（spin）**是指进程在竞争临界资源失败后**不进入阻塞态**，而是反复测试并重置该资源的锁变量、循环等待；用这种方式实现互斥的同步原语称为**自旋锁（spinlock）**。**自旋只适用于临界区很短的场合**，因为自旋期间进程占着 CPU 却不干活，临界区越长浪费越大。

对照 03 篇的四准则，把"该用哪个"摆成一张表：

| 手段 | 多处理机上是否有效 | 为什么 |
|---|---|---|
| 关中断进入临界区 | **失效** | 只能关本核中断，其他核照跑照写共享变量 |
| TSL / Swap 硬件指令 | 有效，但**忙等** | 原子性由硬件保证；拿不到锁只能循环重试 → 就是自旋的原型 |
| 自旋锁（TSL + 退避/超时） | 有效，专门为多核设计 | 在"临界区极短"时，阻塞的开销反而更大 |
| 信号量 / 阻塞式互斥锁 | 有效 | 竞争激烈或临界区长时，让权等待更划算 |

【辨析】**自旋 vs 阻塞，看三个条件是否同时成立**：

```text
该自旋（忙等）→  ① 临界区极短，不含系统调用、不可能阻塞
                ② 持锁时间短，等待者大概率能很快拿到
                ③ 处理机数少、竞争不激烈
任一条不成立 → 阻塞（睡眠、让出 CPU、醒来再抢）
```

两个必须记住的反直觉点：

- **自旋是"违反让权等待"的**：03 篇四准则第三条（让权等待）在 TSL/Swap/自旋锁上**不满足**——拿不到锁的进程并不让出处理机。选择题问"哪种互斥方式满足四准则"时，答案是信号量/互斥锁那一类，不是 TSL。
- **自旋必须配超时或退避**：无节制的循环重试会活锁或让某些线程长期饥饿；内核里的自旋锁一般带"自旋次数上限，超了就转睡眠"。

> 与 04 篇死锁的联系：多个核同时自旋一个**永远得不到**的锁，自旋不会死锁（死锁要求"都无法推进"），但会**活锁**并把 CPU 全部烧光——这是同一类问题的两种结局。

### 3.3 特征的③：进程通信

【辨析】SMP 内部与多计算机之间，通信机制的选择完全不同：

| 维度 | 共享存储器变量交换 | 消息传递 |
|---|---|---|
| 通信方式 | 多个处理机直接读写**同一片主存**变量 | `send` / `receive` 原语，消息经内核缓冲中转 |
| 通信开销 | **很低**，但要自己用锁/信号量同步 | 较高：系统调用 + 拷贝 + （分布式时还有网络） |
| 是否需额外同步 | **需要**（共享就要互斥） | 发送接收原语自带同步语义 |
| 耦合度 | **紧耦合**（要求有共享主存） | **松耦合**（只要求能传消息） |
| 适用场合 | 同构、共享主存的 SMP | 异构、多计算机、分布式系统 |
| 阻塞特性 | 用锁/自旋时一般忙等，**不阻塞** | 邮箱满/空时可阻塞 |

【必背】**共享存储器多处理机系统一般采用共享存储器变量交换进程信息，多计算机系统一般采用消息传递方式**——因为 SMP 有共同主存且处理机同构，消息传递的开销和格式差异都白付；一旦跨机器，主存不共享，就只剩消息这一条路。

一句话判据：**机内共享快，机间消息灵**。

## 4. 调度：分给哪个核，以及怎么分得不亏

### 4.1 非对称多处理（主从式 master/slave）

【必背】**主从式**是指指定一个处理机作为**主处理机（master）**，专门运行操作系统代码、做出**全部调度决策**（进程分派、系统调用处理、中断处理）；其余处理机作为**从处理机（slave）**，**只运行用户进程**，遇到系统调用或中断就把请求通过共享存储器交给主处理机，由主处理机代理完成。

| 优点 | 缺点 |
|---|---|
| 结构简单：调度决策集中在一处，**不必处理多个核同时进内核的同步问题** | **主处理机成为系统瓶颈**：所有系统调用、中断、调度都过主核，主核忙时从核大量空等 |
| 用户程序在主从机上**完全一样**，移植性好 | **负载不均**：从核空闲时无法分担系统工作，从核遇到系统调用必须等主核 |
| 内核不需可重入，不加锁即可 | **可靠性差**：主核故障整个系统瘫痪；核数增加瓶颈更突出，不易扩展 |

### 4.2 对称多处理 SMP

【必背】**对称多处理（symmetric multiprocessing, SMP）**是指多个处理机**地位完全平等、共享同一主存、运行同一个操作系统**，**每个处理机都可以执行内核代码、都可以参与进程调度**——任一处理机上的线程都可被调度到其他任一处理机上运行，从而消除主从式的瓶颈与不对称。

由 SMP 派生的两条硬要求（都能回溯到前面几篇）：

- **内核必须可重入（reentrant）**：多核可同时进入内核各模块，因此内核的全局数据结构必须加锁保护 → 锁就用 §3.2 的自旋锁。这就是 03 篇"临界资源可能同时被多个处理机上的进程访问"在多核上的落地。
- **调度单位必须是线程（可分派实体）**：只有线程才能被单独分到不同的核上；一个多线程进程可以被拆开、散落在多个核运行，这正是 SMP 相对单处理机最大的性能来源（对照 02 篇"进程是资源分配单位、线程是调度单位"）。

**SMP 调度的两个层次**（分清是高频考点）：

```text
进程调度：就绪队列里谁上 CPU      → 算法仍是 04 篇那一套（FCFS/SJF/RR/MLFQ…）
     ▼
处理机分配（线程调度）：谁分到哪个核上跑 → 本篇新增的一层
     │  还要额外盯两件事：核间负载是否均衡｜迁移会不会打掉 Cache 局部性
     ▼
```

| 分配方式 | 分配时机 | 优点 | 缺点 |
|---|---|---|---|
| **静态分配** | 创建进程/线程时就指定核，运行中固定 | 实现简单、无迁移开销 | 负载不均：I/O 型线程会把某个核占满，另一核空转 |
| **动态分配** | 运行时把线程迁到别的核 | 负载均衡好、利用率高 | 迁移开销大：换核 = Cache/TLB 冷启动 |

**就绪队列怎么组织**——SMP 调度最本质的矛盾在这里：

| | 集中式（全系统一个就绪队列） | 分布式（每个处理机一个本地队列） |
|---|---|---|
| 取线程方式 | 任一空闲核都从**全局**队列取 | 先取**本地**队列，本地空了才从别核取 |
| 负载均衡 | **天然均衡**（谁来取谁拿） | 天然**不均**，需要迁移/窃取来补救 |
| Cache 局部性 | **差**：刚跑完的线程可能被另一个核取走，缓存全冷 | **好**：线程贴着原核跑，数据大概率还在缓存里 |
| 调度开销 | 队列需加锁保护，多核争抢同一把锁 | 小 |
| 补救手段 | 无需迁移 | **迁移（push）**、**窃取（work stealing, pull）**、周期性重平衡 |

【辨析】**为什么要有"本地队列"而不是只用全局队列**：因为迁移的代价是真实的——线程换核意味着它的数据不在本地核的 Cache 里了，要重新从内存加载（02 篇"上下文切换的 Cache 冷启动"）。为了缓存局部性宁可容忍短期不均衡，再用窃取机制兜底。这就是 SMP 调度里 **Cache 局部性 ↔ 负载均衡**这对矛盾，题目问"SMP 调度难在哪"就答它。

### 4.3 虚拟处理机（超线程 SMT）

【必背】**虚拟处理机**是指在一个**物理**处理机内部，由硬件把该处理机**划分成多个逻辑处理机**（硬件多线程 / simultaneous multithreading, SMT），每个逻辑处理机拥有**独立的寄存器组、PC 等现场**，但**共享该物理处理机的执行单元和 Cache**；OS 看到的是若干台"虚拟处理机"，可以像调度多个真实处理机一样在其上分派线程。

机制链：

```text
一个物理核（固定发射宽度、固定执行单元数、固定 Cache）
  ├─ 逻辑处理机 0：独立 PC / 寄存器 → 取出指令流 A
  └─ 逻辑处理机 1：独立 PC / 寄存器 → 取出指令流 B
                    │ 共享执行单元与 Cache：谁缺资源谁让谁等
                    ▼
        一个核在同一时刻驱动**多条指令流** → 指令吞吐上升
```

三个必记的辨析点：

| 维度 | 虚拟处理机（SMT） | 虚拟机 / 虚拟化平台 |
|---|---|---|
| 造了几个东西 | 多个**执行流**（硬件线程） | 多个**完整操作系统**（带自己的内核、进程、文件系统） |
| 粒度 | CPU 核内部 | 整台物理机 |
| 共享什么 | 共享**执行单元 + Cache** | 共享物理硬件，OS 之间靠 Hypervisor 隔离 | 
| 对应 01 篇"虚拟" | 时分复用**同一核的执行单元** | 时分复用整机资源 |

- **它提高的是吞吐，不是延迟**：频率不变、单条指令的执行时间不变甚至更长（争抢资源），但单位时间完成的指令数上升。
- **它不是"真并行"**：同一物理核上的两个逻辑处理机共享同一套执行单元，仍在互相争抢，只是把执行单元的空闲间隙填满了。
- **对照 01 篇的"虚拟"三例**：虚拟处理机 = **对处理机时分复用**，虚拟存储器 = **对内存的时空对换**，虚拟设备（SPOOLing）= **用共享设备模拟独占设备**。三个虚拟的"虚拟掉的是什么"要能一句话答出。

## 5. 回到 01 篇：四个基本特征在多处理机上重读

| 01 篇特征 | 单处理机口径 | 多处理机上的变化 |
|---|---|---|
| **并发** | 宏观同时、微观交替 | 多个核上可**真并行**；"并发"一词的宏观含义不变 |
| **共享** | 互斥共享要靠 PV 操作保证 | 还要保证**跨处理机**互斥；关中断失效，自旋锁成为基本手段 |
| **虚拟** | 虚拟处理机（分时）、虚拟存储、虚拟设备 | 虚拟处理机有了**硬件级实现**（SMT），不再纯靠分时 |
| **异步** | 执行速度不可预知 | 额外要面对**核间负载不均**与**迁移时机**的不确定 |

## 6. 一页压缩表

```text
类型：同构/异构（按处理机是否相同）× 共享存储器型(SMP) / 消息传递型(多计算机、分布式)
特征：① 并行性  ② 进程同步（自旋）  ③ 进程通信（共享变量 / 消息）  ④ 处理机及进程调度
主从式：主核跑 OS 并做全部决策｜优点 简单好移植｜缺点 瓶颈、负载不均、可靠性差、不可扩展
SMP   ：核地位平等、同一 OS、可重入内核｜单位是线程｜全局队列(均衡·局部性差) vs 本地队列(局部性好·需窃取)
核心矛盾：Cache 局部性 ↔ 负载均衡（迁移换核 = Cache 冷启动）
虚拟处理机：SMT，一核多逻辑核，共享执行单元与 Cache → 提吞吐不提延迟
选通信：机内共享快，机间消息灵
```

## 7. 典型题型与方法

**题型① 前篇口径的多处理机判定**（给一句 01–07 篇的说法，问"在多处理机上是否成立"）。
抓三个失效点：**关中断**只对本核有效 → 换自旋锁；**同一时刻只有一个运行态进程** → 多核上可多个；**调度只选 1 个进程** → 还要选核。

**题型② 并发 vs 并行 辨析**。
只问两件事：① 是不是"同一时刻"（是→并行，不是→并发）；② 系统有几个处理机（单核给多个程序也只能是并发）。

**题型③ 自旋还是阻塞**（给场景，选手段）。
按 §3.2 三个条件反问一遍：临界区短吗？可能阻塞吗？核多、竞争激烈吗？只要有一条否，就不能自旋。题干出现"关中断保证互斥""多个处理机"时直接选自旋锁/TSL。

**题型④ 主从式 vs SMP 简答对比**。
固定四栏：谁跑 OS 代码 / 谁做调度决策 / 瓶颈在哪 / 可扩展性。
主从式 = 一个核跑 OS 全部；SMP = 每个核都能跑内核都能调度。再补一句"主从式不需要可重入内核，SMP 必须可重入所以内核要加锁"。

**题型⑤ SMP 调度组织选择**（给需求，选队列组织）。
"要最大吞吐、线程都很重、Cache 冷启动可忽略" → 集中式全局队列；
"要保持数据局部性、线程数远少于核数" → 分布式本地队列 + 窃取。答题时必须**两个原因都写**（均衡 vs 局部性），只写一个给一半分。

**题型⑥ 虚拟处理机 vs 虚拟机 辨析**。
看"造出来的是什么"：执行流 → SMT；完整 OS → 虚拟化。再答"为什么 SMT 提吞吐不提延迟"（执行单元共享、争抢资源）。

## 8. 易错点

- "多处理机上关中断也能实现互斥"：错，只能关本核中断，**其他核照跑照写共享变量**（03 篇已列，此处收口）。
- "自旋锁满足让权等待"：错，拿不到锁的线程**占着 CPU 循环重试**，违反让权等待；四准则里只有前两条成立。
- "自旋适合临界区很长的场景"：错，自旋必须在**临界区极短**时用；临界区长就该阻塞让权。
- "自旋一定会死锁"：错，自旋不会造成互相等待的死锁（死锁要求都无法推进），但会**活锁并烧光 CPU**。
- "并发就是并行"：错，并发是时间间隔上的宏观概念，单核多道程序也只有并发。
- "主从式里从处理机也跑操作系统代码"：错，从处理机**只跑用户进程**，遇系统调用/中断要交给主处理机代理。
- "主从式的优点是性能好、负载均"：错，正好相反——主核是瓶颈、负载不均，这是它的**缺点**；优点是简单、易移植、不必处理多核进内核的同步。
- "SMP 里所有核都跑 OS 代码"：半对——每个核**都可以**执行内核代码、都参与调度（这正是"对称"），但具体跑哪段内核取决于当时在处理什么中断/系统调用。
- "SMP 也要用 03 篇的关中断来保护内核数据结构"：错，SMP 的内核全局结构必须用**自旋锁**保护。
- "SMP 的调度单位还是进程"：错，能被拆开分到不同核的是**线程**，所以 SMP 环境下调度单位是线程。
- "本地就绪队列更好，因为不用加锁"：只对一半。好处是 **Cache 局部性好、调度开销小**；代价是**可能负载不均**，必须靠迁移/窃取补救，不能说成"全面更优"。
- "迁移线程总是好的"：错，迁移换来负载均衡，代价是 **Cache/TLB 冷启动**，所以要权衡。
- "超线程让程序跑得更快（响应更快）"：错，它提高**吞吐/资源利用率**，单线程的延迟可能变长。
- "虚拟处理机就是虚拟机"：错，前者在一个物理核内造多个**执行流**，后者在一台机器上跑多个**完整操作系统**。
- "SMP 用消息传递通信"：错，**共享存储器型 SMP 用共享变量交换**；消息传递是多计算机/分布式系统的选型。
