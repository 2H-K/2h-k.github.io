## 2. I/O 系统分层与设备

### 2.1 I/O 软件四层

```text
用户层 I/O 软件      库函数（printf）、SPOOLing
  ▼ 独立性接口
设备独立性软件       逻辑设备名映射、设备保护、缓冲管理、设备分配、差错记录
  ▼ 统一抽象命令
设备驱动程序         把抽象命令翻译成控制器寄存器读写（直接碰硬件的层）
  ▼
中断处理程序         I/O 完成后的善后（唤醒等待进程）
  ▼
硬件                 设备控制器 → 设备
```

层次判断题套路：出现"逻辑设备表"→ 独立性软件；出现"寄存器/设备命令"→ 驱动程序；出现"库函数/SPOOLing"→ 用户层；出现"I/O 完成、唤醒"→ 中断处理。

### 2.2 设备与控制器

- 设备分类【辨析】：按速率（低速键鼠 / 中速打印机 / 高速磁盘）；按交换单位——**块设备**（块为单位、可寻址随机访问、速率高：磁盘）vs **字符设备**（字节流、不可寻址、常中断方式：键盘打印机）。
- **设备控制器**：CPU 与设备之间的接口电路，核心功能——接受并识别 CPU 命令、数据交换、状态报告、地址识别、数据缓冲、差错控制。CPU 写**寄存器**即下命令。
- I/O 端口编址一行：**统一编址**（内存映射 I/O，访存指令操作寄存器）vs **独立编址**（专用 I/O 指令）。

## 3. 中断机构：设备喊 CPU 的方式

### 3.1 外中断 vs 内中断

| | 外中断（中断） | 内中断（异常/陷入 trap） |
|---|---|---|
| 来源 | CPU **外部**：设备完成、时钟、I/O | CPU **内部**：缺页、算术溢出、系统调用 |
| 时点 | 每条**指令周期末**检查响应 | 指令**执行期间**产生并处理 |
| 本篇/前篇 | 本篇：中断机构 | 01 篇 trap；04 篇缺页中断 |

### 3.2 中断处理机制链与多重中断

```text
设备完成 → 控制器发中断请求 → CPU 在指令周期末检查并响应
  → 关中断 → 保存断点和现场 → 执行中断处理程序（驱动程序配套例程）
  → 恢复现场 → 开中断 → 返回被中断的进程
```

- **多重中断（中断嵌套）**：CPU 已在中断处理中，**优先级更高**的新中断可在**开中断**期间打断它——低优先级中断处理时关中断，保护现场那段不可嵌套。
- 对照 04 篇：缺页中断是**内中断**，在指令执行期间处理、一条指令可多次缺页——与本表对照记。

## 4. 设备分配与设备独立性

### 4.1 设备独立性

用户程序用**逻辑设备名**（"打印机"）而不是物理设备名（"/dev/lp0"）申请设备，由系统经**逻辑设备表 LUT**（逻辑名 → 物理名 → 驱动入口）映射。好处：设备分配**灵活**（换设备不改程序）、易实现 **I/O 重定向**。

### 4.2 分配数据结构链

```text
SDT 系统设备表（全系统一张）
  → DCT 设备控制表（每设备：状态、等待队列）
    → COCT 控制器控制表（每控制器）
      → CHCT 通道控制表（每通道）
```

分配顺序：设备 → 控制器 → 通道，三者齐活才能启动 I/O。分配安全性：**安全分配方式**（进程获得设备后阻塞等待，不会死锁但设备利用率低）vs **不安全分配方式**（可继续推进、可能死锁——03 篇银行家思想的设备版）。

### 4.3 SPOOLing（假脱机）

用一台**共享设备（磁盘）**模拟**独占设备**的行为：

```text
用户进程"请求打印" → 输出进程把打印内容排入输出井（磁盘）
  → 打印机空闲时，输出进程从输出井逐个取出送打印
```

组成四件：**输入井/输出井**（磁盘上的区域）、**输入/输出缓冲区**（内存）、**输入进程与输出进程**、**井管理程序**。
三作用【必背】：①提高 I/O 速度（井在磁盘，低速设备转高速）；②把**独占设备改造成共享设备**（多进程"同时"打印，实际排队）；③实现**虚拟设备**——每个进程都以为自己独占一台打印机。
这正是 03 篇死锁预防表里"破坏互斥"的 SPOOLing——打印机不再被某进程独占持有，互斥被共享井绕开。

## 5. 缓冲区管理：给速度差打补丁

引入缓冲的四理由：缓和 CPU 与设备**速度矛盾**；减少**中断频率**（攒一批再打断）；解决**数据粒度不匹配**（设备按块、进程按字节）；提高 CPU 与 I/O **并行性**。

### 5.1 单缓冲与双缓冲

```text
单缓冲（一个缓冲区，"填"与"搬"不能同时）：
  块周期 = max(C, T) + M
双缓冲（两块交替，"填 B2"与"搬 B1"并行）：
  块周期 = max(C + M, T)
（T = 设备输入一块时间，M = 缓冲→工作区传送时间，C = CPU 处理一块时间）
```

例：T = 100μs、M = 10μs、C = 50μs → 单缓冲 max(50,100)+10 = **110μs/块**；双缓冲 max(60,100) = **100μs/块**（瓶颈从 CPU 侧转到设备侧）。
口诀【辨析】：**M 在单缓冲里单列、在双缓冲里并入 CPU 侧**——两公式的差就是 M 能不能和 T 重叠。

### 5.2 循环缓冲与缓冲池

- **循环缓冲**：多缓冲组成环 + in/out 指针，生产者消费者结构（02 篇模型复用）。
- **缓冲池**：全系统公用的缓冲管理——空缓冲队列、装满输入队列、装满输出队列 + 四种工作缓冲（收容输入/提取输入/收容输出/提取输出）。池是**共享资源**，单/双缓冲通常是**每个设备/进程私有**。

## 6. 磁盘：性能、调度与 RAID

### 6.1 存取时间三段

```text
存取时间 = 寻道时间 Ts（磁头径向移动，占比最大）
         + 旋转延迟 Tr（平均半圈 = 60/(2r) 秒）
         + 传输时间 Tt（字节数 / 每秒传输字节数）
```

**磁盘调度优化的是寻道时间**。例：7200 转/分 → 旋转延迟平均 = 60/(2×7200) s ≈ 4.17ms。

### 6.2 磁盘调度六算法

统一例题（磁道 0~199，当前磁道 100，待访问 {55, 58, 39, 18, 90, 160, 150, 38, 184}，向大方向出发；SCAN/C-SCAN 扫到端点 199，LOOK 折返于最远请求）：

| 算法 | 机制 | 移动道数 | 平均寻道 |
|---|---|---|---|
| FCFS | 按到达顺序 | 498 | 55.3 |
| SSTF | 每次**最近**请求 | 248 | 27.6 |
| SCAN（电梯） | 一个方向扫**到端点**再折返 | 280 | 31.1 |
| LOOK | 扫到**最远请求**即折返（电梯真实行为） | 250 | 27.8 |
| C-SCAN | 单向扫描，到端点**快速回到另一端**再扫 | 388 | 43.1 |
| C-LOOK | 单向扫描，回程直返**另一端最远请求** | 322 | 35.8 |

推演示例（SSTF）：100→90(10)→58(32)→55(3)→39(16)→38(1)→18(20)→150(132)→160(10)→184(24)，合计 **248**。
- SSTF 缺点：**饥饿**（新请求总在近处，远端请求无限推迟）——与 03 篇 SJF 饿死长作业同理。
- SCAN 优点：不饥饿、性能好；缺点：对刚扫过的区域偏好不均（刚到端的请求要等一整圈）→ C-SCAN 把等待时间做得**更均匀**。
- 口径警告【辨析】：①SCAN 与 LOOK 的差别只在"到端点还是到最远请求"；②C-SCAN 的**回程不服务**但是否**计入移动道数**看题干，本例计入。

### 6.3 RAID

| 级 | 机制 | 冗余 | 要点 |
|---|---|---|---|
| RAID 0 | 条带化分散存取 | **无** | 性能最高，一块坏全丢 |
| RAID 1 | **镜像** | 100% 冗余 | 容量利用率 **50%**，读性能提升 |
| RAID 2 | 海明码纠错 | 有 | 理论档位，不用 |
| RAID 3 | **位交叉**奇偶校验 | 单校验盘 | 并行度高，单盘容错 |
| RAID 4 | **块交叉**奇偶校验 | 单校验盘 | 校验盘成写瓶颈 |
| RAID 5 | 块交叉 + **分布式**奇偶校验【必背】 | 校验分散各盘 | 最常用；允许**坏 1 块** |
| RAID 6 | 双重校验（P+Q） | 双校验 | 允许**坏 2 块** |

### 6.4 磁盘高速缓存

高速缓存存的是**副本**（读过的块可能反复被读，用 LRU 类算法管理）；缓冲区是**中转**（一次搬运的落脚点）——两个"内存替身"别混。提前读/延迟写进低频清单。

## 7. 知识点卡片：系统调用

```text
【系统调用】
一句话定义：OS 提供给用户程序（用户态）使用内核服务的唯一正式接口。
分类（王道五类）：设备管理、文件管理、进程控制、进程通信、内存管理。
执行过程：
  用户程序准备参数 → 执行陷入指令 trap（访管指令）
  → CPU 转核心态、保存现场 → 按调用号查入口表执行内核服务例程
  → 恢复现场、返回用户态
三个辨析：
  ① trap 是内中断（软中断）——01 篇五态图里"运行→核心态执行"的那条边
  ② 发起在用户态、执行在核心态
  ③ 模式切换 ≠ 进程切换：同一进程内用户态↔核心态往返，不换进程（01 篇口径）
易混：库函数可以纯用户态实现（strlen）；封装系统调用的库函数才进内核（printf→write）。
```

## 9. 典型题型与方法

**题型① 缓冲耗时计算**：先辨单缓冲还是双缓冲（看"一个/两个缓冲区"），再套公式：单 `max(C,T)+M`、双 `max(C+M,T)`；循环缓冲/缓冲池一般只考概念辨析不考计算。注意题目问的是"每块耗时"还是"处理 n 块总时间"（稳态周期 × n + 首块额外量）。

**题型② 磁盘调度大题**：六算法统一模板——①确认当前磁道与出发方向（题干给）；②FCFS 照队列、SSTF 贪心就近；③SCAN/C-SCAN 扫到**端点**，LOOK/C-LOOK 折返于**最远请求**；④C 系回程不服务；⑤逐段累加 |差值|，除以请求数得平均寻道。

**题型③ RAID 辨析**：抓三个开关——有没有冗余（0 无、1 镜像、3/4/5 校验、6 双校验）？校验放哪（专用盘 3/4 vs 分布式 5）？能坏几块（1→0、5→1、6→2）？

**题型④ SPOOLing 简答**：画"请求 → 输出井 → 输出进程 → 打印机"图 + 四组成 + 三作用；结合死锁预防（破坏互斥）或虚拟设备概念出题。

**题型⑤ 中断与系统调用辨析**：外中断/内中断归类表（§3.1）；"调用系统调用是否发生进程切换"——只是模式切换；"缺页中断属于哪种"——内中断且指令执行期间处理。

**题型⑥ 层次归属判断**：题干关键词对号入座四层软件（§2.1 套路）；设备分配时沿 SDT→DCT→COCT→CHCT 顺序找齐三表才算分配成功。

## 10. 易错点

- "引入缓冲只是为了解决 CPU 与设备速度不匹配"：不完整——还减中断频率、匹配数据粒度、提高并行性，四个理由写全。
- 单/双缓冲公式背反：单缓冲 **max(C,T)+M**、双缓冲 **max(C+M,T)**——错就错在 M 能否与 T 重叠（§5.1）。
- "双缓冲一定比单缓冲快一倍"：错，取决于参数——双缓冲把瓶颈从 max(C,T)+M 压到 max(C+M,T)，本题 110→100 只快 10μs。
- "SCAN 会饿死远端请求"：错，会饥饿的是 **SSTF**；SCAN 轮流扫到两端，不会饿。
- SCAN 与 LOOK 混用：SCAN 扫到**物理端点**，LOOK 到**最远请求**折返——题干说"电梯调度"时多数指 LOOK 行为，先看是否给端点。
- "C-SCAN 回程不算移动距离"：口径题——回程**不服务**，但**移动道数是否计入**以题干为准（本例计入）。
- "SPOOLing 后打印机变成了共享设备"：错，打印机**仍是独占设备**；是磁盘上的**井**在承担共享，SPOOLing 实现的是**虚拟设备**。
- SPOOLing 组成漏件：输入/输出**井**（磁盘）、输入/输出**缓冲区**（内存）、输入/输出**进程**、井管理程序——四件套缺一不可。
- "中断随时可嵌套"：错，多重中断需**更高优先级**且在**开中断**状态下才可打断。
- "缺页中断是外中断"：错，缺页是**内中断（异常）**；设备完成、时钟才是外中断。
- "调用系统调用就是进程切换"：错，只是**模式切换**（用户态↔核心态，同进程）；进程切换要换 PCB。
- "库函数都是系统调用的封装"：错，strlen 之类纯用户态实现；只有触内核服务的库函数（printf→write）才涉及系统调用。
- "RAID 0 也有容错"：错，RAID 0 只有条带化**无任何冗余**；要容错从 RAID 1 起步。
- RAID 容量与容错记反：RAID 1 利用率 **50%**；RAID 5 坏 **1** 块、RAID 6 坏 **2** 块。
- "磁盘调度算法优化的是传输时间"：错，优化**寻道时间**（占比最大）；旋转延迟靠扇区排列优化，不靠调度。
- "设备分配只需分配设备"：错，还要分配**控制器**和**通道**，三者齐才能启动 I/O。
