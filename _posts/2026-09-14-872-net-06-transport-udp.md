## 2. 知识框架

```
传输层地位：只存在于主机（端系统），路由器不实现传输层功能
  └─ 向上面的应用层提供通信服务：进程到进程（端到端）的逻辑通信
     └─ 网络层提供主机到主机的通信，传输层把通信延伸到进程

两个协议：
  UDP —— 无连接、不可靠、面向报文、支持一对多，8B 首部
  TCP —— 面向连接、可靠、面向字节流、仅一对一，20B 起首部

端口（协议端口号）：
  └─ 16 位，0~65535；0 保留不用
     ├─ 0~1023    熟知端口（服务器端固定分配）
     ├─ 1024~49151 登记端口（IANA 登记，多用于服务器软件）
     └─ 49152~65535 短暂端口（客户端临时使用，通信结束即回收）

复用与分用：
  发送方不同应用进程的数据 → 传输层统一封装 → 网络：复用
  接收方传输层按 (目的IP, 目的端口) 交付到正确进程：分用
```

- 端口号只是**传输层服务访问点 TSAP 的标识**，不是物理插口；一台主机唯一确定一条 TCP 连接靠**套接字 = (IP, 端口)** 二元组
- UDP 无连接、首部开销小，适合实时应用（音视频、DNS、SNMP）；TCP 可靠有序，适合文件传输、邮件、网页

## 3. 简答与名词解释

### 必背

- **传输层的地位与作用**：传输层为运行在**不同主机上的应用进程**之间提供**逻辑通信**服务。"逻辑"指看起来是端到端直连，实际中间经历了复杂的物理路径；网络层提供主机到主机的通信，传输层在其上把通信对象细化到进程。传输层功能只在**端系统**实现，路由器最高只到网络层。
- **端口号**：端口号是传输层用来**标识本计算机应用层中各应用进程**的 16 位标识符（0~65535），长度 2 字节。通信时用**目的端口**实现分用：接收方传输层根据报文携带的目的端口号把数据交付给对应进程。熟知端口举例：DNS 53、HTTP 80、FTP 21/20、TELNET 23、SMTP 25、SNMP 161。
- **复用与分用**：发送方传输层把多个应用进程的数据统一封装后交给网络层发送，称为**复用**；接收方传输层根据报文中的目的端口等信息把数据正确交付给相应的应用进程，称为**分用**。一句话：复用在发送方，分用在接收方，端口是分用的依据。
- **UDP（用户数据报协议）**：UDP 是无连接的传输层协议，尽最大努力交付，不提供可靠性保证。UDP **面向报文**：对应用层交下来的报文既不合并也不拆分，保留报文边界，一次交付一个完整的 UDP 报文。UDP 支持**一对一、一对多、多对一、多对多**的交互通信，首部仅 8 字节，开销小、时延低。
- **UDP 首部与伪首部**：UDP 首部共 8 字节，四个字段各 2 字节：**源端口、目的端口、长度（首部+数据的总长度）、校验和**。计算校验和时要临时加上 **12 字节伪首部**（源IP、目的IP、全零、协议字段17、UDP长度），伪首部既不向下传送也不算在 UDP 长度内，只用于校验，目的是让校验和同时覆盖 IP 层信息，防止交付错主机。

### 辨析

- **UDP 面向报文 vs TCP 面向字节流**：UDP 把应用层报文当作整体，加首部就交给 IP，报文太长 IP 层要分片；TCP 把应用层数据看作无结构的字节流，自己决定分段大小（MSS），接收方按序号重组。
- **传输层 vs 网络层**：网络层负责把分组从源主机送到目的主机（主机到主机），传输层负责把数据从源进程送到目的进程（进程到进程/端到端）；IP 首部没有端口字段，端口在传输层首部里。
- **熟知端口 vs 登记端口 vs 短暂端口**：0~1023 给标准服务器软件；1024~49151 给登记使用的软件；49152~65535 客户端随机取用作源端口。

### 了解

- UDP 校验和计算：首部与数据一起按 16 位字分组求和（奇数长度补一个零字节），超出 16 位的进位回卷（回加到最低位），最后取反码；结果为 0 时按全 1 写入
- 接收方校验：同样加上伪首部重新求和取反，结果非全 0 则丢弃该数据报
- IPv4 伪首部协议字段为 17（UDP）、6（TCP）；IPv6 中已不包含伪首部，由 IP 层自身校验

## 4. 易混对比表

| 对比项 | UDP | TCP |
|---|---|---|
| 连接 | 无连接 | 面向连接（三次握手建立） |
| 可靠性 | 尽最大努力交付，不可靠 | 可靠：确认、重传、有序 |
| 数据形态 | 面向报文，保留边界 | 面向字节流，无边界 |
| 通信方式 | 一对一、一对多、多对一、多对多 | 仅一对一 |
| 首部开销 | 8 字节 | 最少 20 字节 |
| 拥塞/流量控制 | 无 | 有 |
| 典型应用 | DNS(53)、DHCP(67/68)、SNMP(161)、RIP(520)、实时音视频 | HTTP(80)、FTP(21/20)、SMTP(25)、TELNET(23) |

| 端口类别 | 范围 | 用途 |
|---|---|---|
| 熟知端口 | 0~1023 | 标准服务器（DNS 53、HTTP 80、FTP 21 等） |
| 登记端口 | 1024~49151 | IANA 登记的服务器软件 |
| 短暂端口 | 49152~65535 | 客户端临时源端口 |

> 记法：熟知端口数值"越小越老"；TCP 表全是 TCP 应用（第四行 UDP 表专门放 DNS/DHCP/SNMP/RIP 这类短交互或广播场景）。

**UDP 首部字段速查（固定 8 B）**：

| 字段 | 长度 | 作用 |
|---|---|---|
| 源端口 | 16 位 | 发送方进程，可全 0 表示不需要回复 |
| 目的端口 | 16 位 | 接收方进程，分用的依据 |
| 长度 | 16 位 | 首部 + 数据总长度，最小 8 |
| 校验和 | 16 位 | 覆盖首部 + 数据 + 12 B 伪首部，置 0 表示不校验 |

## 5. 计算与方法

### UDP 校验和计算（选择题考过程，大题少）

**触发条件**：题目给出 UDP 报文各字段或二进制内容，要求算校验和或判断校验是否通过。

**步骤**：
1. 构造 12 字节伪首部：源 IP（4B）+ 目的 IP（4B）+ 全零（1B）+ 协议 17（1B）+ UDP 总长度（2B）
2. 伪首部 + UDP 首部 + 数据按 **16 位一组**切分；若总长为奇数字节，末尾补一个全零字节（仅计算用）
3. 各组按二进制**反码求和**：逐组相加，超出 16 位的进位回卷到最低位，直到无进位
4. 结果按位**取反码**，即得校验和，填入 UDP 首部校验和字段
5. 接收方验证：将伪首部+首部+数据（校验和字段一并）再求和，结果应为**全 1**，否则丢弃

**注意**：UDP 长度字段是"首部 8B + 数据"的总长，不含伪首部；伪首部字段全零那 1 字节在 IPv6 里换成流标号相关处理，但 872 范围只考 IPv4 伪首部。

### 场景选择题：选 TCP 还是 UDP

**判断顺序**：
1. 要不要可靠？要 → TCP（文件、邮件、网页、登录）
2. 要不要一对多/广播？要 → UDP（组播、RIP 周期广播）
3. 要不要低时延、容忍少量丢包？要 → UDP（实时音视频、DNS 查询、SNMP）
4. 都要（如 QUIC）超出考纲，按题干倾向作答

### 一道自编例题

主机 A 的 DNS 客户端向服务器 8.8.8.8:53 发出查询。A 进程使用短暂端口 51200。
- 该 UDP 数据报**源端口 = 51200**，**目的端口 = 53**
- 服务器回送时源端口 = 53，目的端口 = 51200
- 分用依据：**目的 IP + 目的端口**定位进程；一台主机上同一端口可被多个远端共用，但 (IP, 端口) 组合在 TCP 里唯一确定一条连接

## 6. 本节易错点

常见坑：
- "传输层在路由器上实现"：错，传输层功能只在主机（端系统）实现，路由器最高到网络层
- "端口号标识一台主机"：错，IP 标识主机，端口号标识主机内的应用进程；唯一确定一条 TCP 连接的是 (源IP, 源端口, 目的IP, 目的端口) 四元组
- "UDP 长度字段包含伪首部"：错，UDP 长度 = 首部 + 数据，伪首部只参与校验和计算，不计入长度也不被传输
- "UDP 是可靠协议因为 UDP 有校验和"：错，校验和只能检错不能纠错，检出错误直接丢弃，不重传，因此仍是不可靠交付
- "TCP 可以一对多"：错，TCP 只支持一对一；一对多用 UDP 或组播
- "客户端进程不能用熟知端口"：对，客户端通常用短暂端口，熟知端口留给服务器软件
- "复用发生在接收方"：反了，发送方复用、接收方分用
