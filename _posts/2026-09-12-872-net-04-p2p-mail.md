## 2. 知识框架

```
P2P（对等网络）—— 无中心服务器、节点互为client与server
  └─ 性能指标：最小分发时间 D_p2p = max{F/us, F/dmin, NF/(us+Σui)}（N 个对等体，服务器上行 us，对等体上行 ui、最小下载 dmin）
  └─ 组织方式：集中式目录（Napster）/ 全分布式洪泛（Gnutella）/ DHT（Kademlia）
  └─ BitTorrent：.torrent 元数据 + tracker + swarm（种群）+ chunk（块）+ rarest first（最稀少优先）+ tit-for-tat（针锋相对）+ choking（阻塞）

电子邮件系统
  └─ 协议：SMTP（发送/推送，TCP 25）、POP3（拉取，TCP 110）、IMAP（同步，TCP 143）
  └─ 格式：RFC 822 邮件格式 + MIME 多媒体扩展（Base64 编码）
  └─ 收发流程：MUA → MTA → MDA → MTA → MTA → MDA → MRA → MUA
```

- P2P 与 C/S 是互联网两大基本架构，C/S 是考试对比基准
- 邮件系统是"应用层协议组合"的最佳例子，综合了推送（SMTP）+ 拉取（POP3/IMAP）+ 多媒体（MIME）

## 3. 简答与名词解释

### 必背

- **P2P（对等网络）**：对等网络是一种分布式体系架构，每个节点（peer）既可以是客户端请求资源，也可以是服务器向其他节点提供资源，节点之间直接共享内容而不依赖中心服务器。
- **P2P 最小分发时间公式**：设服务器需分发文件 F（bit）给 N 个对等体，服务器上传速率 us，对等体 i 的下载速率 di、上传速率 ui。C/S 架构 `D_cs = max{NF/us, F/dmin}`（随 N 线性增长）；P2P 架构 `D_p2p = max{F/us, F/dmin, NF/(us+Σui)}`。三项含义：服务器至少发出 1 份完整副本、最慢对等体下完 1 份、全体对等体共需下载 N 份而由服务器与所有对等体一起上传。N 很大时第三项 → F/ū（ū 为平均上行），故 P2P 分发时间**有上界、趋于常数**，而 C/S 线性增长。
- **BitTorrent 机制**：BitTorrent 是典型的 P2P 文件共享协议。文件被划分为固定大小的 chunk（块），发布者生成含元数据的 .torrent 文件；加入同一 torrent 的对等体集合称 swarm（种群），各节点向 tracker 注册并获取其他对等体列表（后续 DHT 实现去中心化）。**对等体拿到任意一个 chunk 即可立即向其他对等体上传**——不需要事先拥有完整文件，也不需要经过中心服务器授权，对等体之间直接建立 TCP 连接交换数据，这是 P2P 区别于 C/S（服务器必须先有完整文件才能分发）的关键。下载时优先请求 rarest first（最稀少优先）——即先下载 swarm 中副本最少的块，使块分布更均匀、降低"灭绝"风险；对等体采用 tit-for-tat（针锋相对）策略，向给自己提供数据的对等体回馈数据，并定期测试连接速率替换低效对等体。
- **SMTP（简单邮件传输协议）**：SMTP 是用于发送电子邮件的应用层协议，采用推（push）模式，TCP 端口 25。SMTP 只能传送 7 位 ASCII 文本，后被 MIME 扩展支持多媒体。
- **POP3（邮件访问协议第3版）**：POP3 是用于从邮件服务器拉取邮件的协议，采用拉（pull）模式，TCP 端口 110。默认情况下邮件下载到本地并删除（也可选择不删除），不支持在服务器上建立文件夹。
- **IMAP（互联网邮件访问协议）**：IMAP 是比 POP3 更强大的邮件访问协议，邮件保留在服务器端允许多终端同步访问，支持在服务器上创建/管理文件夹，TCP 端口 143。
- **MIME（多用途互联网邮件扩展）**：MIME 扩展了 SMTP 的邮件格式，支持非 ASCII 文本、图像、音频、视频等多媒体。常用编码方式：Base64（将 3 字节映射为 4 个 ASCII 字符）、Quoted-Printable（可打印字符直接表示，非 ASCII 用"=HH"表示）。

![电子邮件系统的组成结构](/assets/img/csreview/dianziyoujian.png)
_三大组成：用户代理、邮件服务器、邮件协议；三段传输：发件人 UA --SMTP:25--> 发送方邮件服务器 --SMTP:25--> 接收方邮件服务器 --POP3:110/IMAP:143--> 收件人 UA_

一封邮件从发件人到收件人要经过三段独立的传输，使用协议和方向都不同，这是大题画流程图的标准结构。第一段：发件人在用户代理里编辑好邮件，用户代理作为 SMTP 客户，与发送方邮件服务器的 SMTP 服务器建立 TCP 25 端口连接，把邮件推送到自己所属的邮件服务器。第二段：发送方邮件服务器根据收件人地址中的域名，查 MX 记录找到接收方邮件服务器，此时它自己扮演 SMTP 客户，与对方的 SMTP 服务器再建立一条 TCP 25 连接进行服务器之间的投递——所以邮件服务器同时具有 SMTP 客户和 SMTP 服务器双重身份。第三段：邮件到达接收方邮件服务器后存入收件人信箱，收件人用用户代理通过 POP3（TCP 110，下载到本地）或 IMAP（TCP 143，留在服务器同步管理）把邮件拉取下来。注意方向：前两段都是"发"用 SMTP 推，第三段是"收"用 POP3/IMAP 拉，考试常考"哪几段用 SMTP、哪一段用 POP3/IMAP"。

### 辨析

- **SMTP vs POP3 vs IMAP**：SMTP 是"发邮件"（推给服务器），POP3/IMAP 是"收邮件"（从服务器拉）。POP3 简单、离线；IMAP 复杂、在线同步、多设备。SMTP 只支持 ASCII，MIME 解决多媒体；HTTP 也可作为邮件访问协议（MUA ↔ HTTP ↔ MSA），但考试重点是传统 SMTP+POP3/IMAP。
- **P2P 分发时间 vs C/S 分发时间**：C/S 架构下 N 个客户端都从服务器下载，D_cs = max{NF/us, F/dmin}（受服务器带宽限制，随 N 线性增长）；P2P 架构下服务器和所有对等体都参与分发，D_p2p = max{F/us, F/dmin, NF/(us+Σui)}，其中 NF/(us+Σui) 随 N 增大趋于常数，故总分发时间有上界。当 N 很大时，C/S 线性增长而 P2P 趋于饱和，P2P 显著更优。
- **IMAP 的"同步"含义**：IMAP 允许客户端在服务器上操作文件夹（创建、移动、标记已读），状态同步到服务器，其他终端访问同一账号时看到一致状态，区别于 POP3 的"本地独占"。

### 了解

- 邮件收发完整流程（872 口径，三组件三段传输）：发件人用户代理 --SMTP/TCP 25--> 发送方邮件服务器（服务器收、内部再以 SMTP 客户身份转发）--SMTP/TCP 25--> 接收方邮件服务器（存入收件人信箱）--POP3/TCP 110 或 IMAP/TCP 143--> 收件人用户代理。教材另用 MTA（邮件传输代理）、MDA（邮件投递代理）等名称指称服务器内的不同功能模块，本质就是上面两台邮件服务器承担的角色。
- BitTorrent 专有名词：choking（阻塞）——暂时拒绝向某对等体上传但继续下载，以优化上传带宽分配；unchoking（解除阻塞）——恢复对某对等体的上传；optimistic unchoking（乐观解除阻塞）——每隔一段时间随机解除对一个对等体的阻塞，新加入、尚无数据可回馈的对等体正是靠它拿到第一批块，同时用于测试新连接。
- SMTP 扩展 ESMTP（Extended SMTP）：支持 AUTH 认证、安全传输（STARTTLS）等扩展。
- POP3 常用命令（RFC 1939，分授权、事务、更新三阶段）：授权阶段 `USER <用户名>`、`PASS <口令>`；事务阶段 `STAT`（统计邮件数与总大小）、`LIST [n]`（列出邮件大小）、`RETR n`（取回第 n 封）、`DELE n`（标记删除）、`TOP n m`（取第 n 封前 m 行）、`UIDL`（唯一标识）、`RSET`（取消删除标记）、`NOOP`；`QUIT` 后进入更新阶段真正删除。特点是"下载并删除"、命令简单、服务器无跨会话状态。
- IMAP 常用命令（RFC 3501）：`LOGIN`（登录）、`SELECT`/`EXAMINE`（选中/只读打开邮箱）、`FETCH`（取邮件或属性）、`STORE`（改标志，如 \Seen 已读、\Deleted）、`SEARCH`（条件检索）、`LIST`（列文件夹）、`CREATE`/`DELETE`/`RENAME`（文件夹管理）、`APPEND`（把邮件存入服务器文件夹）、`CLOSE`、`LOGOUT`、`CAPABILITY`、`NOOP`。特点是邮件留服务器、状态（已读/文件夹）同步，支持多终端在线访问。

## 4. 易混对比表

| 维度 | C/S 架构 | P2P 架构 |
|---|---|---|
| 核心节点 | 中心服务器 | 所有节点对等 |
| 文件分发 | 服务器→N 个客户端 | 服务器+所有客户端→所有客户端 |
| 分发时间 | max{NF/us, F/dmin}（线性） | max{F/us, F/dmin, NF/(us+Σui)}（有上界，趋于常数） |
| 可扩展性 | 差（服务器瓶颈） | 好（节点越多性能越好） |
| 可靠性 | 依赖服务器 | 无单点故障 |

| 协议 | 模式 | 端口 | 功能 | 特点 |
|---|---|---|---|---|
| SMTP | 推 | 25 | 发邮件 | 只支持 ASCII，需 MIME 扩展 |
| POP3 | 拉 | 110 | 收邮件（离线） | 下载后默认删除，不支持文件夹 |
| IMAP | 拉 | 143 | 收邮件（在线） | 服务器同步、多设备、文件夹管理 |

## 5. 计算与方法

### P2P 分发时间计算题模板

**触发条件**：题目给出文件大小 F、服务器上行速率 us、N 个客户端、每个客户端上行速率 u，求分发时间。

**步骤**：
1. 写出 C/S 架构基准：`D_cs = max{NF/us, F/dmin}`（所有客户端从服务器下载）
2. 写出 P2P 架构公式：`D_p2p = max{F/us, F/dmin, NF/(us+Σui)}`
   - F/us：服务器至少发送一份完整副本的时间
   - F/dmin：下载最慢的对等体下完一份的时间（dmin = min{di}）
   - NF/(us+Σui)：N 份副本总量除以"服务器 + 全体对等体"的总上行带宽
3. 取三者最大值即为 P2P 最小分发时间
4. 比较 C/S 与 P2P：C/S 随 N 线性增长；P2P 的 NF/(us+Σui) 当 N 很大时趋于 F/ū，分发时间有上界、趋于常数

**自编例子**：文件 F = 100Mb，服务器上行 us = 10Mbps，每个客户端上行 u = 1Mbps、下载 d = 10Mbps，N = 10 个客户端。
- C/S：D = max{10 × 100 / 10, 100 / 10} = max{100, 10} = 100 秒
- P2P：D = max{100/10, 100/10, 10×100/(10+10×1)} = max{10, 10, 50} = 50 秒
（此例 P2P 快一倍；N 越大、对等体上行越高，P2P 优势越明显）

### 邮件收发流程画图模板

**自编例子**：Alice（@gmail.com）发邮件给 Bob（@163.com）。

流程即上文"电子邮件系统的组成结构"图：Alice 的用户代理 --SMTP--> gmail 发送方邮件服务器 --SMTP--> 163 接收方邮件服务器 --POP3/IMAP--> Bob 的用户代理，前两段都走 TCP 25，最后一段走 TCP 110/143。画图时要在每一段连线上标明协议与端口，并画出两台邮件服务器各自内部的双重角色（发送方服务器内有 SMTP 服务器和 SMTP 客户，接收方服务器内有 SMTP 服务器和 POP3 服务器）。

三个组件的职责：用户代理（MUA，如 Outlook、Foxmail、网页邮箱）负责编辑、发送、接收、显示邮件；邮件服务器负责存放用户邮件、发送和接收邮件，是整个系统的核心；邮件协议（SMTP、POP3、IMAP）规定邮件如何在各组件之间传递。

### BitTorrent rarest first 原理

**核心思想**：网络中副本最少的 chunk 最稀缺，应该优先下载，确保整个 Swarm（种子里所有对等体的集合）中块的分布更均匀，减少"灭绝"风险。每个对等体在本地维护一个 rarest 列表，按稀缺度排序发起请求。

```mermaid
flowchart TD
    A[文件划分为多个 chunk] --> B[计算每个 chunk 在 swarm 中的副本数]
    B --> C[优先请求副本数最少的 chunk——rarest first]
    C --> D[下载过程中持续交换数据]
    D --> E[tit-for-tat: 向给自己数据的对等体回馈数据]
    E --> F[定期测试连接速率，替换低效对等体]
```

## 6. 本节易错点

常见坑：
- "P2P 不需要服务器"：错，需要种子（.torrent）发布源和 tracker 服务器来协调对等体发现，BT 的 tracker 是中心化组件（后续 DHT 才是去中心化）
- "SMTP 可以拉取邮件"：错，SMTP 只负责发送（推），收邮件用 POP3/IMAP
- "POP3 和 IMAP 都删除服务器上的邮件"：错，POP3 默认删除但可设"保留"，IMAP 同步不删除
- "Base64 编码是为了加密"：错，Base64 是编码不是加密，目的是让二进制数据可以通过只支持 ASCII 的 SMTP 传输
- P2P 分发时间公式写错：漏掉 dmin 项、把 max 中三项相加、或把 NF/(us+Σui) 写成 NF/us / NF/u——正确为 `max{F/us, F/dmin, NF/(us+Σui)}`
- "对等体必须先有完整文件才能上传"：错——文件分块后，拿到任意一个 chunk 即可上传，这正是不需要 B 事先做任何准备的体现
- "一封邮件全程都用 SMTP"：错——发件人到发送方服务器、服务器之间这两段用 SMTP 推，收件人从自己服务器取信用 POP3/IMAP 拉
- "邮件服务器只充当 SMTP 服务器"：错——发送方邮件服务器向外投递时是 SMTP 客户，接收方邮件服务器还运行 POP3 服务器，是双重角色
