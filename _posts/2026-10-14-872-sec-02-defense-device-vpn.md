## 7. 防火墙技术

### 7.1 防火墙定义与基础

**定义**：一种部署于不同网络安全域之间的高级访问控制设备，它通过相关的安全策略控制（允许、拒绝、监视、记录）进出网络的访问行为。

- **部署位置**：网络边界。
- **基础功能**：过滤。

### 7.2 防火墙的检测与过滤技术（核心）

| 技术 | 检测机制 | 工作层 | 简要特点 |
|---|---|---|---|
| **包过滤**（Packet Filter） | 根据数据包头部 IP 地址、端口、协议类型等标志确定是否允许数据包通过 | 网络层 | 速度快、配置简单；**不检查数据区**，不建立连接状态表，应用层控制弱，易受 IP 欺骗 |
| **应用代理**（Application Proxy） | 通过编写不同的应用代理程序实现对应用层数据（数据负载）的检测和分析 | 应用层 | **不检查 IP、TCP 报头**；不建立连接状态表；网络层保护比较弱 |
| **状态检测**（Stateful Inspection） | 访问控制方式与包过滤同，但处理的对象不是单个数据包，而是整个连接，通过规则表和连接状态表综合判断是否允许数据包通过 | 2–4 层 | 检查**整个连接**；不检查数据区；建立连接状态表；前后报文相关；应用层控制很弱；性能高，支持大量应用 |
| **完全内容检测**（Complete Content Inspection） | 全部数据（报头至应用层内容）不仅分析数据包头信息、状态信息，而且对应用层协议还进行还原和内容分析，有效防范混合型安全威胁 | 2–7 层 | 最全面，能还原协议并分析内容；网络层保护强；应用层保护强；会话保护很强；上下文相关；前后报文有联系 |

### 7.3 防火墙的发展、体系结构与局限

#### 7.3.1 发展五代

| 代 | 时间 | 形态 |
|---|---|---|
| 第一代 | 20 世纪 80 年代 | 依附于路由器的包过滤防火墙 |
| 第二代 | 1989 年 | 贝尔实验室电路层防火墙 |
| 第三代 | 20 世纪 90 年代初 | 应用层 / 代理防火墙 |
| 第四代 | 1992 年前后 | 动态包过滤 / 状态检测；1994 年 Check Point 商业化 |
| 第五代 | 1998 年 | NAI 自适应代理（Gauntlet Firewall for NT） |

#### 7.3.2 四种体系结构

| 结构 | 组成 | 特点 / 弱点 |
|---|---|---|
| **过滤路由器** | 单个路由器做包过滤 | 被攻陷难发现、不能识别不同用户、日志能力弱 |
| **双宿主主机** | 两块网卡的堡垒主机 | 内外网之间唯一节点；被入侵则内网失守 |
| **被屏蔽主机** | 屏蔽路由器 + 堡垒主机 | 两道屏障；堡垒主机是重点保护对象 |
| **被屏蔽子网（DMZ）** | 周边网络、外部路由器、内部路由器、堡垒主机 | 双层防护；成本高、配置复杂。内部路由器只允许堡垒主机访问内网，外部路由器阻挡外部直接访问，两道规则配合，避免单侧失效 |

#### 7.3.3 DMZ 与安全域

- 安全域划分：内部可信区、外部不可信区、DMZ（半可信区）。
- 防火墙在逻辑上是两个安全域之间通信流的**唯一通道**（不考虑移动介质、旁路等）。
- 规则表通常包含：协议、源地址 / 端口、目的地址 / 端口、动作（Permit / Deny）。

#### 7.3.4 WAF（Web 应用防火墙）

- **部署**：串行部署在 Web 服务器前，常用反向代理 / 基于会话的双向代理；生产环境要考虑 HA 与 Bypass。
- **防护**：SQL 注入、XML 注入、XSS、应用层 DDoS / CC、恶意爬虫等。
- **检测**：
  - 特征识别：Shellcode、SQL 注入特征串（如 `1=1`）等。
  - 算法识别：KNN、贝叶斯分类器、PCA、LDA、NMF、GMM 等。
- **原理**：解析 HTTP 请求/响应，按规则或模型判定并阻断。

#### 7.3.5 防火墙的局限性

- **防外不防内**：内部攻击、内网横向移动管不住。
- **难管理配置**：规则复杂、易出错，策略之间可能冲突。
- **只做粗粒度访问控制**：主要是网络 / 会话 / 服务级，难到客体级。
- **不能防绕过防火墙的攻击**：移动介质、旁路、加密隧道等。
- **难以防范内部攻击**，也不能替代主机、应用、数据层安全。

### 7.4 三种典型防火墙的特点（简答题）

#### 7.4.1 包过滤防火墙

**优点**

- 只对数据包的 IP 地址、TCP/UDP 协议和端口进行分析，规则简单，处理速度较快
- 易于配置
- **对用户透明**——用户访问时不需要提供额外的密码或使用特殊的命令

**缺点**

- 检查和过滤器只在网络层——不能识别应用层协议或维持连接状态
- 安全性薄弱——不能防止 IP 欺骗等
- 静态策略可能成为漏洞

#### 7.4.2 应用代理或网关防火墙特点（简答题）

**优点**

- 可以检查应用层、传输层和网络层的协议特征，对数据包的检测能力比较强
- 提供良好的安全性——所有数据的有效负载都在应用层进行检查

**缺点**

- 支持的应用数量有限，无法很好的支持新的应用、技术和协议
- 对用户不透明
- 性能表现欠佳

> 但是，自适应代理技术的出现让应用代理防火墙技术出现了新的转机，它结合了代理防火墙的安全性和包过滤防火墙的高速度等优点，在不损失安全性的基础上大大提高了代理防火墙的性能。

#### 7.4.3 状态检测防火墙

- 性能大大提高
- 支持大量应用
- 在内核级实现检测过滤
- 在所有接口对进/出的数据包进行状态检查
- 支持应用层协议检查
- 在动态状态表中存储连接状态
- 检查对外的连接并预先计算出将返回的连接

**"策略明明拒绝，连接却建立了"的机制解释（场景化理解）**

状态检测的核心是维护一张**动态连接状态表**（会话五元组 + 状态标志），表项在连接发起时创建、结束时删除：

| 步骤 | 发生的事 | 状态表如何处理 |
|---|---|---|
| 1 | 内网主机向外发起访问，出站 **SYN** 放行 | 新建表项：内网 IP:端口 → 外网 IP:端口，状态置为"等待 SYN-ACK" |
| 2 | 外网回送 **SYN-ACK** | 查表命中"等待 SYN-ACK"，判定为**对该连接的合法响应**，放行并推进状态 |
| 3 | 内网主机回 **ACK**，三次握手完成 | 表项转为"已建立"，此后双向报文均按该表项放行 |
| 4 | 会话结束 | 表项超时或收到 FIN/RST 后删除 |

由此可以解释两类现象：

- **默认策略是拒绝，最终连接却建立成功了**——"拒绝"针对的是**查不到表项的报文**。由于出站 SYN 先于入站响应到达并建好了表项，后续报文全部命中表项，连接得以完整建立。
- **已禁止未经请求的访问，却仍收到了（并放行了）TCP 的确认报文**——该 ACK/SYN-ACK 能在状态表中匹配到此前记录的**出站请求**，因此被判定为"**已获授权的会话数据**"，而不是"未经请求的访问"。

**为什么无状态包过滤做不到**：包过滤只能逐个检查报文头的五元组，无法区分"**未经请求的 SYN-ACK**"和"**对内部请求的正常响应**"——这两种报文在头部字段上可以完全相同。判断"该不该放行"需要连接的**上下文**，而上下文只有状态检测才掌握。

> 题目里只要出现"策略禁止却仍被放行""收到了不该收到的响应 / 确认报文"这类描述，答案基本就是**状态检测（会话跟踪）机制**。

### 7.5 防火墙其他重要功能详解

![防火墙需具备五个基本功能](/assets/img/csreview/fw-five-functions.png)

![防火墙的其它功能：控制信息流向、隐藏内部结构、流量日志、NAT、隔离网段、集中安全管理、VPN](/assets/img/csreview/fw-other-functions.png)

| 功能 | 做法 | 好处/作用 |
|---|---|---|
| **地址转换**（NAT） | 将内部网络的私有 IP 地址转换为对外的公有 IP 地址 | 隐藏内部网络结构，实现 IP 地址复用，解决公网地址不足问题 |
| **地址/端口映射**（MAP） | 将公网 IP 的特定端口映射到内部服务器的私有 IP 和端口 | 让使用私有地址的服务器能对外提供服务，同时隐藏内部网络结构 |
| **IP 与 MAC 地址绑定** | 绑定 IP 与 MAC 的对应关系 | 防止 IP 地址欺骗和滥用。例如，绑定后，防火墙允许 Host A 上网，但会阻止 Host B 假冒 Host A 的 IP 地址上网 |
| **与 IDS 的安全联动**（重点） | 防火墙可以与入侵检测系统（IDS）联动。当 IDS 识别出攻击时，可通知防火墙采取措施 | 如阻断连接 |

### 7.6 防火墙的工作接入方式

#### 7.6.1 路由接入方式

防火墙作为一个**简单的路由器**（同时是网关），需要配置 IP 地址，连接不同网段。接在一个普通路由器后面。

![防火墙路由接入方式：防火墙相当于一个简单的路由器，提供简单的路由功能](/assets/img/csreview/fw-route-mode.png)

- ✅ **特点 1**：支持多网段隔离（不同接口配置不同网段，实现 VLAN 间路由和访问控制）
- ✅ **特点 2**：路由策略灵活，可基于目标网段、协议、端口做精细转发

#### 7.6.2 透明接入方式

防火墙相当于**网桥**，不改变原网络拓扑和主机配置，接口无需 IP 地址。（红字是特点）

![防火墙透明接入模式：防火墙相当于网桥，原网络结构没有改变，透明模式下不需要配置 IP 地址](/assets/img/csreview/fw-transparent-mode.png)

![防火墙的透明接入工作模式：内网 192.168.1.0/24 经路由器 192.168.1.254/24 连到外部网络](/assets/img/csreview/fw-transparent-topology.png)

#### 7.6.3 混合接入方式

同时支持以上两种模式，根据网络需求灵活部署。

- 工作于**透明接入模式**的防火墙可以实现透明接入。
- 工作于**路由模式**的防火墙可以实现不同网段的连接。
- **路由接入模式的优点和透明接入模式的优点是不能同时并存的。**
- 大多数的防火墙一般同时保留了透明接入模式和路由接入模式。
- 根据用户网络情况及用户需求，在使用时由用户进行选择。

![防火墙的混合接入工作模式：不同子网做路由通信、同一网段地址走透明模式](/assets/img/csreview/fw-hybrid-mode.jpeg)

### 7.7 衡量防火墙性能的五大指标

| 指标 | 含义 |
|---|---|
| **吞吐量** | 在不丢包的情况下，设备能够转发的最大数据速率。吞吐量小会成为网络瓶颈 |
| **时延** | 数据包第一个比特进入设备到最后一个比特输出设备的时间间隔。时延越小性能越好 |
| **丢包率** | 在连续负载下，设备应转发却未转发的数据包百分比。丢包率越小性能越好 |
| **背靠背** | 从空闲状态开始，以达到传输介质最小合法间隔极限的传输速率发送相当数量的固定长度的帧，当出现第一个帧丢失时，发送的帧数。体现防火墙对突发数据流的处理能力，主要考察设备缓冲容量 |
| **并发连接数** | 数据包穿越防火墙同时建立的的最大连接数。主要用来测试防火墙建立和维持 TCP 连接的性能。并发连接数越大，处理能力越强 |

**背靠背补充说明**：通俗来说，"背靠背"测试就像是你尽可能快地通过网络发送数据到阈值，直到网络开始丢包，然后你看看在丢包发生之前你成功发送了多少数据。这有助于了解你的网络在高负载下的表现如何。衡量标准：背对背包主要是指防火墙**缓冲容量的大小**；网络上经常有一些应用会产生大量的突发数据包（例如 NFS、备份、路由更新等），而且这样的数据包的丢失可能会产生更多的数据包的丢失，强大缓冲能力可以减小这种突发对网络造成的影响。

#### 7.7.1 防火墙的可靠性与高可用

- **单点失效**：单台设备故障即导致业务中断。
- **双机热备（Active-Standby）**：两台同型号防火墙经心跳链路同步会话表、配置、状态表；主机故障时备机秒级接管，业务 IP 不变（使用 VRRP / 虚拟 MAC 时 MAC 也不变）。
- **集群（Active-Active）**：多台设备负载分担，提高吞吐量与可用性。
- **五性对应**：高可用、高可靠、高性能、高扩展、高并发；双机热备主要满足**高可用**，集群侧重**高性能 / 高扩展**。

### 7.8 防火墙的"胖瘦"之争

| | "胖"防火墙 | "瘦"防火墙 |
|---|---|---|
| 定义 | 功能大而全的防火墙，集成访问控制、病毒防护、入侵检测等多种安全功能。它力图将尽可能多的安全功能包含在内，从而成为用户网络的一个安全平台 | 指功能少而精的防火墙，专注于核心的访问控制功能，通过与其他安全产品联动形成解决方案 |
| 优势 | 功能全、控制力度细，协作能力强，降低采购和管理成本 | 性能高、专业性强、配置简单 |
| 不足 | 性能可能降低，配置复杂，稳定性不强（系统越大 bug 越多），自身安全性相对较弱 | 功能单一，整体采购成本可能较高 |

### 7.9 防火墙与访问控制：能控制什么、控制不到什么

**【答题骨架】** 防火墙是**边界上的集中式访问控制设备**，它能管到哪一层取决于它**工作在第几层**；凡是"信息根本不在网络流量里"的控制，防火墙**加插件、加功能也做不到**。

**① 能实现的访问控制（按工作层分级）**

| 层级 | 手段 | 能控制到的"客体"粒度 |
|---|---|---|
| 网络级 | 包过滤 | 五元组（源/目的 IP、协议、端口） |
| 会话级 | 状态检测 | 连接 / 会话（凭连接状态表判断） |
| 应用级 | 应用代理、完全内容检测 | 服务与协议内容 |
| 上下文级 | 状态检测的扩展 | 时间、用户身份、上下文的组合 |

对应到访问控制模型（都是"集中式、粗粒度"版本）：**DAC** 视角 = 管理员统一策略、主体不能转移权限；**MAC** 视角 = 网段级安全标签控制；**RBAC** = 按用户/角色组授权；**上下文访问控制** = 状态检测的本质。

**② 做不到的（原生不可实现，加插件/加功能也不可实现）**

| 做不到的控制 | 为什么做不到 |
|---|---|
| **客体级（对象级）细粒度访问控制**——文件、目录、数据库字段的读写限制 | 这些信息**根本不在网络流量里**，必须在客体所在的操作系统/数据库内部实现（ACL、SELinux 标签、数据库权限） |
| **真 DAC 的"属主自主授权、权限可传递"** | 网关策略由管理员集中制定，**客体属主无法在防火墙上自主授权**（见上篇 §6.5） |
| **BLP / Biba 的信息流无环控制** | 密级流发生在**进程与客体之间**（读哪个文件、密级几级），边界设备判不出"这次读写作用在哪个客体" |
| **内部信息流与内部威胁** | 防火墙管"进出边界"，流量进入内网后主机之间的访问它管不了（除非部署内部/分布式防火墙） |
| **加密流量的应用层控制** | 对 TLS 加密报文无法做内容级判定（见 §7.2"不检查数据区"） |

**一句话记法**：防火墙能管**"谁能从哪儿连到哪儿"**（网络/会话/服务级），管不了**"他能碰哪个对象、能改哪几个字段"**——后者属于客体所在系统的权限体系；最后的兜底是**端到端加密**。

## 8. 入侵检测技术

### 8.1 核心概念

| 概念 | 定义 |
|---|---|
| **入侵** | 指在非法或未经授权的情况下，试图存取或处理系统或网络中的信息，或破坏系统/网络正常运行，致使机密性、完整性和可用性受到破坏的**故意行为** |
| **入侵检测** | 对入侵行为的发觉。通过从计算机系统或网络的关键点采集信息并进行分析，从中发现违反安全策略的行为和被攻击的迹象 |
| **入侵检测系统** | 实现入侵检测功能的软件和硬件的集合 |

### 8.2 入侵检测模型

| 模型 | 说明 |
|---|---|
| **通用入侵检测模型**（也称为 Denning 模型） | 核心思想是通过检查系统的审计记录，从中识别异常使用系统的入侵行为。它是一个**基于规则的模式匹配系统** |
| **层次化入侵检测模型** | 将入侵检测过程分为六个抽象层次：数据层、事件层、主体层、上下文层、威胁层和安全状态层，通过数据关联简化对跨主机入侵行为的识别 |
| **管理式入侵检测模型**（即 SNMP-IDSM 模型） | 重点解决多个 IDS 之间的协同工作问题 |

#### 8.2.1 工作原理（重点掌握）

- 假设 IDS A 监视主机 A，IDS B 监视主机 B。
- 当 IDS A 检测到一个来自主机 B 的攻击企图时，它会使用 **MIB（管理信息库）脚本**向 IDS B 发送请求。
- IDS B 收到请求后，执行脚本（功能类似于 netstat、lsof 等命令），收集主机 B 的网络和用户活动信息。
- IDS B 将这些信息反馈给 IDS A。
- IDS A 根据收到的信息进行进一步的入侵分析验证。

**目的**：以 SNMP 为公共语言实现 IDS 间的信息交换和协同检测。

### 8.3 入侵检测系统的分类（三维）

#### 8.3.1 按分析技术：异常检测 vs 特征检测

| | 异常检测 | 特征检测 |
|---|---|---|
| **是什么**（重点） | 首先建立用户或系统的**正常行为模型**（知识库），然后检测实际活动是否偏离该正常模型。假设"所有入侵行为都是异常的"。也称为**基于行为的检测** | 建立**已知入侵行为的模型**（攻击特征库），判别当前活动是否符合已知的攻击模式。假设可以识别所有攻击特征。也称为**误用检测** |
| **优点** | 可能检测未知攻击，具有自适应性 | 准确率高，算法简单 |
| **缺点** | 正常模型难以建立，明确划分正常与异常较难 | 无法检测新的入侵，特征库需不断更新 |

#### 8.3.2 按数据来源：NIDS vs HIDS

| 维度 | NIDS（网络 IDS） | HIDS（主机 IDS） |
|---|---|---|
| 数据来源 | 网络流量；旁路镜像抓包 | 主机内部：系统日志、文件、进程、系统调用 |
| 部署位置 | 网络边界或核心交换机旁路 | 装在被监控主机上的 Agent |
| 检测范围 | 整个网段通信 | 单台主机内部活动 |
| 优势 | 监视整个网段、实时性好、部署集中 | 不依赖网络拓扑、不受交换与加密流量影响、能定位到具体主机 / 进程、可监测应用程序异常行为 |
| 劣势 | 看不到加密流量、看不到主机内部行为 | 每台主机都要安装与管理、开销大、实时性相对弱 |
| 典型场景 | 边界、DMZ、核心网 | 关键服务器、数据库、主机审计 |

#### 8.3.3 按响应方式：被动响应 vs 主动响应

- **被动响应**：只报警、记录，不直接阻断；传统 IDS 属于这一类。
- **主动响应**：联动防火墙 / IPS 阻断连接、终止会话、自动取证；IPS 可视为 IDS 主动响应的产品化形态。

#### 8.3.4 HIDS 的检测对象、方法与部署

**三大检测对象**

| 对象 | 重点看什么 |
|---|---|
| 系统日志 | 反复登录失败、越权访问、非正常登录 |
| 文件系统 | 受限目录 / 文件被非正常创建、修改、删除 |
| 进程记录 | 进程被异常中止或行为异常 |

HIDS 同样分异常检测与误用检测，只是数据源从网络流量换成了主机审计数据。

- **异常检测**：基于系统调用跟踪建立正常行为数据库，偏离即报警；能发现未知行为，但正常模型难建、误报较高。
- **误用检测**：预定义入侵模式 / 签名匹配；能发现已知攻击，但漏报率高、难防零日。

**部署方式**

- **单机部署**：每台主机单独装 Agent，监控深入，但管理成本高。
- **分布式部署**：中央管理端 + 多主机 Agent，全面监控，扩展性与容错性更好。

> 一句话：NIDS 看“网”，HIDS 看“机”；异常检测看“偏不偏”，特征检测看“像不像”。

### 8.4 IDS 的检测指标

- **漏报率**：指攻击事件没有被 IDS 检测到。
- **误报率**：指将正常事件识别为攻击并报警。
- **关系**：误报率与检出率通常成正比例关系。

![IDS 能够解决的安全问题：总体威胁趋势分析、流量及连接分析、安全事件分析](/assets/img/csreview/ids-security-problems.png)

**IDS 能解决的安全问题**：① 总体威胁趋势分析（重点）；② 流量及连接分析（重点）；③ 安全事件分析（重点）；④ 对蠕虫类攻击爆发进行预警。

> IDS 从总体和趋势上的分析能力是其他安全设备难以实现的；通过基于流量、统计等方面的分析，IDS 理论上可防御未知攻击（严格说 IDS 主要负责发现 / 预警，不负责阻断）。

### 8.5 为什么需要 IDS 与深度防御

**深度防御三步**：预防入侵 → 检测入侵 → 对入侵做出响应。

| 步骤 | 内容 |
|---|---|
| **预防入侵** | 网络 / 操作系统 / 应用的设计与实现缺陷、隧道技术、内网攻击等，单靠预防挡不住 |
| **检测入侵** | 实时分析大量审计数据，发现违反安全策略的行为和被攻击的迹象 |
| **响应入侵** | 实时响应、减小影响、尽快恢复服务 |

**为什么需要 IDS**：边界防火墙主要挡外部入侵、自身有弱点、对 APT 保护很弱；合法用户仍可非法使用系统；防火墙只能拒绝非法连接，却对攻击行为一无所知。IDS 补的就是“看见”的能力。

**案例：Google Aurora（极光）攻击**：向员工发恶意链接 → 下载木马成肉鸡 → 内网渗透 + 暴力破解获取管理员权限 → 长期远程控制。它说明单点边界防护不够，需要关联分析、威胁溯源、攻击链挖掘。

**分析技术与引擎**

- 分析技术：统计分析、状态转移分析、关联分析。
- 引擎设计：模式匹配（从包头开始逐字节比较）、协议分析。

**层次化模型六层内涵**：数据层 → 事件层 → 主体层 → 上下文层 → 威胁层 → 安全状态层；安全状态层用 1–100 的数值表示，数字越大越不安全。

## 9. 其他网络安全技术及设备

### 9.1 入侵防御系统（IPS）

**长定义**：IPS 是一种集入侵检测和防御于一体的安全产品，它不但能检测入侵的发生，而且能通过一定的响应方式，实时地中止入侵行为的发生和发展，实时地保护信息系统不受实质性的攻击。IPS 使得 IDS 和防火墙走向统一。

**简单理解**：可认为 IPS 就是**防火墙加上入侵检测系统**。

**简单定义**：能够实时检测并主动阻断入侵行为的系统。

#### 9.1.1 与 IDS 的区别（重点）

| 维度 | IPS | IDS |
|---|---|---|
| 部署方式 | **在线**，流量必须通过 IPS | **旁路**，通过镜像获得数据 |
| 实时性 | 实时，其时延必须满足业务要求 | 准实时，可接受秒级时延 |
| 影响 | 立刻影响网络报文 | 对网络及业务无直接影响 |
| 作用范围 | 作用范围有限制 | 监控范围广 |
| 设计出发点 | 无误报、满足峰值流量和时延要求、不能影响业务系统可用性 | 无漏报、满足平均流量，可接受秒级时延、只需关注自身功能实现 |

![部署方式与设计出发点对比：IPS 与 IDS](/assets/img/csreview/ips-vs-ids.png)

- **IDS**：旁路监听，主要功能是检测和报警，属于**事后响应**。
- **IPS**：部署在网络边界（在防火墙后或者相同位置），串联部署，具备实时阻断能力，属于**事中防御**。

#### 9.1.2 能解决的安全问题

![IPS 能够解决的安全问题：阻拦已知攻击、为已知漏洞提供虚拟补丁、速率或流量控制、行为管理](/assets/img/csreview/ips-security-problems.png)

**IPS 能解决的安全问题**：① 阻拦已知攻击（重点）；② 为已知漏洞提供虚拟补丁（重点）；③ 速率或流量控制；④ 行为管理。

> IPS 可提供有效的、防火墙无法提供的应用层安全防护；但为了避免误报，IPS 对未知攻击的防御能力几乎没有。

> IDS 侧的“能解决的安全问题”见 §8.4。

### 9.2 安全隔离与信息交换系统（网闸）

**定义**：网闸是在两个不同安全域之间，通过特殊的通讯协议转换的手段，以信息摆渡的方式实现数据交换，且只有被系统明确要求传输的信息才可以通过。其信息流一般为通用应用服务。

**核心思想**：在信息摆渡过程中内外网（上下游）**从未发生物理连接**，从而彻底阻断网络层攻击。

**作用**：网闸主要用于在两个物理隔离的网络之间进行安全的数据交换。

**物理隔离带来的问题与解决**：物理隔离保证了安全，但阻碍了必要的数据交换。网闸通过其特殊组成解决此矛盾。

**安全隔离网闸的组成**：通常由内、外网处理单元和专用的隔离交换硬件（如电子开关、固态介质）组成，数据通过"摆渡"方式单向流动。

> 概念、原理 + 画出网闸的三个组成部分，再简单说明原理 + 关键字"**私有协议**""**切断**"。

![安全隔离网闸的三个组成部分：外网主机系统、内网主机系统、外网隔离交换模块、内网隔离交换模块、隔离交换矩阵](/assets/img/csreview/gap-composition.png)

![网闸隔离系统：内外网单元经协议剥离后用私有协议通过专用隔离硬件交换](/assets/img/csreview/gap-private-protocol.png)

> （要画图，关注安全隔离网闸的组成图里的小字，"私有协议"！考题类似于"画出三个组成部分并说明原理"。）

#### 9.2.1 网闸数据交换过程

![网闸数据交换过程：非可信网络经外网隔离交换模块（Leadsec ASIC）摆渡到可信网络](/assets/img/csreview/gap-data-exchange.png)

| 组成 | 功能 | 工作流程 |
|---|---|---|
| **外网处理单元** | 面向外部非可信网络。负责接收来自外网的用户或应用请求 | ① **协议终止与剥离**：完整终止外网的网络连接（如 TCP/IP），将应用层数据（如 HTTP 内容、数据库查询语句、文件块）从网络数据包中"剥离"出来<br>② **深度内容检查**：对剥离出的应用数据进行严格的安全检查，包括病毒木马查杀、恶意代码过滤、内容合规性验证、格式有效性判断等<br>③ **数据格式化**：将"净化"后的数据转换为专有的、简化的格式（通常只是一串待交换的原始数据块），准备交由隔离硬件摆渡 |
| **内网处理单元** | 面向内部可信网络。负责将数据安全地送达内网目标服务器 | ① **数据接收与重组**：从隔离交换硬件接收已摆渡过来的专有格式数据<br>② **协议重建与发起**：以发起方的身份，在内网侧重新建立全新的网络连接，将应用数据重新封装成符合内网标准协议（如 TCP/IP）的数据包<br>③ **数据送达**：将重建的数据包发送给内网指定的目标服务器。对于内网向外网发送数据，流程则相反 |
| **专用隔离交换硬件** | 实现物理隔离的核心部件，是内外网处理单元之间的"空气间隙"和"摆渡船"。**在任何时刻，该硬件只与一侧的处理单元连接，与另一侧完全物理断开** | 常见实现方式：**电子开关阵**（通过高速电子开关，在电路层面实现快速切换连接）；**固态存储介质（如 RAM）**（数据先写入一个与一端相连的存储区，然后断开连接，切换电路，再让另一端来读取，存储区在每次读写后都会被擦除） |

**专用隔离交换硬件工作流程（"摆渡"原理）**

1. **连接外网单元**：隔离硬件首先物理连接到外网处理单元，接收其送出的"净化"数据，完成后立即物理断开与外网的连接。
2. **瞬时无连接状态**：此时，隔离硬件与内外网均无连接，处于"孤岛"状态。
3. **连接内网单元**：隔离硬件转而物理连接到内网处理单元，将存储的数据推送给它，完成后再次断开与内网的连接。

> 此过程单向进行，一次摆渡只完成一个方向的数据传输。反向传输需要发起另一次独立的摆渡周期。

#### 9.2.2 网闸与防火墙的区别（重点）

| | 防火墙 | 网闸 |
|---|---|---|
| 隔离方式 | 基于**逻辑隔离**（规则过滤） | 基于**物理隔离** |
| 网络连接 | 存在网络连接 | 无网络连接 |
| 风险 | 可能遭受协议攻击 | 从物理上切断 TCP/IP 等协议，安全性更高 |

#### 9.2.3 网闸的使用环境（简答 / 画图）

**四种典型环境**

1. 不同涉密网络之间。
2. 同一涉密网络的不同安全域之间。
3. 与 Internet 物理隔离的涉密内部网 ↔ Internet 之间。
4. 未与涉密网络连接的网络 ↔ Internet 之间。

**产品定位对比**

- 防火墙：在保障互联互通的前提下尽可能安全。
- 网闸：在保证必须安全的前提下尽可能互联互通；通过在不可信网络一侧“牺牲自己”来保护可信网络。

**政策依据**

- 中办发〔2002〕17 号文：政务内网与政务外网物理隔离，政务外网与互联网逻辑隔离。
- 国家保密局《计算机信息系统国际联网保密管理规定》第六条：涉密系统必须物理隔离。

**单向光闸（数据二极管）**

只允许数据单向流动、没有回传信道，从物理上消除数据回传泄露路径；与双向摆渡的网闸区分开。

### 9.3 统一威胁管理系统（UTM）

UTM 由 IDC 于 2004 年提出。**定义**：把防病毒、防火墙、入侵检测等概念融合为“统一威胁管理”新类别，是把多种安全特性集成到一个硬件平台上的标准统一安全平台。

**九大功能**：防火墙、NAT、VPN、防病毒、防垃圾邮件、URL 过滤、行为审计、流量控制、漏洞防护。

**两个考点补充**

- 行为审计需配合 UTM Manager；公安部第 82 号令《互联网安全保护技术措施规定》要求记录留存技术措施至少保存 60 天记录备份。
- 与 IPS 的差距：UTM 的攻击特征库可能只有 1000 条，同性能 IPS 可能有 10000 条，课件比喻为“小学生和大学生”。

### 9.4 安全管理平台（SOC）

**来源**：SOC 源自 NOC（网络运行中心），从“看网络”扩展到“看安全”。

**现实痛点**

- 绝大多数设备不是免维护的；各设备日志格式不同，海量事件无从处理。
- 系统管理员：不懂应用日志。
- 管理者：看不到全局报表，不知是否遵循标准、投入回报如何。
- 网络管理员：海量事件看不完，不知是否有人处理过。

**SOC 七步日志处理过程**

1. 资产分类
2. 收集日志（No agent）
3. 格式化日志
4. 过滤日志（按事件来源）
5. 日志归类
6. 日志关联
7. 日志展现

**格式化后的字段**：设备、设备地址、事件类型、源地地址、目标地址、端口。

**关联示例**：100 条 TIF 在 10 秒内收到（源 1.1.1.1、目标 2.2.2.1~2.2.2.100、端口 100、Firewall Alert-100）→ 合并为 1 条，事件类型设为 Horizontal Port Scan（水平端口扫描）。

**MCE 规则示例**：SingleSuppressWithThreshold；模式 REGEXP；窗口 10；阈值 100。

> SOC 的价值：把“海量日志”变成“可处置的安全事件”，再做关联分析与全局报表。

### 9.5 网络准入控制

**定义**：使用网络准入安全策略，确保进入网络的设备符合策略。

**功能需求与流程**

![网络准入控制系统的功能需求：身份鉴别、安全认证、动态授权三道关，非法用户拒绝入网、不合格进入隔离区](/assets/img/csreview/nac-flow.png)

```text
用户接入请求 → 身份鉴别 → 合法用户进行安全认证（非法用户拒绝入网）→ 认证不合格则进入隔离区；认证合格后对用户进行动态授权
```

> **演进关系**：网络准入控制（NAC）常被视为**零信任**（Zero Trust）的前身与特例——NAC 只解决"能否进入网络"这一次鉴权，零信任把它泛化为"每一个访问请求都重新鉴权"。三条核心原则见[网络安全（上）](/posts/872-sec-01-theory-model-auth-ac/) §6.8（该系列课件未设零信任专章，按了解层级记）。

## 10. 虚拟专用网（VPN）技术

### 10.1 VPN 基础概念与优点

**概念（名词解释）**：虚拟专用网（VPN）是一种通过对网络数据封包和加密传输，在公网上传输私有数据、达到私有网络安全级别，从而利用公网构筑企业专用网的组网技术。它兼备公众网的便捷和专用网的安全。

**优点**

- **降低成本**：利用现有互联网，节省专线费用。
- **易于扩展**：网络扩容方便。
- 可随意与合作伙伴联网。
- 完全控制主动权。

### 10.2 IPSec 框架

IPSec 是一个协议框架，其安全联盟（SA）规定了通信双方需约定的要素：

1. **加密算法**：如 DES、3DES、AES。
2. **验证（认证）算法**：如 MD5、SHA-1。
3. **安全协议**：AH 或 ESP。
4. **模式**：传输模式或隧道模式。
5. **密钥有效期**：如 3600 秒。

![IPSec 框架：加密、验证、安全协议、模式、密钥有效期等要素由通信双方自行协商](/assets/img/csreview/ipsec-framework.png)

![IPSec 对等体之间对安全联盟 SA 的约定：安全协议、加密认证算法、封装模式](/assets/img/csreview/ipsec-sa.png)

![IPSec 协议体系：IP 安全结构下分 ESP 协议、密钥管理协议、AH 协议，三者均由加密算法、认证算法与解释域 DOI 支撑](/assets/img/csreview/ipsec-protocol-system.png)

IPSec 的安全协议由三个主要的协议组成，它由下图的第二层以及加密和鉴别算法组成。

> 可概括为：**IPsec = 安全协议 + 密钥管理 + SA/数据库 + 工作模式**

#### 10.2.1 安全协议

| | AH（Authentication Header） | ESP（Encapsulating Security Payload） |
|---|---|---|
| 协议号 | **51** | **50** |
| 提供 | 数据完整性、源认证、抗重放 | 机密性、完整性、源认证、抗重放 |
| 不提供 | **机密性** | — |
| 认证范围 | 包括 IP 头中不变字段 + AH 头 + 载荷 | 认证范围**不包括外层 IP 头** |
| 备注 | — | 是实际中最常用的 IPsec 协议 |

#### 10.2.2 密钥管理协议

| 协议 | 说明 |
|---|---|
| **IKE**（Internet Key Exchange） | 用于协商 SA、交换密钥、认证对端 |
| **ISAKMP** | Internet 安全协商和密钥管理协议，是 IPSec 的另一个主要组件 |
| **Oakley** | 提供 DH 密钥交换模式 |
| **SKEME** | 提供认证和密钥交换技术 |
| **DOI** | 解释域，如 IPsec DOI，说明 AH、ESP 等如何使用 |

**IKE 版本**

- **IKEv1**：两阶段。阶段 1：建立 ISAKMP SA / IKE SA，主模式或野蛮模式；阶段 2：建立 IPsec SA，快速模式
- **IKEv2**：简化流程，常用 IKE_SA_INIT、IKE_AUTH、CREATE_CHILD_SA

**ISAKMP 说明**：ISAKMP 提供了用于应用层服务的通用格式，它支持 IPSec 协商方的密钥管理需求。重点在于它**不直接完成密钥交换**，而是规定 SA 从协商、建立到修改、删除的全生命周期管理框架和统一报文格式：报文由 ISAKMP 头和若干载荷组成，载荷可承载 SA、提案、变换、密钥、身份、认证、随机数、通知、删除等信息，交换类型支持主模式、野蛮模式、快速模式等，并通过"阶段一建立 ISAKMP SA/IKE SA、阶段二在其保护下建立 IPsec SA"的两阶段流程为 AH/ESP 服务；IKE 就是基于 ISAKMP 框架，结合 Oakley 的 DH 交换和 SKEME 的认证机制，用 **UDP 500（NAT-T 为 4500）** 实现对等体认证、密钥协商和 SA 维护。

> IKE 使用 **UDP 500**，NAT-T 使用 **UDP 4500**。

#### 10.2.3 SA 与数据库

**SA（Security Association，安全关联）**

- 是 IPsec 的基础，AH 和 ESP 都依赖 SA
- SA 是**单向**的，双向通信需要两个 SA
- 唯一标识：**SPI + 目的 IP + 安全协议标识**

| 数据库 | 用途 |
|---|---|
| **SAD**（Security Association Database） | 存储 SA 参数：SPI、序列号、算法、密钥、生命周期、模式等 |
| **SPD**（Security Policy Database） | 定义什么流量需要 IPsec、如何保护、绕过还是丢弃 |
| **PAD**（Peer Authorization Database） | 用于对端授权认证，RFC 4301 中定义 |

### 10.3 安全协议：AH

AH 提供数据来源认证、完整性校验和抗重放攻击，**不提供加密**。根据 AH 头插入 IP 包的位置不同，AH 有传输模式和隧道模式。

#### 10.3.1 AH 的传输模式

AH 头插入**原 IP 头后面**。

![AH传输模式：AH 头插入原 IP 头之后，格式为 原IP头 | AH头 | TCP/UDP头 | 数据](/assets/img/csreview/ah-transport-mode.png)

#### 10.3.2 AH 的隧道模式（重点）

将 AH 头插入**原 IP 分组的 IP 头之前**，并在 AH 头之前添加新的 IP 头。新的 IP 头协议字段为 **51**，表明其后是 AH 头。

![AH隧道模式：新IP头 | AH头 | 原IP头 | TCP/UDP头 | 数据，新IP头协议字段为 51](/assets/img/csreview/ah-tunnel-mode.png)

### 10.4 ESP 协议的传输模式与隧道模式

ESP 提供**加密**，以及数据来源认证、完整性校验和抗重放攻击。

#### 10.4.1 传输模式

IP 头的协议字段由原来的值变为 **50**，用于保护传输层载荷（如 TCP/UDP 数据）。

![ESP传输模式：原IP头 | ESP头 | TCP/UDP头 | 数据 | ESP尾，IP头协议字段由原来的值变为 50](/assets/img/csreview/esp-transport-mode.png)

#### 10.4.2 隧道模式

整个原始 IP 包（包括原 IP 头）都被封装在 ESP 有效载荷中，并产生一个新的 IP 头附着在 ESP 头之前。新 IP 头的协议字段为 **50**。隧道模式能**保护子网内部拓扑，支持使用私有 IP 地址**。

![ESP隧道模式：新IP头 | ESP头 | 原IP头 | TCP/UDP头 | 数据 | ESP尾，新IP头协议字段为 50](/assets/img/csreview/esp-tunnel-mode.png)

> **ESP 加密的是 ESP 头和 ESP 尾之间的数据。**

### 10.5 VPN 通道的四种建立方式

| 方式 | 要求 |
|---|---|
| **Host 对 Host** | 该模式要求两边主机都支持 IPSec；VPN 网关可支持也可不支持 IPSec |
| **Host 对 VPN 网关** | 该模式要求 host 方主机支持 IPSec；VPN 网关 VPN 一侧需要支持 IPSec |
| **VPN 网关对 VPN 网关** | 该模式不要求主机支持 IPSec；两边的 VPN 网关必须支持 IPSec |
| **Remote User 对 VPN 网关** | 该模式不要求网关内主机支持 IPSec；远程用户主机必须支持 IPSec；VPN 网关必须支持 IPSec |

![VPN 通道建立方式：Host to Host，两端主机必须支持 IPSec，网关可支持也可不支持](/assets/img/csreview/vpn-host2host.png)

![VPN 通道建立方式：Host to VPN，host 方主机必须支持 IPSec，对端网关必须支持 IPSec](/assets/img/csreview/vpn-host2gw.png)

![VPN 通道建立方式：VPN Gateway to VPN Gateway，主机可以不支持 IPSec，两端网关必须支持 IPSec](/assets/img/csreview/vpn-gw2gw.png)

![VPN 通道建立方式：Remote User to VPN，主机必须支持 IPSec，网关必须支持 IPSec](/assets/img/csreview/vpn-remote2gw.png)

### 10.6 数据完整性保护过程（重点）

发送端对原始数据包进行 Hash 运算生成"摘要"，将加密后的数据包和摘要一同传输。接收端解密数据包后，对原始数据包重新计算摘要，并与接收到的摘要进行比较，若一致则验证通过，确保数据未被篡改。

![数据完整性保护过程：发送端 Hash 生成摘要并加密数据包一同传输，接收端解密后重新 Hash 与摘要比较](/assets/img/csreview/vpn-integrity.png)

### 10.7 SSL 与 TLS

- **SSL**：安全套接层协议，广泛用于 Web 浏览器与服务器之间的身份认证和加密数据传输。
- **TLS**：传输层安全协议，是 SSL 的 IETF 标准化版本，类似 SSLv3 但有若干改进。

![TLS 与 SSLv3 的九点不同：版本号、消息验证码、伪随机函数、警告码、密码组、客户端证书类型、Certificate_Verify 和结束消息、密码计算、填充](/assets/img/csreview/tls-vs-sslv3.png)

**TLS 与 SSLv3 的九处不同（背诵版）**

1. **版本号**：TLS 主版本 3、次版本 1（TLS 1.0）。
2. **消息验证码**：改用 RFC 2104 定义的 HMAC；MAC 覆盖 SSLv3 的全部字段，并增加 `TLSCompressed.version` 字段。
3. **伪随机函数**：TLS 使用 PRF 伪随机函数扩展密码为数据块。
4. **警告码**：支持 SSLv3 定义的全部警告码（`no_certificate` 除外），并新增若干警告码。
5. **密码组**：TLS 不包含 Fortezza 方案。
6. **客户机证书类型**：`certificate_request` 中定义 `rsa_sign`、`dss_sign`、`rsa_fixed_dh`、`dss_fixed_dh`。
7. **Certificate_Verify 与结束消息**：`certificate_verify` 中 MD5 / SHA-1 只在 `handshake_messages` 中计算；结束消息的哈希计算也与 SSLv3 不同。
8. **密码计算**：TLS 的计算方法与 SSLv3 不同。
9. **填充**：只要总长度是密码块长度的倍数，填充字节可以是最大 255 字节的任意数量。

**SSL 在我国的三点限制**

- **合规**：我国《商用密码管理条例》要求使用国家批准的商用密码算法，国外密码算法不能直接作为合规商用密码使用。
- **安全基础**：SSL 常用的证书与密钥交换大量依赖 RSA；RSA 依赖大整数分解，面对量子计算有长期风险。
- **出口限制**：美国早期出口限制只允许 512 位 RSA、40 位对称密钥，导致早期 SSL 强度不足。

**重放问题**：SSL/TLS 用连接序号 / 随机数抗重放，但课件认为仅靠序号不能根本解决重传攻击，有效办法是加入时间戳 / 新鲜性随机数。

**SSL 握手协议**：用于在实际数据传输开始前，通讯双方进行身份认证、协商加密算法、交换加密密钥等。主要分为建立安全能力、服务器认证与密钥交换、客户端认证与密钥交换、完成四个阶段。

### 10.9 HTTPS 通信过程（单向鉴别）

1. 客户端向服务器发起 HTTPS 请求。
2. 服务器生成公私钥对，通过可信机构对公钥等信息进行数字签名，形成服务器证书。
3. 服务器发送证书响应请求（公钥）。
4. 客户端验证证书，并用证书公钥加密一个随机生成的密钥（key）发送给服务器。
5. 服务器用私钥解密获得随机密钥。
6. 双方使用该随机密钥进行后续对称加密通信。

![HTTPS 通信过程（单向鉴别）：公钥私钥对即数字证书，客户端生成随机密钥用证书公钥加密传输，服务器私钥解密后双方用该密钥对称通信](/assets/img/csreview/https-single-auth.png)

#### 10.9.1 SSL 中间人攻击（MITM）与 PKI 证书链

**攻击过程（6 步）**

1. 攻击者控制客户端与服务器之间的链路，截获 HTTPS 请求。
2. 服务器返回自己的公钥 / 证书，被中间人截获。
3. 中间人自建一对密钥，把伪造的公钥 / 证书发给客户端；客户端若不严格验证证书有效性，就会接受。
4. 客户端用伪造公钥加密会话密钥。
5. 中间人用自己的私钥解密得到会话密钥，再用服务器真公钥重新加密，转发给服务器。
6. 服务器以为是客户端直发；此后中间人可以窃听、篡改双方的通信内容，而双方都不知情。

**根因**：客户端未严格验证证书有效性（或 CA 被攻破、证书链被伪造）。

**对策：PKI 证书链验证**

- 信任链：CA 信任根 → 中间 CA → 叶子证书。
- 验证内容：证书链、有效期、域名、吊销状态（CRL / OCSP）。
- 配套：X.509 证书、CA / RA。

> HTTPS 能防被动窃听；只有在客户端不验证证书或 CA 被攻破时，才不能防 MITM。正确 PKI + 严格证书校验是 HTTPS 防 MITM 的前提。

## 11. 系统安全

### 11.1 漏洞与漏洞利用

**漏洞**：系统在设计、实现、配置、运行等环节中存在的缺陷或弱点，可被威胁利用造成安全事件。

**五类漏洞**：代码漏洞、配置漏洞、设计漏洞、逻辑漏洞、物理漏洞。

**漏洞利用三类**

| 类型 | 典型方式 |
|---|---|
| 控制流劫持 | 改函数指针、返回地址，劫持执行流 |
| 内存破坏 | 缓冲区溢出、整数溢出、UAF 等 |
| 注入攻击 | SQL 注入、命令注入、LDAP 注入等 |

**Exploit**：触发漏洞的程序或代码。编写五步：漏洞分析 → 利用漏洞 → 开发 Exploit → 测试验证 → 保持匿名 / 清理痕迹。

**漏洞利用链**：联合多个漏洞绕过认证、获取权限、执行恶意代码。

**防御与修复**

- 安全编码：输入验证、最小权限、错误处理与日志。
- 安全测试：静态分析、动态分析、渗透测试、模糊测试。
- 漏洞确认与分析。
- 补丁开发与发布、漏洞公告与协调披露。
- 应急响应：识别评估 → 控制 → 恢复与总结。

**缓冲区溢出防御**：堆栈金丝雀 Canary（溢出先破坏金丝雀即被检测）、DEP 数据执行保护、内存隔离、ASLR 地址空间布局随机化。

### 11.2 漏洞分析方法

| 方法 | 定义 |
|---|---|
| **静态分析** | 通过对源代码、字节码或可执行文件等静态数据进行分析来发现潜在漏洞和安全问题的过程。在分析过程中，**不需要运行程序**，而是通过检查代码本身来识别潜在的漏洞 |
| **动态分析** | 一种采用**运行时数据**来分析软件漏洞和安全问题的方法。动态分析通常涉及执行软件程序，监视其行为，并记录程序执行时产生的数据 |
| **模糊测试** | 一种**自动化的动态安全测试**方法，旨在发现软件系统中的漏洞和异常行为。在模糊测试过程中，会向目标软件系统输入大量随机、异常或非预期的数据，监控系统的反应，并检测系统在处理这些数据时是否会出现问题 |

### 11.3 数据安全的定义

| 口径 | 定义 |
|---|---|
| **国家标准定义** | 通过管理和技术措施，确保数据有效保护和合规使用的状态 |
| **法律定义** | 通过必要措施，确保数据有效保护和合法利用，以及具备保障持续安全状态的能力 |

### 11.4 联邦学习（名词解释题）

**定义**：旨在不集中数据的情况下进行模型训练。联邦学习通过在分布式设备上进行本地计算，避免了数据的集中存储和传输，从而增强了数据隐私保护，同时有效利用分布式资源进行协同学习。

**核心思想**：联邦学习的核心是将模型分布在多个参与方（如个人设备、企业或机构）之间，每个参与方在本地训练模型，然后将训练结果（如模型参数）发送到中央服务器进行聚合，只有训练后的模型参数被共享，从而保护数据隐私。

![现代隐私保护方法：联邦学习（水平联邦、垂直联邦、联邦迁移学习）](/assets/img/csreview/federated-learning.png)

### 11.5 可信计算与国产算法

**可信计算**：以安全芯片为基础，建立不受恶意代码攻击的可信执行环境（TCB），通过度量、存储、报告建立信任链。定义可按 ISO/IEC、IEEE、TCG、冯登国等口径表述；考试按“安全芯片 + 可信执行环境 + 信任链”答即可。

**三大可信根**

| 可信根 | 作用 |
|---|---|
| **RTM 可信度量根** | 复位后 CPU 执行 CRTM，对 BIOS、OS Loader 等逐级度量，度量值存入 PCR |
| **RTS 可信存储根** | 安全存储密钥和度量值（PCR） |
| **RTR 可信报告根** | 对 RTS 中的内容签名后向外报告，用于远程证明 |

**信任链**：CRTM → BIOS → OS Loader → OS → 应用，逐级度量，形成信任链。

**三大核心**：远程证明、隔离执行（TEE）、信任根。

**四大关键技术**：可信存储、度量与证明、可信执行环境、安全启动。

**TEE 的支撑**：内存页加密、地址随机化（ASLR）、DEP、影子栈等。

**国外算法 vs 国产替代**

| 国外算法 | 主要问题 | 国产替代 |
|---|---|---|
| DES | 56 位，EFF 曾用 56 小时破解 | SM4 |
| AES | 128/192/256 位，安全强度高；自主可控场景仍需国产算法 | SM4（对称场景） |
| MD5 | 存在碰撞；“火焰”病毒用 MD5 碰撞伪造微软代码签名证书 | SM3 |
| RSA / ECDSA | 依赖大整数分解 / 离散对数；RSA 公司 BSAFE 曾默认使用含 NSA 后门的 Dual_EC_DRBG 随机数发生器 | SM2 |
| 传统 PKI 证书体系 | 证书管理复杂 | SM9（基于身份，无需数字证书） |

### 11.6 数据脱敏与隐私计算

**数据脱敏**：通过变形、遮蔽、替换等手段，使敏感数据在非生产环境中不可还原或不可识别，同时保留可用性。

**五原则**：有效性（无法还原原始）、真实性（保留特征与结构）、最小化、一致性、合规性。

**四类方法**

| 方法 | 做法 | 例子 |
|---|---|---|
| **泛化** | 降低精度 / 粒度 | 截断、取整、归类、区间化 |
| **抑制** | 直接遮蔽 / 删除 | `?`、`X`、`#`、`*` 掩码（长度不变） |
| **扰乱** | 加噪 / 变换，保留统计特性 | 加密、散列、置换、加噪 |
| **仿真** | 生成虚拟 / 合成数据 | 合成数据、虚拟数据 |

**K-匿名**：每条记录在准标识符上至少与 k−1 条记录相同；风险：同质性攻击、背景知识攻击。

**L-多样化**：每个等价类至少 L 个不同敏感值。

**T-接近性**：等价类敏感属性分布与全局分布的距离（EMD / KL）不超过阈值 T。

**差分隐私**：Dwork 2006；加 / 删一条记录不显著影响输出，用噪声换取隐私。

**同态加密**：$\mathrm{Dec}(f(\mathrm{Enc}(x),\mathrm{Enc}(y)))=f(x,y)$。

- **PHE**：部分同态，只支持一种运算。
- **SHE**：有限同态，支持有限次运算。
- **FHE**：全同态，支持任意运算。

### 11.7 软件安全（例题）

> 说明：本课程课件没有独立“软件安全”章，下面按 §11.1 漏洞、§11.2 漏洞分析、§11.5 可信计算相关页整理；软件供应链见 §12.1。

**例题（简答）**：简述软件安全的重要性与主要措施。

**重要性**（三句话）：

1. 软件是资产的组成部分；**软件缺陷（程序代码缺陷）本身就是脆弱性**，是风险的内因。
2. 漏洞是攻击的主要入口，可组合成**漏洞利用链**；且武器化周期在缩短——课件引报告：2025 上半年新增漏洞 23351 个，高危 / 极危占 43.5%；并举例 CVE-2025-59287 补丁发布后，PoC 公开短时间内即被大规模利用。
3. 应用层安全是安全技术体系的独立层次；可信计算也以降低软件风险、保证软件行为可信为目标。

**措施**（按课件 §9.5.3 三段式）：

| 环节 | 措施 |
|---|---|
| **防御策略** | **安全编码**：输入验证与清理、最小权限、错误处理与日志；**安全测试**：静态分析、动态分析、渗透测试 |
| **修复流程** | 补丁开发与发布；漏洞公告与协调披露 |
| **应急响应** | 建立漏洞应急团队、定期培训演练；事件识别与评估 → 事件控制 → 恢复与总结 |

**常见缺陷的针对性防护**：

| 缺陷 | 防护 |
|---|---|
| SQL 注入 | 预编译 / 参数化查询；输入验证与过滤；使用 ORM |
| XSS | 输入验证；输出编码；CSP；避免内联 JS；HttpOnly / Secure；安全框架与库 |
| 不安全默认配置 | 改默认密码 / 强密码；禁用默认高权限账户；限制数据库 IP / 端口；最小权限；关无用服务；日志审计；SSL/TLS |
| 补丁管理缺失 | 定期检查更新；补丁管理工具；测试环境验证；风险评估；监控供应商公告 |
| 缺少审计监控 | 日志记录与实时监控；定期审核访问日志、识别异常 |

**再补两层**：

- **运行时 / 系统层**：栈保护 Canary、DEP、内存隔离、文件系统权限与加密、及时打补丁。
- **可信计算**：安全启动、TEE、可信存储、度量与证明，从“信任根”开始保证软件运行可信。

> 收口：软件安全的核心是“**安全左移 + 安全开发 + 漏洞修复 + 应急响应**”，不能只靠 WAF / 防火墙补。

## 12. 其他考点

### 12.1 供应链安全

#### 12.1.1 软件供应链安全

**必要性**：软件供应链攻击已常态化。攻击者通过污染开源库、篡改硬件固件等方式，在软件生产与分发环节植入恶意代码，进而渗透目标系统，造成广泛影响。

**影响方面**

- **开源产品后门**：攻击者可向 NPM、PyPI 等公共开源仓库投毒，使依赖这些开源组件的产品被植入后门。
- **企业名誉与业务**：供应链攻击可导致企业系统被控、数据泄露、服务中断，造成重大经济损失并严重损害企业声誉。

#### 12.1.2 数据供应链安全

**是什么**：数据供应链涉及数据从产生、传输、存储、处理到销毁的**全生命周期**。其安全核心是确保数据在整个链条中的机密性、完整性和可用性。

**应用场景与风险**：在物联网、云计算、大数据等场景中，数据在多个实体间流动。风险包括：数据在传输或存储时被窃取（**机密性破坏**）、被非法篡改（**完整性破坏**）、以及因系统故障或攻击导致无法访问（**可用性破坏**）。

#### 12.1.3 物理供应链安全

**核心要点**：物理安全是信息安全的基础，常被忽视。它确保信息系统所在的物理环境（如数据中心）和硬件设备本身的安全。

**风险案例**：攻击者可利用物理安全漏洞（如门禁设计缺陷）接触设备，直接植入恶意硬件或窃取数据。管理疏忽（如"忘记关门"）是物理安全的最大威胁之一。

#### 12.1.4 关联与总结

软件、数据、物理供应链安全是网络空间安全的重要组成部分。安全是**动态、相对**的，需要技术、管理和人员意识相结合，并在安全与发展、开放与防护之间取得平衡。

### 12.2 特殊通信场景安全

#### 12.2.1 卫星通信的安全威胁与防护

卫星通信把节点搬到天上，链路变成"地面站—卫星—地面站"的空中微波中继。**安全上最大的变化是：攻击面从"网络内部"扩展到了"物理可达的无线信道"**——传统有线链路上"偷不到线"的天然屏障消失了。

> 链路的**性能特性**（时延取舍、窗口下限、对 TCP 的影响、vs 地面蜂窝）见 [物理层 §卫星通信](/posts/872-net-15-phy/) 和 [TCP 拥塞控制 §大 RTT 链路](/posts/872-net-09-congestion/)，本节只补**安全**维度。

**三类典型威胁**

| 威胁 | 作用的安全属性 | 说明 |
|---|---|---|
| **窃听与截获** | **机密性** | 无线信道开放，信号可被任意接收方捕获；若链路层不加密，内容即为明文 |
| **干扰与压制** | **可用性** | 窄带压制、宽带阻塞、功率压制直接淹没信号；导航场景还存在 **GPS 欺骗**——伪造导航信号使终端定位错误 |
| **欺骗与劫持** | **完整性 + 身份真实性** | 伪造合法卫星或终端身份接管链路；地面站设备物理暴露，易被接触后植入 |

**对应的安全机制**

| 机制 | 解决什么 | 说明 |
|---|---|---|
| **链路层与应用层加密** | 窃听 | 对信道数据直接加密，弥补无线信道的开放性 |
| **IPsec 隧道模式** | 窃听 + 拓扑暴露 | 跨广域/星地链路建立端到端安全通道。隧道模式**封装整个原始 IP 分组**，因此能隐藏内部网络地址、**保护子网内部拓扑**（见 §10.4.2）——这在跨越不可控的空域链路时尤其关键 |
| **身份认证与完整性保护** | 欺骗 + 篡改 | 双向鉴别确认通信对端身份；用 AH/ESP 的完整性校验与**抗重放**字段防止数据被篡改和重放 |
| **抗干扰技术** | 干扰压制 | 扩频、跳频、纠错编码、自适应编码调制，提高抗窄带干扰与衰落能力 |
| **物理防护与冗余** | 物理攻击与单点失效 | 地面站机房门禁、电磁屏蔽；多星/多路径备份，避免单点被物理接管 |

说白了，卫星通信的威胁全部来自**无线信道是敞开的**，一共三类：信号被人收走（窃听）、信号被人压掉（干扰）、有人冒充通信的一方（欺骗）。

前两类分别靠加密和抗干扰技术挡住，第三类靠身份认证加完整性校验挡住。

题目问"**两种**安全威胁"时，两个答案要来自**不同维度**——比如机密性配可用性，或者机密性配真实性。不要把"窃听"和"截获"这种同源说法拆成两种答，那只算一种。

### 12.3 大数据与人工智能安全

#### 12.3.1 大数据安全

**为什么大数据带来新问题**：

- 数据价值密度低但总量大，**易复制、传播快、边际成本低**；一次泄露不可撤回，传统“边界防护 + 内外网隔离”不够。
- 数据在**全生命周期**流动，收集、存储、使用、加工、传输、提供、公开、销毁每个环节都有风险。

| 环节 | 典型风险 | 主要措施 |
|---|---|---|
| **收集** | 过度收集、无授权采集 | 最小必要、告知同意、合法性基础 |
| **存储** | 泄露、越权访问 | 分类分级、加密、访问控制、审计 |
| **使用 / 加工** | 滥用、违规分析、训练数据泄露 | 脱敏 / 匿名化、隐私计算、目的限制 |
| **传输** | 窃听、篡改 | TLS / VPN、完整性校验 |
| **提供 / 公开** | 违规共享、跨境、交易 | 合规评估、DLP、脱敏、合同约束 |
| **销毁** | 残留数据被恢复 | 安全删除、介质销毁 |

**隐私计算**：联邦学习、安全多方计算（MPC）、可信执行环境（TEE）、差分隐私——做到“数据可用不可见 / 可算不可识”。

#### 12.3.2 人工智能安全

**两条主线，答题必须分开写**：

| 方向 | 关注点 | 典型技术 / 措施 |
|---|---|---|
| **AI 自身安全**（AI 作为攻击面） | 对抗样本、数据投毒、模型后门、模型窃取、提示词注入 / 越狱、深度伪造、训练数据泄露 | 对抗训练、数据清洗与来源验证、模型访问控制 / 水印、输入输出过滤、内容溯源、安全评估与红队 |
| **用 AI 做安全**（AI 作为防御工具） | 异常检测、恶意代码分析、漏洞挖掘 / 模糊测试、钓鱼识别、日志告警降噪 | 人机结合、可解释性、误报控制、模型持续更新 |

**AI 供应链**：开源模型、数据集、模型权重、推理框架、算力基础设施都可能被投毒或劫持；与 §12.1 软件 / 数据供应链安全接壤。

#### 12.3.3 交叉与收口

- **数据是 AI 的燃料**：数据投毒 → 模型投毒；大数据安全是 AI 安全的**上游**。
- **开源模型 / 数据集是新的供应链**：模型后门 = 供应链后门的 AI 版。
- **生成式 AI 的新交互面**：自然语言即接口 → 提示注入、越狱；传统“输入校验 / 规则过滤”不够，要加语义过滤、权限隔离、工具调用白名单。
- **算力也是资产**：GPU 集群、模型文件、向量库、推理 API 都要纳入资产与风险管理。

> 一句话：大数据安全管“数据全生命周期”，AI 安全要分“AI 自身安全”和“用 AI 做安全”两面写，交叉点是数据投毒与模型供应链。

### 12.4 开放题万能框架（背下来套用）

**五步框架**

1. **定性背景与威胁**：CIA + 风险 = 威胁 × 脆弱性 × 资产价值。
2. **技术手段**：加密、鉴别、访问控制、检测、隔离、审计，每项配 1–2 个例子。
3. **管理与法律**：等级保护定级、备案、测评、整改；日志留存不少于 6 个月；数据分类分级。
4. **产业与自主可控**：信创、供应链安全。
5. **效果与短板**：残余风险、持续监控、动态调整。

**反间谍 / 数据窃取专用骨架**

- 加密：AES / RSA / ECC。
- 多因素认证：生物识别、硬件令牌、OTP。
- 最小权限 / RBAC / 职责分离。
- IDS / IPS 实时阻断。
- 数据分类分级与 DLP、审计取证。
- 网闸 / 单向光闸物理隔离。
- 信创与供应链安全。
- 三部法律合规：网络安全法、数据安全法、个人信息保护法。
