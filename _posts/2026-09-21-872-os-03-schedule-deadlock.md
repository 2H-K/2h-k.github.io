## 2. 调度算法：七个算法逐个过

### 2.1 FCFS 先来先服务

- 机制：按**到达先后**排队，非抢占。
- 优点：公平、简单。缺点：**对短作业极不友好**——长作业在前的"护航效应"（convoy effect）让后面所有短作业陪跑。
- 定位：批处理基线算法，常作对比项。

### 2.2 SJF 短作业优先 / SRTN 最短剩余时间优先

- **SJF**（非抢占）：就绪队列里**服务时间最短**的先上。
- **SRTN**（抢占版）：新进程到达或进程唤醒时，比较**剩余时间**，更短者抢占。
- 结论【必背】：**在非抢占算法中，SJF 的平均等待时间、平均周转时间最短**；SRTN 作为抢占版可以更优。
- 代价：① 对长作业不利，可能**饥饿（starvation）**——不断有短作业插队，长作业无限推迟；② 服务时间只能**估计**（批处理靠作业说明书，交互系统难办）。

### 2.3 HRRN 高响应比优先

- 响应比 = **(等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待/服务**【必背】。
- 非抢占：每次调度时计算**所有就绪进程**的响应比，选最高者。
- 精髓：服务时间短 → 响应比高（继承 SJF 优点）；等待越久 → 响应比越高（长作业等到一定时候必然上）——**兼顾长短作业，不会饥饿**。

### 2.4 RR 时间片轮转

- 机制：就绪队列 FIFO，队首进程上 CPU，跑满一个**时间片**就被剥夺、回到**队尾**。
- 时间片大小的权衡【必背】：
  - 太大（超过典型交互响应需求）→ 退化为 **FCFS**；
  - 太小 → **切换开销**占比过高，真正干活的时间变少。
- 定位：**分时系统**标配，保证响应时间，不区分作业长短。
- 细节：时间片没用完就主动阻塞/完成的进程，直接去相应队列，**不占满时间片**。

### 2.5 优先级调度

- 机制：按优先级选进程，分**抢占式 / 非抢占式**两版。
- 优先级设定惯例：系统进程 > 用户进程；交互式 > 非交互式；**I/O 型 > 计算型**（让 I/O 早启动，设备与 CPU 并行，提高吞吐）。
- 静态优先级简单但可能**饥饿**高优先级长驻 → **动态优先级 + 老化（aging）**：等待越久优先级渐增。

### 2.6 多级队列 MLQ 与多级反馈队列 MLFQ

同一"多队列"思想的两个算法（汤书 3.3 两者都收），区别只在一点：进程动不动。

多级队列 MLQ（静态版）：按进程类型固定分桶——系统进程、交互（前台）进程、批处理（后台）进程各占一个队列；进程一旦入队就固定归属，不能迁移。队列之间两种安排：固定优先级（高级队列全空才轮到低级，高级可抢占），或按比例分配 CPU 时间（如前台 80%、后台 20%）；队列内部各配各的算法，典型是前台 RR、后台 FCFS。缺陷：类型被定死后不灵活，低优先级队列可能饥饿。

多级反馈队列 MLFQ（动态改进版）【必背】给多级队列加上"反馈"，进程按行为升降级：

1. 设多个就绪队列，优先级从高到低，时间片从小到大（如 1、2、4……常成倍增）；
2. 新进程进最高级队列队尾，按 FCFS 等待调度；
3. 本队列时间片内没跑完 → 降一级入下一级队列队尾；最低级队列按 RR 轮转；
4. 只有第 1 ~ i−1 级全空才调度第 i 级；低级进程被高级到达者抢占后，回自己所在队列的队尾；
5. 可再加老化规则：等待过久的进程升级，防低级饥饿。

效果：短作业在高级队列几个小时间片内跑完（周转好）；长作业逐级下沉、用大时间片省切换开销；I/O 型跑不满时间片、留在高级队列保持响应——各类进程通吃，且无需预知运行时间。

两算法对照（选择辨析）：

| 对比项 | 多级队列 MLQ | 多级反馈队列 MLFQ |
|---|---|---|
| 进程归属 | 固定在某队列，不迁移 | 按行为在队列间升降级 |
| 队列间调度 | 固定优先级，或按比例分 CPU 时间 | 高级全空才调低级，高级可抢占 |
| 队列内算法 | 各配各的（前台 RR、后台 FCFS） | 高级 FCFS、最低级 RR |
| 反馈调整 | 无 | 核心：按 CPU/IO 行为反馈升降 |
| 饥饿 | 低级队列可能饥饿 | 加老化升级可缓解 |

### 2.7 算法对比总表

| 算法 | 抢占？ | 会饥饿？ | 需预知运行时间？ | 适用场景 |
|---|---|---|---|---|
| FCFS | 否 | 不会（但短作业陪跑） | 否 | 批处理基线 |
| SJF | 否 | **会**（饿死长作业） | 要（估计） | 批处理 |
| SRTN | 是 | 会 | 要（估计） | 批处理 |
| HRRN | 否 | 不会 | 否（按响应比） | 批处理折中 |
| RR | 是（时间片到） | 不会 | 否 | **分时/交互** |
| 优先级 | 两版都有 | **会**（静态时） | 否 | 实时/通用 |
| 多级队列 MLQ | 队列间可抢占 | 会（低级队列） | 否 | 类型可预分的系统 |
| 多级反馈队列 | 是 | 基本不会（可加老化升级） | **否** | **通用系统** |

> 实时调度（EDF 最早截止时间优先、RM 速率单调）：EDF 按截止期动态调，RM 周期越短静态优先级越高——细节见 §7 低频清单。

## 3. 调度计算大题：甘特图五步法

```
第 1 步  画时间轴/甘特图：每个调度时刻只问一句"现在该谁上？"
         （到达？片尽？抢占比较？——按算法规则走）
第 2 步  标完成时刻
第 3 步  周转时间 T = 完成 − 到达（I/O 阻塞也算在内，01 篇口径）
第 4 步  带权周转 W = T / 实际服务时间，W ≥ 1
第 5 步  求平均（题目问谁平均就算谁）
```

统一例题（四个进程）：

| 进程 | 到达 | 服务 |
|---|---|---|
| P1 | 0 | 7 |
| P2 | 2 | 4 |
| P3 | 4 | 1 |
| P4 | 5 | 4 |

**FCFS**：`P1(0-7) P2(7-11) P3(11-12) P4(12-16)`
周转 = 7、9、8、11 → 平均 **8.75**；带权 = 1、2.25、8、2.75 → 平均 **3.5**（P3 一个短作业被护航拖惨）。

**SJF（非抢占）**：P1 独跑到 7，就绪 {P2(4), P3(1), P4(4)} → 选 P3；P2、P4 平手取先到。
`P1(0-7) P3(7-8) P2(8-12) P4(12-16)`
周转 = 7、10、4、11 → 平均 **8**；带权 = 1、2.5、4、2.75 → 平均 **≈2.56**。

**SRTN（逐时刻推演，最易错）**：
- t=0：P1 运行（剩 7）。
- t=2：P2 到（4）< P1 剩 5 → **抢占**。P2 运行。
- t=4：P3 到（1）< P2 剩 2 → **抢占**。P3 运行。
- t=5：P3 完成；P4 到（4）。就绪 {P1 剩 5, P2 剩 2, P4 = 4} → P2 上。
- t=7：P2 完成。P4(4) < P1(5) → P4 上。t=11 P4 完成 → P1 上。
甘特图：`P1(0-2) P2(2-4) P3(4-5) P2(5-7) P4(7-11) P1(11-16)`
周转 = 16、4、1、6 → 平均 **6.75**；带权 = 16/7、1、1、1.5 → 平均 **≈1.45**（四算法最优）。

**RR（q=2）**：口径——同一时刻"新到达"先入队、"片尽回尾"后入队。
`P1(0-2) P2(2-4) P3(4-5) P1(5-7) P2(7-9) P4(9-11) P1(11-13) P4(13-15) P1(15-16)`
周转 = 16、7、1、10 → 平均 **8.5**；带权 = 16/7、1.75、1、2.5 → 平均 **≈1.89**。
注意：RR 平均周转**不一定**优于 FCFS（本题 8.5 > FCFS 不成立、但短作业 P3/P4 明显受益），它买的是响应时间。

> HRRN 不再单独展开算例，方法就是 t=7 时刻算响应比：P3 (3+1)/1=4 最高先上，再 P2 (6+4)/4=2.5 > P4 (3+4)/4=1.75——结果同 SJF 本题。

## 4. 死锁：从现象到四策略

### 4.1 概述与辨析

- **死锁**：多个进程**互相等待**对方占有的资源，无外力干预都无法推进【必背】。
- 两个成因：**竞争不可剥夺资源**、**进程推进顺序非法**。
- 只发生在**不可剥夺资源**上（打印机、磁带机……）；CPU、内存可剥夺，不会因此死锁。
- 死锁处理四策略总览：**预防**（静态限分配）→ **避免**（动态判安全）→ **检测 + 解除**（先放任后处理）→ **鸵鸟策略**（不理睬，实际通用系统的选择）。

| 对比项 | 死锁 | 饥饿 |
|---|---|---|
| 进程数 | **≥ 2** 且等待成环 | 可以只有 1 个 |
| 能否推进 | 全都停 | 系统整体仍在推进，只是它轮不上 |
| 根源 | 资源分配**顺序/方式**非法 | 分配**策略**（如短作业优先） |
| 典型来源 | 02 篇：同步 P 与互斥 P 反序、哲学家同拿左筷 | SJF 饿死长作业、静态优先级 |

### 4.2 死锁的四个必要条件

1. **互斥**：资源一次只能一个进程使用；
2. **占有并等待**（请求并保持）：拿着手里的，还要等新的；
3. **不可剥夺**：只能由占有者主动释放，不能抢；
4. **循环等待**：等待链头尾相接 P0→P1→…→Pn→P0。

> 口径必须记牢：四条是死锁的**必要条件**——缺一条就死锁不了；但四条同时成立**不一定**死锁（循环等待还要求等待链上的请求得不到满足才真正成环）。反方向则是充要的：**死锁 ⇒ 四条件全部成立**。
> 02 篇伏笔在此落定：哲学家三防法（限 4 人 / 奇偶错峰 / 同时拿两支）分别破坏循环等待、循环等待、占有并等待；生产者-消费者"同步 P 在互斥 P 后"正是"占有并等待 + 循环等待"的现实写照。

### 4.3 死锁预防：静态破坏四条件之一

| 破坏哪条 | 做法 | 代价 |
|---|---|---|
| 互斥 | 把独占资源改造为共享（SPOOLing 把打印机虚拟成共享打印队列） | 大多数资源互斥是固有属性，**不通用** |
| 占有并等待 | 运行前**一次性申请全部**资源，不满足就不运行 | 资源浪费、利用率低；需求多的进程可能**饥饿** |
| 不可剥夺 | ① 申请不到新资源 → 释放全部已有；② OS 强行剥夺低优先级进程资源 | 实现复杂；只适用**易保存恢复**的资源（CPU、内存） |
| 循环等待 | **顺序资源分配法**：全部资源编号，只能递增申请 | 编号难定；被迫先申请用不上的资源，浪费 |

### 4.4 死锁避免：银行家算法

- 核心概念【必背】：
  - **安全序列**：一个进程排列 {P1…Pn}，使每个 Pi 还需要的资源都能由"当前剩余 + 排在它前面的进程归还的资源"满足；
  - **安全状态**：**存在**至少一条安全序列；**不安全状态**：不存在。
  - 关系链：**安全 ⇒ 无死锁；死锁 ⇒ 不安全；不安全 ⇏ 死锁**（可能侥幸推进完）。
- 数据结构（n 进程、m 类资源）：`Available[m]` 剩余；`Max[n][m]` 最大需求；`Allocation[n][m]` 已分配；**`Need = Max − Allocation`**。
- 进程请求 `Req` 的三道门：
  1. `Req ≤ Need`？超出申报量 → 报错；
  2. `Req ≤ Available`？没这么多 → 等待；
  3. **试探分配**（Available−=Req, Allocation+=Req, Need−=Req）→ 跑**安全性检测**：找 `Need ≤ Work` 的进程，假想完成并归还（`Work += Allocation`），循环直到全标记（安全，真分配）或找不到（不安全，**回滚**，让进程等待）。

标准例题（5 进程 3 类资源，Available = (3,3,2)）：

| 进程 | Allocation | Need |
|---|---|---|
| P0 | (0,1,0) | (7,4,3) |
| P1 | (2,0,0) | (1,2,2) |
| P2 | (3,0,2) | (6,0,0) |
| P3 | (2,1,1) | (0,1,1) |
| P4 | (0,0,2) | (4,3,1) |

安全性检测：Work=(3,3,2) → P1(1,2,2)≤ ✓ → Work=(5,3,2) → P3(0,1,1) ✓ → (7,4,3) → P4(4,3,1) ✓ → (7,4,5) → P0(7,4,3) ✓ → (7,5,5) → P2(6,0,0) ✓ → (10,5,7)。**安全序列 P1→P3→P4→P0→P2**（不唯一，如 P1→P3→P4→P2→P0 也行；判"是否安全"的结论唯一）。

### 4.5 死锁检测与解除：资源分配图

- 资源分配图：进程圆圈、资源方框（框内点 = 实例数）；**请求边** P→R、**分配边** R→P。
- **化简法**：找一个"既不孤立也**不阻塞**"的进程（它的请求边都能被当前空闲实例满足）→ 删去它的全部请求边与分配边（它可运行完并释放）→ 归还的资源去满足别的等待者 → 重复。
- **死锁定理【必背】**：状态 S 死锁 **⇔** S 的资源分配图**不可完全化简**。
- 检测时机：请求得不到满足时 / 周期性定时检测。
- 解除三法：**剥夺资源**（转给别的进程）、**撤销进程**（全部强制撤销，或逐个撤销直到死锁消除，代价按优先级/耗时排序）、**进程回退**（回滚到足以避开死锁的检查点）。

### 4.6 三种处理策略对比

| 维度 | 预防 | 避免 | 检测 + 解除 |
|---|---|---|---|
| 时机 | 事前静态约束 | 运行中动态判定 | 死锁发生后 |
| 判据 | 破坏四条件之一 | 银行家安全性 | 资源分配图化简 |
| 需要的信息 | 只需资源性质 | **Max/Need 申报** | 无需申报 |
| 资源利用率 | 最低 | 中 | **最高** |
| 代价 | 保守、可能饥饿 | 每次分配都要算 | 检测与解除的开销 |

## 5. 典型题型与方法

**题型① 调度计算大题**：§3 五步法。
先判抢占性再动手；SRTN 每个"到达/完成"时刻都比较剩余时间；RR 先确认入队口径（同刻"到达先"还是"片尽先"，题干会给，没给按"到达先"）。

**题型② 算法特性选择**：给特征选算法。
抓三个开关——抢占？会饥饿？要预知时间？对照 §2.7 总表。

**题型③ 最少资源数计算**：n 个进程，每个最多申请 k 个同类资源，系统不死锁至少要几个？
最坏情况【必背】：每个都握着 k−1 个、还差 1 个——只要再多 **1** 个就能放行一个进程、解开全链。**R = n(k−1) + 1**。例：3 进程各最多要 4 台打印机 → 3×3+1 = **10** 台。
一般化：Σ(maxᵢ − 1) + 1 ≤ 资源总量。

**题型④ 银行家算法大题**：给快照判安全 / 问某请求能否满足。
先算 Need = Max − Allocation；请求走"三道门"；安全性检测逐步列表（Work、Need 比较、归还），找不到就停——结论只有"安全/不安全"两种，序列不唯一。

**题型⑤ 资源分配图化简**：判断当前是否死锁、有几组死锁进程。
找不阻塞进程删边归还；化到不能再化，**剩下的非孤立部分 = 死锁进程集合**；不要画完就下结论，必须化到无进程可删。

**题型⑥ 概念辨析**：死锁 vs 饥饿（§4.1 表）、安全 vs 不安全 vs 死锁（§4.4 关系链）、预防 vs 避免 vs 检测（§4.6 表）。

## 6. 易错点

- "多级队列和多级反馈队列是一回事"：错，前者进程固定归属某队列、队列间无反馈，后者按行为升降级（对照表见 §2.6）；题干出现"降到下一级队列"说的才是反馈队列。
- "SJF 平均等待时间最短"没说口径就选错：严格说法是**在非抢占算法中** SJF 平均等待/周转最短；SRTN（抢占版）还能更优。
- "HRRN 是抢占式"：错，HRRN **非抢占**，只在"该选下一个了"的时候算响应比。
- "时间片越大越好"：错，太大退化成 FCFS，太小切换开销占比过高。
- "RR 的平均周转时间一定比 FCFS 短"：错，RR 买的是响应时间，平均周转未必赢（见 §3 例题）。
- "多级反馈队列需要预知运行时间"：错——**不需要**正是它优于 SJF 的地方。
- "多级反馈队列里被高级抢占的进程回最高级队列"：错，回**自己所在队列**的队尾；"降级"只发生在片内没跑完时。
- "死锁四条件同时成立就一定死锁"：错，四条**必要不充分**；但"死锁 ⇒ 四条件成立"是必然。
- "破坏互斥是预防死锁的常用手段"：错，互斥多数不可破坏；常用的是**破坏循环等待**（顺序分配）或**破坏占有并等待**（一次申请）。
- "不安全状态就是死锁"：错，不安全只是"可能"死锁；**安全状态一定无死锁**。
- "银行家算法属于死锁预防"：错，是**避免**——预防静态约束，避免动态判定。
- 死锁定理写错对象：它说的是**资源分配图不可完全化简 ⇔ 死锁**，不是"不安全 ⇔ 死锁"。
- 银行家计算用 `Max` 去和 `Work` 比：错，比较对象是 **Need = Max − Allocation**，且试探分配后三个矩阵都要更新。
- "死锁进程一定处于阻塞态；阻塞态的进程一定在死锁"：前半对，后半错——普通 I/O 等待也是阻塞。
- 顺序资源分配法"必须先申请编号大的"：错，只能**递增**申请（从小到大），倒序申请才可能成环。
